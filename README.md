Пройдены 41 этап ПК, 172 теста, 22 группы штатных путей H03 и общие проверки M32R. **Готового TCM BIN пока нет:** после включения реальной привязки полный линк требует 10 поставщиков платформы и датчиков. Исправлены общие зависимости сборки и подключение двигателя по CAN. [Проверки и точные ограничения](verification/project-audit/final-integration-20261121/README.md).

Чаты закрепляют задачи и файлы через общий учёт в GitHub. **«На проверке» теперь освобождает резерв:** сданный коммит сохраняется в отдельной очереди, а тот же или другой чат может занять продолжение. Для работы с этим кодом сначала включить сданные коммиты в свою ветку. Действующий резерв защищает от одновременного редактирования; приёмка старой порции не закрывает новый. Перед работой обновить tools/task_coordination.py из main. [Порядок продолжения](docs/multi-chat.md)

Внизу страницы **«Кто сейчас выполняет задачи»** добавлены **«Что осталось доделать»** и раскрываемые карточки: сделано, осталось, следующий шаг и текущий исполнитель. Продолжения сохраняют прежние ID задач. Всем чатам подходит одна команда: «Обнови main, открой общий список, найди продолжение своего направления, займи свободную задачу и выполни следующий шаг». Восемь номеров вручную распределять не нужно.

Проект RB Motors для отдельного Mazda TCM **LFJ8-18-9E1C**, коробки **Aisin U340E** и двигателя **GW4G15 с Bosch ME7.9.71 E4M3**. Алгоритмы восстанавливаются из Toyota S01, обмен исследуется по Chery Tiggo T11 и Continental TA2005.

Действуют последние решения владельца. Публикация проекта в GitHub возобновлена по указанию от 20.11.2026. Запись в блок выполняет владелец. Два дополнительных реле и импульсный выход панели отложены; скорость по CAN остаётся в первом файле.

### Куда идти дальше

1. [H03-03: Единое расписание и запуск приложения H03](docs/project-map.md#h03-03). Определение rbm_h03_application_binding уже есть и связано с CAN-адаптером. Остались реальные rbm_h03_target_takeover_ops, startup_gear, startup_gp, engine, ram_owned, clock_ready, initialize, take_toyota и service_phase; согласованный профиль и rbm_h03_sensor_config. Их испытательные поставщики не являются целевой программой.
2. [H03-04: Память, стек и сервисные пути](docs/project-map.md#h03-04). Установить окончательные переходы, данные и все недостающие поставщики; включить остальные ASM и сервисную политику в один состав. Подтвердить владение Flash/RAM, полный стек и поведение DMA/SBI/IRQ во всём времени работы. FF и частичное размещение не разрешают выпуск.
3. [TOY-02: Подтверждённая нагрузка двигателя для Toyota](docs/project-map.md#toy-02). Определить источник и шкалы GP−9046/−8288/−8330 и флаги режимов, включая переходные режимы; подключить квалификацию и отказы.
4. [CAN-05: Полнота штатного обмена Chery](docs/project-map.md#can-05). Профили с нативным T4/IF1 уже собираются и проверены на ST10. Для выпуска остаются фактическая RAM и поколение, срок lease_ticks, соединение с потребителем/арбитражем ECU-02 и проверка интервалов под нагрузкой.
5. [DTC-04: Хранение DTC после выключения питания](docs/project-map.md#dtc-04). Выделить независимые стираемые блоки, реализовать физический драйвер и политику износа, подключить восстановление/очистку к штатному запуску.

Этот порядок относится к доступной программной работе. Незакрытая зависимость ограничивает интеграцию, но не мешает отдельно исследовать модуль. Физические ограничения перечислены в карточках и в [протоколе приёмки](docs/lfj8-9e1c-minimum-bench.md).

### Быстрое продолжение

```powershell
python -B tools/project_status.py --check
python -B tools/project_status.py --task DTC-02
```

Первая команда проверяет ссылки, зависимости, актуальность карты и контрольные суммы проверенного кода/отчётов. Она не повторяет симуляции. Вторая показывает точные файлы, настройки, ограничения и команды выбранной подзадачи. При изменении кода повторяются затронутые проверки.

Статусы редактируются в [едином реестре](data/project-tasks.json), затем страницы обновляются командой `python -B tools/project_status.py --write`. Сам отчёт проверки этой командой не обновляется.
