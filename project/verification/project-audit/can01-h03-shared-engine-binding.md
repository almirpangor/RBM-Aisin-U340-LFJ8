# CAN-01 — нативная привязка входов двигателя H03

База `main` — `06ab447e19de0fa7d864e2ae674dff4a29678b10`. Нативная модель использовала H03 LFJ8-18-9E1C с SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

## Подключение

`lfj8_h03_application_binding.c` определяет неизменяемый `rbm_h03_target_engine` при явной конфигурации двигателя в профиле H03. Прежний интерфейс с внешним определением сохраняется для стендовых и раздельных компоновок, которые не задают ни одного из параметров профиля. Внутренний дескриптор подключён к существующему полю `rbm_h03_application_binding.engine`. Общий запуск передаёт его уже реализованному `lfj8_h03_engine_feed_target_init`. Foreground опрашивает тот же экземпляр, а Task 2 использует тот же квалификатор и старейшую метку.

Приёмник работает с общим `h03_can_owner.setup_generation`, нативным `lfj8_h03_mmio` и квалифицированным временем TML0 из `rbm_h03_atf_now_us`. `lfj8_h03_can_service_placement.py` привязывает три абсолютных имени к уже имеющимся полям типизированного блока `communication` и отвергает повторное выделение под тем же именем. Общая адресная сборка применяет эти алиасы при --with-can-service и актуальном --storage-report. Сервис CAN использует указатель DTC этого же дескриптора. В адресной модели на инвентаре M32R получены следующие интервалы:

| Символ | Диапазон с исключающим концом |
| --- | --- |
| `rbm_h03_engine_rx` | `0x808E40–0x808E78` |
| `rbm_h03_engine_qualifier` | `0x808E78–0x808E7E` |
| `rbm_h03_dtc_state` | `0x808F54–0x808F72` |

Профиль передаёт все четыре параметра:

| Имя | Источник и единица |
| --- | --- |
| `RBM_H03_PROFILE_ENGINE_MAX_AGE_TICKS` | Подтверждённый предел возраста RPM/ECT в тиках CAN0TSTMP. Должен быть в диапазоне 1…32767. |
| `RBM_H03_PROFILE_ENGINE_MAX_POLL_GAP_US` | Подтверждённый интервал опроса по TML0 в мкс с учётом худшего пути. Инициализация приёмника сохраняет предел 30 000 мкс. |
| `RBM_H03_PROFILE_ENGINE_BIT_TIME_US` | Доказанная верхняя оценка длительности тика CAN0TSTMP в мкс на целевой CAN. |
| `RBM_H03_PROFILE_ENGINE_CONTEXT` | IRQ-безопасный поставщик согласованного `Ta2005EngineQualificationContext` с консервативной старейшей меткой по тому же TML0. |

## Результаты

- Модель M32R проверила реальные абсолютные адреса трёх полей, общий DTC и CAN owner, привязку к его поколению и совпадение отметки с CAN-сервисом после допуска часов. Без допуска чтение времени отказало. Пройдены 16 шагов нативной службы и оба отказа без установленных переходов. Четыре неполных или не представимых профиля отклонены компилятором.
- На ПК прошёл 41 этап, включая 194 теста Python и сквозную модель.
- Широкая адресная композиция 39 порций удержала дескриптор с 36 байтами Flash и без нового кода или статической RAM. Для замера использованы только декларация внешнего контекста и параметры испытательного профиля. Компонент разрешён, контекст остался обязательной ссылкой. Весь известный состав вырос с 106 016 до 106 052 байт, верхний — с 102 428 до 102 464 байт при ёмкости 102 356. Дефицит верхних окон составил 108 байт до остальных отсутствующих частей. Полный статус остался `FAIL_BINDINGS`. Прирост стека от дескриптора отсутствует. Полный стек приложения требует отдельного измерения.
- Отдельно прошли 68 сценариев штатного запуска, прежняя нативная привязка с внешним дескриптором и пять тестов разрешения алиасов. Без параметров двигателя общая модель повторила исходные 106 016 байт и тот же статус FAIL_BINDINGS.

## Остаётся

Нужна самая ранняя пригодная метка, включая удержанные и резервные значения. Модель проверяла адреса, вызовы и отказ без допуска часов. Физический обмен и рабочий профиль ещё открыты. Блоки не прошивались.
