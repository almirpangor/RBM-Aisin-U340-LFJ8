# MODE-02 — квалификация кнопок в тракте селектора H03

Основа проверки — `a52ab8ce955959ed109d53e6c554beb68f814c2e` и H03 `LFJ8-T-D.bin` с SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

`lfj8_range_control_step_with_buttons` принимает нормализованный снимок M, `+`, `−` и OD со временем захвата. Устойчивость всей маски подтверждается новым снимком после настроенного интервала. Повторный опрос сам по себе не подтверждает переход. При потере, переполнении или истечении давности фильтр снова допускает команды после устойчивого отпускания. Время обработки и время захвата используют один 32-битный счётчик. Вызов передаёт состояние в существующий `rbm_u340e_step` вместе с декодированным положением селектора и возвращает логическую заявку передачи. Политика Auto, Tiptronic и OD берётся из переданного `RbmU340ePolicy`. [Контракт](../../targets/lfj8/lfj8_range_control.h) · [Реализация](../../targets/lfj8/lfj8_range_control.c)

## Проверки

- **ПК.** `tools/build_pc_checks.py` с Zig 0.13.0 прошёл 33 шага, включая 65 тестов Python. Сквозная проверка C подтверждает подавление дребезга при нажатии и отпускании, удержание, одноразовые `+`, `−` и OD, конфликт одновременных `+`/`−`, переход счётчика через ноль, отбрасывание повторных, переставленных и будущих снимков, потерю, истечение давности и повторное разрешение после отпускания. Числа в тесте задают границы сценариев. [Сценарии C](../../tests/u340_integration_host.c)
- **Сборка M32R.** `controller/build_target.py m32r` и `targets/lfj8/build.py` с GCC 4.8.0 собрали перемещаемые ELF, привязка моста проверена по SHA-256 H03. `check_h03_link.py` скомпоновал тестовый ELF. `range.o` содержит 812 байт кода, 0 байт статических данных и BSS. `sizeof(Lfj8ButtonFilter)` для M32R составляет 24 байта. Новые точки входа вызваны сквозным тестом. Штатный H03-планировщик их ещё не вызывает.
- **Модель M32R.** Сквозной сценарий с теми же проверками кнопок и 17 компонентных прогонов прошли. Сквозной прогон соответствует сохранённому результату ПК при воспроизведении `0x0FA=12c05f7400230000` и `0x278=b4ffffffffffffff`. Источник этих кадров — существующая проверочная трасса Bosch. [Трасса Bosch](../e4m3-can-9e1c/ordinary-model/round-trip.json)
- **Оборудование.** Проверка контактов, уровней, дребезга и времени на физическом блоке ещё не выполнена. Аппаратная приёмка и образ для записи остаются открытыми.

Команды из корня. Переменные `$zig`, `$m32rGcc` и `$h03` берутся из локальной конфигурации.

```powershell
python -B tools/build_pc_checks.py --cc $zig --out local/pc-checks
python -B controller/build_target.py m32r --cc $m32rGcc --out local/audit/controller
python -B targets/lfj8/build.py --output local/audit/bridge --m32r-cc $m32rGcc --base-9e1c $h03
python -B targets/lfj8/check_h03_link.py --base $h03 --gcc $m32rGcc --bridge local/audit/bridge/lfj8_9e1c_m32r.o --controller local/audit/controller/rbm_u340e_m32r_be.o --out local/audit/h03-link.json --bosch-trace verification/e4m3-can-9e1c/ordinary-model/round-trip.json
```
