# SRC-01 — проверка закреплённых Git-ревизий доноров

База — `b2ca79d006426a9839d64e8553cd81bf71953fe9`.

`verify_sources.py` проверяет наличие ровно того объекта commit, который
указан в `data/sources.json`. Источники Git читаются из закреплённой
ревизии через `rev-parse` и `cat-file`. Выбранная ветка, индекс и
рабочие файлы могут содержать другие версии. Локальные правила
`git replace` отключаются для этих команд.

```powershell
python -B tools/verify_sources.py --donor-repo $r1 --base-9e1c $h03 --repo R2 $chery --repo R3 $chery --repo R4 $r4
```

`--donor-repo` задаёт R1. Повторяемый параметр `--repo ID PATH`
добавляет локальный клон для другого зарегистрированного источника.
Для R2 и R3 подходит одна копия Chery-TA2005-U340E с обеими ревизиями.
Если запись образа ссылается на другой Git-источник, ему требуется
соответствующий локальный клон. Для образов по-прежнему отдельно
сверяются Git blob, длина и SHA-256.

## Результаты

- Проверены R1 `8cf4308d`, R2 `39bf857d`, R3 `7585de69`
  и R4 `dc6b4f08` из реестра. Прошли проверки ТЗ, S01–S04 и H03.
  Исторические S05/S06 пропущены.
- Два теста с временными Git-репозиториями прошли. Проверена
  маршрутизация образа через второй репозиторий с грязной рабочей
  копией и другим HEAD, а также отказ при отсутствии закреплённого
  объекта commit или при попытке использовать объект blob.
- Исходная команда SOURCES с одним R1 прошла. Передача клона R1
  как R3 вернула ошибку отсутствующего коммита.
- Изменения относятся к инструменту проверки на ПК. Правки реестра
  и аппаратные проверки в эту порцию не входили. Общий снимок аудита
  требуется актуализировать для двух файлов при интеграции.
