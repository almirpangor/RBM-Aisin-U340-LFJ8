# DTC-01 — отзыв очереди RX при потере допуска CAN

Основа `main` — `f64eff7c24744cef0fe608415039c6d10c677ff1`. Проверен исходный H03 `LFJ8-T-D.bin` с SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

Нативный путь `lfj8_h03_dtc_target_poll → lfj8_h03_can_owner_poll → lfj8_h03_dtc_foreground_poll` передаёт допуск TX13 и согласованную пару времени CAN/TML0. Потеря пары в нативном владельце отзывает допуск. Оборот без допуска теперь не передаёт тик T6 таймеру сеанса и не извлекает голову очереди. При отказе CAN13 штатное закрытие сеанса дополняется сбросом всей программной очереди, включая запросы очистки и открытия сеанса. Это также покрывает отказ CAN после получения пары времени. Текущие DTC и история сохраняются.

При отзыве проект не пишет в TX13 старого поколения. Повторный допуск после использованного поколения остаётся за существующим владельцем CAN, который ждёт освобождения аппаратных слотов и меняет поколение. Один пропущенный снимок времени у прямого вызова с сохранённым допуском сохраняет поведение FIFO. Штатное истечение C0 по T6 по-прежнему выставляет границу для кадров из аппаратного RX.

## Проверки

- На прежней реализации добавленная проверка воспроизвела сохранение запросов после отзыва. На исправленной прошли пять групп `check_h03_dtc_foreground.py` на ПК и M32R. Проверены bus-off после выборки времени, потеря пары на переполнении счётчика, очередь с запросом очистки и запросом открытия, отозванный допуск при занятом TX13 и ответ только на новый кадр после смены поколения.
- На исходном H03 прошли 18 сравнений BasicCAN со штатным кодом, три обхода резидентной врезки, проверки границы записи и стирания и регистровая модель Virtual Flash. Нативный тракт сохранил путь `0x732 → 0x722`.
- В отдельном проверочном worktree с DTC-02 `1e27a0f6dc02d66f62edbd3724af9d55b17d3e44` и DTC-04 `0ea8154b495bc10e565ecac034f19babadf3585f` повторены проверки foreground и BasicCAN, включая девять сценариев допуска нижних переходов. При отсутствии носителя очистка не отправила TX13, а чтение вернуло сохранённый P0710.
- `check_integrated_h03.py --suite native` прошёл 22 проверки. На ПК прошёл 41 шаг, включая 179 тестов. `project_status.py --check` прошёл на чистой `main`, а на рабочей ветке отметил три изменённых файла для приёмки интегратором.
- Объект foreground при GCC M32R 4.8.0 и `-Os` вырос с 296 до 364 байт кода без роста статической RAM. Время исполнения и стек на физическом H03 ещё не измерены.

```powershell
python -B targets/lfj8/check_h03_dtc_foreground.py --cc $m32rGcc --controller $controller
python -B targets/lfj8/check_h03_dtc_basiccan.py --base $h03 --gcc $m32rGcc --with-resident-target-rx --out local/dtc01/rx.json
```

Для аппаратной приёмки остаются подтверждение профиля T6 и его интеграции в общий запуск, назначение двух секторов DTC-04, постоянное хранение и проверка сеанса сканером. Прогоны выполнялись на ПК и в симуляторе.
