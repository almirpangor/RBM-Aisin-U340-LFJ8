# TOY-06. Давление и команда SLU в SECONDARY

20.11.2026. База `b2ca79d006426a9839d64e8553cd81bf71953fe9`.

`lfj8_h03_slu_secondary` принимает единый квалифицированный снимок и выполняет численный участок Toyota `05DCE8 → 055C5E`. Рассчитывает `GP−7136` из базового давления, выбранного знакового смещения, режима, температурной задержки и приоритетного значения `GP−7082`. Затем передаёт рассчитанное слово в характеристику S01 и возвращает команду с выбором обычной или форсированной ветви.

В состоянии сохраняются предыдущий режим `GP+1637` и счётчик `GP−4735`. Компонент сбрасывает счётчик при донорском переходе 1→2 с активным `GP−4828.7`. Его продвижение принадлежит вызывающему расписанию. При недостоверном снимке результат очищается, состояние сохраняется. [Разбор цепочки R3](https://github.com/almirpangor/Chery-TA2005-U340E/blob/7585de6945b4b6b3ef381c6062070a5f417cf588/docs/C167_SECONDARY_SLU_PRESSURE_RU.md)

## Что требуется для включения в H03

Для снимка ещё нужны производители смещений и приоритетного давления, исходные флаги и подтверждённое расписание счётчика. Для применения команды остаются физический выход, полярность, ток и проверка на стенде скольжения и снятия блокировки при отказе. Обновление общего аудита требуется при приёме коммита.

## Базовое давление 05DC5E

Продолжение от `583cf4a14897616018a6e08ee84dfa5c627b84b9`. Вызов `lfj8_h03_slu_secondary_from_baseline` вычисляет `GP−7026` по двум кривым с общим 12-байтовым банком обучения S01, знаковой поправке и базовому слову. Значения передаются из одного квалифицированного снимка. Учтены нулевая передача, приоритет режима 1, удержание предыдущего давления и пределы `2560…20480` в единицах донора. При обеих активных ветвях для итогового `GP−7032` используется кривая NT, которая у донора записывается последней. Сравнение относится к состоянию на границах вызовов. При отказе оба состояния сохраняются, а результат очищается.

| Уровень | Повторный результат |
| --- | --- |
| ПК, закреплённый R3 | Совпали `GP−7026`, `GP−7032`, выходное давление, таймер, режим и команда SLU в 120 сочетаниях флагов, 2 400 вариантах кривых и арифметики и пяти последовательных шагах. Шесть отказов прошли. Сценарии предыдущей порции повторены. |
| Общий набор ПК | 35 шагов и 71 тест без пропусков, Zig 0.13.0, донор S03 задан в `RBM_S03`. |
| Симулятор M32R, GCC 4.8.0 | 11 сценариев расчёта давления и команды, девять сценариев полной численной цепочки с базовым давлением и три отказа прошли. |
| Адресная модель M32R | Добавление новой точки входа в прежнюю раскладку вызывает `CAN extension window overflow`. В проверочном варианте с модулем часов фаз в основном окне 17 компонентных прогонов и интеграционный прогон прошли. |
| Оборудование | Привязка входов и выхода SLU, владение RAM/Flash, стек полного цикла, ток и поведение по отказу остаются открытыми. |

В адресном варианте основной диапазон занял 65 200 байт из 65 536, второй 15 800 из 16 100. Суммарный прирост к предыдущей модели 420 байт. Модуль `lfj8_h03_phase_clock.o` и три его точки входа перенесены в основное окно только при проверке `check_split_layout`. Остальные корни и границы обоих окон сохранены. Перемещаемые объекты совпадают с предыдущим прогоном по SHA-256 (`c92795ce…` для LFJ8, `c8ee987a…` для Toyota). Повторена модельная трасса Bosch с нормализованным SHA-256 `818627831cff4a55caaa2bd612dc411b4e5e63191e83f560a436de2246d88d2a`. Результат описывает ELF адресной модели.

Для воспроизведения области Flash запустить `check_h03_link.py` на точном H03 с теми же объектами и `verification/e4m3-can-9e1c/ordinary-model/round-trip.json` как `--bosch-trace`. К надстройке модели предыдущей порции добавить `lfj8_h03_slu_secondary_from_baseline` в `CAN_EXTENSION_ROOTS`. Только в вызове `check_split_layout` перенести `lfj8_h03_phase_clock.o` из `extension_objects` в `primary_objects`, а `lfj8_h03_phase_clock_init`, `lfj8_h03_phase_clock_release` и `lfj8_h03_phase_clock_take` из `extension_roots` в `H03_ROOTS`. Воспроизведение прежней раскладки выполняется без переноса модуля.
