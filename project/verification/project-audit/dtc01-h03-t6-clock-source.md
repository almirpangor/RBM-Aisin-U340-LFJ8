# DTC-01 — источник тиков T6 для CAN foreground H03

Ветка начата с опубликованной `main 20bf48d15b27608a39876bc96aacae68c705863a`. В неё включены обе сданные порции `c9d57c1fb0a038b06a5acff8aafffa639d3b0726` (таймер и очистка RX) и `ed5fd7118b1f4296a952a5811a9364d682e6b7a9` (нативный владелец CAN и привязка IRQ). Доска сохранила обе зависимости при новом claim. [Таймер C0](dtc01-h03-session-foreground.md) · [Привязка BasicCAN](dtc02-h03-native-owner.md)

## Подключение

`lfj8_h03_dtc_native_start_t6` фиксирует первый отсчёт квалифицированного TML0 и начальное значение тика T6. Приложение передаёт подтверждённый период как дробь в микросекундах и максимально допустимый интервал между отсчётами. `lfj8_h03_dtc_native_poll_t6` читает TML0 под той же блокировкой, сохраняет остаток дроби и передаёт вычисленный `diagnostic_tick` действующему владельцу CAN13. Счётчик T6 и TML0 оборачиваются независимо. Параметры ограничены так, чтобы сумма масштабированного интервала и остатка помещалась в 32 бита.

Для подключения из `rbm_h03_application_binding` нужны один экземпляр `Lfj8H03DtcT6Clock` в зарезервированной RAM и подтверждённые поля `Lfj8H03DtcT6Config`. После инициализации владельца и квалификации TML0 приложение вызывает `lfj8_h03_dtc_native_start_t6` до первого допуска CAN, а в CAN foreground использует `lfj8_h03_dtc_native_poll_t6`. При потере квалификации или превышении заданного интервала источник отключается, брокер отзывает допуск через обычный путь. Повторный запуск требует явной инициализации, смена фазы при действующем допуске отвергается. Интерфейс с внешним тиком T6 сохранён.

Изменены `targets/lfj8/lfj8_h03_dtc_native.c`, `targets/lfj8/lfj8_h03_dtc_native.h`, `targets/lfj8/h03_dtc_rx_hook_fixture.c` и `targets/lfj8/check_h03_dtc_basiccan.py`. Состояние часов принадлежит вызывающей стороне и занимает 28 байт по ABI M32R. В модели пересчёт и старт находятся выше приложения H03, вне нижнего графа RX.

## Проверки

- В нативном M32R-маршруте BasicCAN → CAN foreground → TX13 получен штатный ответ `0x722`. Дробный период `5/2` мкс используется только в модели. Проверены перенос остатка, переполнение обоих счётчиков, закрытие сеанса на девятой фазе, граница допустимого разрыва, шесть отказов настройки, отказ смены фазы при допуске и потеря часов во время сеанса. Восстановление регистра и новое поколение CAN сами по себе не запускают остановленные часы.
- `check_h03_dtc_basiccan.py --with-resident-target-rx` прошёл 18 сравнений BasicCAN, три обхода, контроль допуска записи/стирания и пробы теней Virtual Flash. Нижний участок в совмещённой модели занял 3472 байта `[0x006000, 0x006D90)`. SHA-256 сценариев `03549d419ea23515c4751bc109fcc2adbde12933c6cf9a2bebb83feb54ac3ba1`.
- Отдельно прошли сборки `--with-target-rx` и `--with-target-rx --can-owner-dir targets/lfj8`. Вторая повторяет тест T6 с нативным владельцем CAN вне нижнего размещения. SHA-256 её отчёта `d20d30b2edb22579c4a5a723dfcf5e17fd3530e6e8745168b0937fe428feac5c`.
- Сборка контроллера M32R и транспортный `check_h03_dtc_foreground.py` на ПК и M32R прошли. Проверены очередь на границе сеанса, отзыв TX13 и дальнейший приём.
- Общий прогон ПК завершил 41 шаг, включая 129 тестов Python без пропусков. Первый запуск остановился из-за отсутствия места на C:. После переноса кэша и временных файлов на D: полный повтор прошёл. `project_status.py --check` прошёл на исходной `main`. Общий снимок нужно обновить при объединении обеих основ ветки и этой порции.

Из S03 известно соотношение `T_T6 = 80000 / f_CPU`. Для подключения конкретного H03 ещё нужны подтверждённый физический период T6, фазовая база и предел фактического интервала вызовов CAN foreground. Также открыты итоговый `rbm_h03_application_binding`, назначение RAM, длительность маскирования IRQ, аппаратные часы и прогон штатным сканером. BIN для записи не создавался, блок не прошивался.
