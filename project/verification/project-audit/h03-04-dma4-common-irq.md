# H03-04 · DMA4 и ранние IRQ в общей компоновке

Основание — `main f64eff7`, порция DMA4 `4e954c1` и связанные нижние переходы DTC-02 `1bc3c22`. Использован H03 с SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

## Подключение

`tools/check_h03_image_layout.py --with-dma4-guard` включает штатный переход DMA4 `0x00CF0C` и очистку указателя BasicCAN на общем пути обоих векторов сброса. Для этого состава нужны `--with-bindings --with-dtc-rx --storage-report`. Общий компоновщик включает обе врезки в план на точных адресах, привязывает штатные продолжения и проверяет исходные и связанные слова.

По `0x003DBC`, когда SPI уже выставлен и IE ещё снят, новая обёртка в нижнем окне очищает существующее слово `.bss.irq_target`, восстанавливает регистр и выполняет исходное разрешение IE. Дополнительный указатель отсутствует. Адрес слова берётся из общей компоновки RAM. Этот же адрес входит в неизменяемую политику защиты DMA4 вместе с кандидатными областями приложения, монитором и условными стеками. В ELF сверяются адрес локального символа указателя, секция NOLOAD, размер слова и байты политики.

## Проверка

- В общем расчёте с защитой удержано 96 948 байт против 96 720 без флага. В заполняемых окнах добавлено 220 байт, ещё два слова по OEM-адресам заменяют существующие инструкции. Прежние четыре байта статической RAM сохранились. Для проверенного размещения указатель находится по `0x806F90`, ранняя обёртка по `0x006D5C`, DMA4-защита по `0x029CF8`. Собственный временный кадр ранней обёртки составляет четыре байта SPI.
- Общая компоновка вернула `FAIL_BINDINGS` для тех же семи определений приложения, датчиков и RAM, что и исходный прогон с BasicCAN. Проверочный `early-irq.elf` содержит только независимую связанную цепочку с адресами из того же плана. Сборщик проверил четыре OEM-перехода, модель RAM, единственную политику и отсутствие неопределённых ссылок внутри проверочной цепочки. Подмена адреса указателя в отчёте отклонена.
- Один и тот же проверочный ELF прошёл холодный `0x000000` и программный `0x000020` сбросы. На `0x003DBC` слово содержало `0xA5A5A5A5` при снятом IE. На `0x003DC0` IE выставлен, слово обнулено, SPI сохранился. Принудительный вызов CAN0 после этого прошёл через реально связанный проектный диспетчер и вернулся к `0x0013F0`. Отдельно прошёл наблюдатель по `0x001534` с продолжением `0x001538`. Обе ветви увидели нулевой указатель.
- В том же запуске DMA4 отклонил перенастройку на это слово до записи регистров и принял штатный буфер SIO0 по `0x80683A`. Два тестовых перехода после наблюдаемых точек добавлялись только в память симулятора для принудительного входа в CAN0 и последующего вызова DMA4. Срабатывание аппаратных IRQ и перенос DMA по шине в этот прогон не входят.
- Повторно прошли 12 сценариев DMA4 в `small` и `medium`, штатный прогон ранних SBI/DMA, девять сценариев сервисного допуска BasicCAN, 25 тестов размещения и шесть групп исполнения размещённого ядра.
- Все 41 этап ПК прошли. Python сообщил 182 теста, один пропущен из-за отсутствия локального образа S03.

```powershell
python -B tools/check_h03_image_layout.py --base $h03 --gcc $gcc --controller $controller --bridge $bridge --profile padding-candidate --with-bindings --with-dtc-rx --with-dma4-guard --storage-report $storage --out $layoutDir
python -B targets/lfj8/check_h03_boot_writers.py --base $h03 --gcc $gcc --placed-elf "$layoutDir/early-irq.elf" --layout-report "$layoutDir/layout.json"
```

## Остаток

Нужны окончательные поставщики общего приложения, полный охват писателей при старте и сервисе, определение `rbm_h03_boot_writers_owned`, замеры SPI/PSW с вложенными IRQ и подтверждение видимости размещённого кода при Virtual Flash. Проверка раннего CAN0 ограничена двумя связанными переходами. Адресный ELF предназначен для симулятора. Выпуск двух рабочих BIN остаётся открытым.
