# H03-03 — целевое определение привязки приложения

Рабочая ветка создана от `main 20bf48d` с инструментом координации
формата 2. До нового claim включены H03-03 `5c75117`, запуск с
восстановлением TOY-05 `4311060` и ранее сданные порции этого чата
H03-02 `e27adef`, VSS-02 `3ffed06`, MODE-01 `8974a4a` и TOY-03
`3f2596f`. Файлы штатного запуска и его общей проверки оставлены
за действующим резервом CAN-01.

## Привязка

`lfj8_h03_application_binding.c` определяет постоянный
`rbm_h03_application_binding` на существующем интерфейсе. Поля
указывают на типизированные места текущего инвентаря RAM.

| Символ | Поле RAM |
| --- | --- |
| `rbm_h03_takeover_state` | `control/takeover` |
| `rbm_h03_cycle_state` | `control/cycle` |
| `rbm_h03_runtime_state` | `control/runtime` |
| `rbm_h03_cycle_workspace` | `workspace/toyota` |
| `rbm_h03_main_result` | `communication/main_result` |
| `rbm_h03_cycle_input` | `workspace/cycle_input` |

Новые экземпляры перечисленных объектов привязка не создаёт.
Перед инициализацией платформы она повторяет проверку владения RAM
и очищает почтовый ящик AN2 под той же блокировкой, что и захват
AN2. После её снятия инициализируются прочие источники.
События штатного foreground и данные датчиков направляются в
предоставленные платформой функции отбора Toyota и обслуживания фазы.

Сборка модуля требует явный заголовок через
`-DRBM_H03_APPLICATION_PROFILE="..."` и путь поиска к нему.
Заголовок задаёт пять значений для существующего инициализатора:
`RBM_H03_PROFILE_PHASE_CONFIG`, `RBM_H03_PROFILE_STARTUP_RANGE`,
`RBM_H03_PROFILE_TOYOTA_MAX_PERIOD_TICKS`,
`RBM_H03_PROFILE_STARTUP_REQUEST_1120` и
`RBM_H03_PROFILE_READ_ADAPTATION`. Последнее поле задаёт источник
чтения слотов либо явно выбирает холодную базу S01 через `NULL`.
Профиль и реализация поставщиков должны сопровождаться доказательствами
целевого времени, первоначального состояния и владения ресурсами.

## Верификация и границы

- `check_h03_application_binding.py` собрал связанный ELF M32R с
  новым определением. Компиляция без заголовка профиля отклонена.
  Проверены адресные связи шести полей, сохранность содержимого RAM
  без разрешения, отказ без часов, сброс AN2 при холодном и тёплом
  старте, передача одного снимка обоим потребителям через
  нативную обёртку foreground и отзыв срока без следующей фазы.
  Профиль, разрешения платформы и OEM-сбор входов в этом ELF
  подставлены только испытательной программой.
- Штатный `check_h03_phase_boot.py` прошёл 56 сценариев и
  80 проверок контекста возврата из IRQ на точном H03 с
  объединёнными предыдущими порциями. В этом наборе используется
  отдельная штатная фикстура, включая проверки адаптаций.
- Прошли `check_h03_input_lifecycle.py`, привязка нативных
  S51/S83 и 11 пар штатных и кандидатных сценариев ATF.
- Отдельная частичная линковка M32R с тестовым заголовком и
  свежим отчётом ABI разрешила все семь ссылок на имеющиеся поля
  RAM, включая AN2. Само неизменяемое определение занимает
  92 байта. Остались восемь символов поставщиков платформы,
  объявленные в `lfj8_h03_application_binding.h`. Привязка
  испытана отдельно от итоговой компоновки Flash и защиты RAM.

```powershell
python -B targets/lfj8/check_h03_application_binding.py --gcc $gcc --controller $controller --out local/h03-03-binding/binding.json
python -B targets/lfj8/check_h03_phase_boot.py --base $h03 --gcc $gcc --controller $controller --out local/h03-03-binding/phase-boot.json
python -B targets/lfj8/check_h03_input_lifecycle.py --base $h03 --gcc $gcc --out local/h03-03-binding/input-lifecycle.json
```

Для целевого образа требуются утверждённый профиль, итоговые
адреса RAM, проверенные операции вывода, источник разрешения RAM и часов,
производители событий Toyota и обслуживания фазы, исходные данные GP
и `rbm_h03_sensor_config`. Аппаратные значения в эту порцию не внесены.
Завершение физической приёмки и выпуск BIN открыты.
