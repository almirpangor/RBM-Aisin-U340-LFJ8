# DTC-02 — нижний BasicCAN в сервисном режиме H03

База `main` `f64eff7c24744cef0fe608415039c6d10c677ff1`, H03 LFJ8-18-9E1C с SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

При `0x804887 = 4` и сброшенных прежних запретах (`0x80801C = 0`, `FCNT1 = 0`) исходные проектные обёртки вызывали `rbm_h03_dtc_rx_begin` один раз и `rbm_h03_dtc_rx_observe` три раза. Новый фильтр в [обеих обёртках](../../targets/lfj8/h03_dtc_rx_hook.S) использует тот же признак сервисного режима, что [действующая защита запуска CAN](../../targets/lfj8/lfj8_h03_can_monitor_startup.c). Врезки `0x001534` и `0x004738` обходят проектные обработчики и продолжают OEM BasicCAN. Подтверждение приёма и повторы выполняет исходный код H03. Обёртки не читают проектный указатель IRQ на пути обхода.

## Проверки

```powershell
python -B targets/lfj8/check_h03_dtc_service_gate.py --base $h03 --gcc $m32rGcc
python -B targets/lfj8/check_h03_dtc_basiccan.py --base $h03 --gcc $m32rGcc --with-resident-target-rx --out local/dtc02-resident.json
python -B -m unittest discover -s tests -p test_h03_dtc_rx_placement.py -v
```

- M32R связал обе ветви в нижний сектор. В состояниях `0` и `3` сохранились три доставки и три попытки OEM. В состоянии `4` обе точки вызова пропущены, включая вариант со стёртым верхним приложением. Три попытки OEM, их регистровый контекст и результат совпали со штатным путём. До изменения этот тест остановился на проектных вызовах в сервисном режиме.
- Повторены 18 сравнений BasicCAN, три прежних обхода, проверки Virtual Flash и границы штатной записи/стирания. Пройден путь `0x732` → нижний IRQ → очередь → foreground → `0x722` в CAN13. На ПК пройдены четыре проверки расчёта размещения и косвенных адресов.
- Изменение добавляет 24 байта к двум секциям кода, по 12 на обёртку. Нижний код и таблицы проверочного ELF занимают 3496 байт. Новых объектов RAM нет. Максимальная наблюдавшаяся запись стека 272 байта при активном сценарии и 68 при обходе. Это измерения модели одного маршрута IRQ.

Открыты установки обеих нижних ветвей в итоговую композицию, порядок раннего владения RAM, защита нижних страниц от Virtual Flash и фактическая граница записи на оборудовании. Для полного пути также нужны целевой CAN foreground и квалифицированные часы. Эта порция проверяет код нижнего пути в ELF симулятора. Рабочий BIN и стендовая приёмка остаются открытыми.
