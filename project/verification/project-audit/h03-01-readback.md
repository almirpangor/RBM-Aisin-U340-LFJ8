# H03-01 — сравнение readback LFJ8-18-9E1C

[Сверка readback](../../tools/check_h03_readback.py) принимает ожидаемый BIN длиной 524 288 байт со встроенным номером LFJ8-18-9E1C и один или несколько локальных файлов с байтами чтения. Начальный адрес каждого файла задаётся явно в координатах образа. Для полного чтения используется адрес `0x000000`. В JSON сохраняются SHA-256 ожидаемого BIN и каждого чтения, уникальное покрытие, непрочитанные интервалы и расхождения. Если два чтения перекрываются, каждый адрес считается один раз. Совпадающее чтение не скрывает расхождения в другом файле. [Условие приёмки REL-02](../../docs/lfj8-9e1c-minimum-bench.md)

```powershell
python -B tools/check_h03_readback.py --expected $expectedBin --read 0x000000 $readbackBin
python -B tools/check_h03_readback.py --expected $expectedBin --read 0x008000 $applicationRead --read 0x000000 $lowerRead
```

Адреса берутся из протокола конкретного считывания. Штатные маркеры, код и калибровки сравниваются байт в байт в пределах фактического покрытия. Оператор привязывает SHA-256 ожидаемого BIN к выбранной сборке и сохраняет протокол получения readback. Скрипт работает с файлами. Физическая доступность адресов, запуск контроллера и происхождение файла считывания устанавливаются отдельно на стенде.

| Код CLI | Результат |
| ---: | --- |
| 0 | `MATCH`, все адреса совпали |
| 1 | `MISMATCH`, найдено хотя бы одно расхождение |
| 2 | Некорректный ввод либо ошибка чтения |
| 3 | `PARTIAL_MATCH`, прочитанные байты совпали и есть непрочитанные адреса |

## Проверки на базе ae393e8

Прошли пять новых тестов на ПК, включая CLI, выход за конец, пропуск диапазонов и перекрывающиеся чтения с конфликтом. Прошли два прежних теста идентификации и сверка ТЗ, S01–S04 и точного H03 из реестра. [Тесты readback](../../tests/test_h03_readback.py)

Для проверки CLI из утверждённого H03 созданы временные срезы. Вместе они дали `MATCH` на 524 288 байтах. Срез только с `0x008000` дал `PARTIAL_MATCH` с пропуском 32 768 байт по `[0x000000,0x008000)`. Дополнительный перекрывающийся файл с изменённым байтом дал `MISMATCH` по `0x008000`, даже при полном покрытии. SHA-256 исходника `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`. Физическое чтение для этих проверок не выполнялось.
