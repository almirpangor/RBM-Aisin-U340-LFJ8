# MODE-02. Профиль AN2 и подготовка входов H03

База `main` `06ab447`. Код проекта подключён к штатному тракту AN2/P1DATA и к запуску H03. Исходный образ H03 проверен по SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

`RbmU340eSelectorProfile` принимает шесть непересекающихся окон `[min, max)` в порядке P/R/N/D/2/L и требуемое число последовательных отсчётов. Путь `lfj8_h03_input_capture` передаёт профиль существующему декодеру и фильтру, сохраняя прежний порядок проверки времени, отзыва селектора и сброса фронтов кнопок. Старый API оставляет прежние окна и четыре отсчёта для существующих вызовов.

Для нативного профиля `RBM_H03_PROFILE_TOYOTA_INPUT_STARTUP` указывает неизменяемую политику режима и измеренные интервалы селектора и кнопок. После общей подготовки входов и повторной проверки RAM и TML0 платформа H03 сбрасывает существующих владельцев селектора и кнопок до подготовки CAN. Привязка сверяет единственный штатный AN2 mailbox и тот же MMIO. Для этого запуска обязательны валидные окна селектора. Сброс mailbox остаётся в общей привязке приложения.

## Проверки и память

- Сборка controller и моста 9E1C прошла. `check_h03_input_binding.py` на ПК и M32R проверил все шесть диапазонов по отдельной испытательной таблице, включительность нижней и исключительность верхней границы, число отсчётов, отказ перекрывающихся окон, выход за 10-битную шкалу и удержание UP при перезапуске. Штатные проверки прежней таблицы, кнопок и логики режима тоже прошли.
- `check_h03_target_platform.py --base` прошёл для существующих профилей. Дополнительный прогон на локальной копии симуляторного сценария подключил новый объект startup, убрал инициализацию режима из тестового callback и использовал отдельные AN2-коды N/D. Штатный запуск, foreground, MAIN S1/S2 и отзыв команды прошли по адресам общего плана M32R.
- M32R big-endian medium, GCC 4.8.0, `-Os`. Суммарная прибавка загружаемых секций трёх объектов контроллера и адаптера составила 266 байт. Включение startup в платформу добавило 92 байта. Удерживаемый код и данные профильной модели выросли с 100 540 до 100 898 байт Flash. Отдельные внешние константы занимают 26 байт окон и счётчика, 16 байт политики и интервалов и 4 байта указателя в неизменяемой привязке. Новой mutable RAM нет. Собственный кадр `lfj8_h03_input_startup` занимает 12 байт без вызываемых функций.
- Прошли 22 штатные группы M32R, шесть групп исполнения размещённого ядра и 57 тестов Python `test_h03*.py`. Повторная общая композиция известных поставщиков с декларацией нового startup удержала 106 374 байта и ожидаемо вернула `FAIL_BINDINGS`. Верхней части требуется 102 786 байт при 102 356 доступных. Дефицит 430 байт относится к этому составу до добавления недостающих поставщиков и данных.

```powershell
python -B controller/build_target.py m32r --cc $gcc --out local/mode02/controller
python -B targets/lfj8/build.py --output local/mode02/bridge --m32r-cc $gcc --base-9e1c $h03
python -B targets/lfj8/check_h03_input_binding.py --gcc $gcc --controller local/mode02/controller/rbm_u340e_m32r_be.o --out local/mode02/input.json
python -B targets/lfj8/check_h03_target_platform.py --base $h03 --gcc $gcc --controller local/mode02/controller/rbm_u340e_m32r_be.o --bridge local/mode02/bridge/lfj8_9e1c_m32r.o --out local/mode02/platform.json
```

## Остаток

Физический профиль должен задать измеренные окна AN2 всех шести положений, число отсчётов, интервалы свежести и дребезга, распиновку и полярность P1DATA/OD и согласованную политику режимов. Остаются квалифицированный поставщик Toyota driver/range/load и его отдельные операнды. Параметры проверки принадлежат модели. Итоговый профиль, общий линк, физическая проверка и выпуск BIN открыты.
