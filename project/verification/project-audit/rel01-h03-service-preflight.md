# REL-01 — проверка сервисных записей H03 перед выпуском

Проверена выбранная основа H03 `LFJ8-T-D.bin` для LFJ8-18-9E1C. Инвентарь M32R для `main e24ae2c` повторно дал 2 532 байта. Границы ниже взяты из измеренного ABI и совпали с сохранённым отчётом. В карточке H03-04 на этом срезе остались прежние верхние границы. Кандидат от H03-03 `7ced523` ещё на отдельной проверке, его состояние и стек в этот расчёт не входят. [Исходный отчёт RAM](integration-3/final-storage.json)

| Область | Начало | Конец, исключая |
| --- | --- | --- |
| Управление | `0x806B40` | `0x806F78` |
| Обмен | `0x808E40` | `0x809034` |
| Рабочий буфер | `0x809034` | `0x8093EC` |

## Что подтвердил симулятор

- Исходный прямой писатель `0x002924 → 0x002978` изменил крайние байты каждой из трёх областей. Штатная проверка запретила контрольную прямую запись внутрь своего защищённого участка. Отдельный прогон проверки диапазонов подтвердил допуск всех 2 532 байт модели в 11 непересекающихся интервалах.
- Исходное закрытие `0x002E80` снимало активный бит сеанса, при этом следующий вход ADC0 `0x003608 → 0x0035F4 → 0x002D1C` выполнял отложенные записи по `0x002DE0`. Передача на 257 байт прошла двумя вызовами, сначала 256, затем 1. Передача, начатая на байт ниже блока управления, изменила его первый байт. Исполнитель готовой отложенной операции также достиг контрольного адреса, который отверг прямой писатель. Этот сценарий начинается с подставленного состояния операции.
- Нулевой остаток копирования сохранял контрольные байты. При 257 байтах незавершённой контрольной суммы первый вызов обрабатывал 256 байт суммы, оставлял один байт и откладывал копирование. Проверялись оба остатка, оба указателя, значение суммы и контрольные байты по краям записи.
- Все 18 сценариев повторены с исходным селектором Virtual Flash и с принудительной ветвью выключения, применённой только в памяти симулятора. При выключении `FCNT1: 1 → 0` и `FESBANK1: 0x8020 → 0x0020`. Итоговые записи RAM в обоих вариантах совпали. Физическое наложение страниц, допуск внешней команды монитором и периферия платы остаются за рамками прогона. [Проверка CPU](../../targets/lfj8/check_h03_service_writes.py)

## Условия до записи H03

1. Исключить новые сервисные записи в проектные диапазоны и завершить или отменить уже принятые операции до передачи RAM рабочему циклу. Это отдельное условие от блокировки Virtual Flash. Проверка должна учитывать пересечение полного диапазона копирования с проектной RAM.
2. Повторить проверку на окончательной карте линковщика с включёнными привязками H03-03 и других подсистем. Отдельно подтвердить резидентность кода, констант и путей возврата, стек и безопасный запрет силовых выходов.
3. Для модели отключения Virtual Flash требуются четыре байта по `0x003568`. Штатный H03 отклоняет этот адрес и `0x007FFF`, допускает `0x008000`. Документация PCM Flash перечисляет профиль Melco Mazda5/6 512 КБ модуля 08 с чтением, записью и контрольной суммой. Покрытие ниже `0x008000` для LFJ8-18-9E1C остаётся неподтверждённым. Для выбора варианта нужны точный профиль и подтверждённая карта записи либо проектное решение, размещаемое в пределах подтверждённого диапазона. [Руководство PCM Flash](https://eu.pcmflash.ru/legal/manual.pdf) · [Штатная граница и проверка 128 страниц](../e4m3-can-9e1c/h03-vflash-lockout.json)

PCM Flash в этом прогоне не запускался. Работа выполнялась на точном исходнике и модели M32R. Записываемые BIN H03 и Bosch не собраны.

```powershell
python -B targets/lfj8/check_h03_vflash_lockout.py --base $h03 --gcc $m32rGcc --out local/rel01-h03/lockout.json
```
