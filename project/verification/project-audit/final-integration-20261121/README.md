## Почему пока нет готового BIN

- Старый prefix-кандидат не вмещает даже удерживаемое ядро: 84470 байт. Расширенная padding-модель прошла, но она не заменяет исполняемое приложение.
- С реальной native binding и нижним BasicCAN известны 101026 байт Flash. Для измерения использованы только временные числа из SIMULATOR_ONLY_PROFILE; они не являются калибровкой автомобиля. Поставщики платформы не заменялись заглушками. Полный состав не связан.
- В combined-profile/protected_padding.json перечислены 10 неопределённых символов: rbm_h03_sensor_config и rbm_h03_target_clock_ready, engine, initialize, ram_owned, service_phase, startup_gear, startup_gp, take_toyota, takeover_ops.
- Существование оболочки binding не закрывает производителей нагрузки Toyota, подтверждённые шкалы/возраст входов, физические выходы SLT/SLU и их отказ. Проверка оригинала H03 выявляет продолжающийся PWM на TIO9/P97 после общего запрета; это отражено в допуске изоляции.
- Окончательные NVM/адаптации, полный стек, все переходы и владение памятью ещё требуют завершения. Наличие десяти символов — точный текущий отказ линкера, а не утверждение, что достаточно задать десять констант.

## Воспроизведение

В манифестах PC-CHECKS.json и */summary.json сохранены команды. Использовать свежие controller/bridge и storage.json. Данные запуска сохранены на D:/RBM-Integration-20261121-final, чтобы не заполнять C: временными сборками. check-combined-profile.py воспроизводит измерение с явно тестовым профилем и не создаёт BIN. Никакие BIN/ELF из локального каталога не являются выпуском для автомобиля.
