# TOY-03 — квалификация независимых операндов диапазона Toyota

Основа — `b2ca79d006426a9839d64e8553cd81bf71953fe9`. Контракт штатного потребителя описан в [карте входов H03](../../docs/lfj8-h03-input-paths.md#независимые-признаки-диапазона-toyota-toy-03).

`lfj8_h03_range_snapshot` собирает GP−5722[3:0] из четырёх нормализованных входов. Пятый вход от производителя состояния двигателя отдельно задаёт GP−5250.2. Для каждого входа нужны подтверждение пригодности источника, нормализованный уровень 0 или 1, время захвата и общее текущее поколение. Положение селектора из AN2 передаётся циклу отдельно. Ответвления физической проводки и полярности задают производители входов после их подтверждения. [Интерфейс](../../targets/lfj8/lfj8_range_control.h) · [Реализация](../../targets/lfj8/lfj8_range_control.c)

Каждый возраст проверяется по отдельному пределу. Предел задаёт владелец по данным измерения, а равенство пределу означает истечение срока. Снимок возвращается целиком только при пригодности всех пяти входов, иначе результат очищается и функция возвращает 0. Старейшая метка определяется сравнением возрастов относительно одного `now_us`, в том числе через переход 32-битных часов через ноль. При сбросе часов или пропуске половины периода счётчика вызывающий код начинает новое поколение и заново получает значения.

Для вызова `lfj8_h03_cycle_tick` владелец расписания дополнительно проверяет селектор и остальные операнды. Он учитывает `oldest_us` при выборе самой ранней метки для `command_at`. Существующие проверки общего GP и рабочего допуска сохраняют свои условия. [Контракт цикла](../../targets/lfj8/lfj8_h03_cycle.h)

## Проверки

Сквозная C-фикстура проверяет все 32 сочетания нормализованных уровней с переходом часов через ноль. Для каждого из четырёх битов диапазона отдельно проверены отсутствие подтверждения, прежнее поколение и точная граница давности. Для входа двигателя отдельно проверены поколение, граница давности и некорректный признак пригодности. Добавлены проверки будущей метки, недопустимого значения, неверных пределов и отсутствующих аргументов. При отказе проверяется очистка ранее заполненного результата. Старейшая метка может принадлежать как входу диапазона, так и входу двигателя. [Сценарии ПК и M32R](../../tests/u340_integration_host.c)

- **ПК.** Zig 0.13.0, 35 шагов и 71 тест Python. Сквозная C-фикстура и проверка закреплённого донора S03 через `RBM_S03` прошли.
- **Сборка M32R.** GCC 4.8.0 собрал перемещаемые объекты контроллера и моста. Компоновка проверена на точном H03 `LFJ8-T-D.bin` с SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`. Новый код входит в `range.o`, который компонуется в тестовый ELF.
- **Модель M32R.** Сквозная C-фикстура прошла с исходными кадрами сохранённой трассы Bosch и совпала с эталонным выходом ПК. Прошли 17 компонентных прогонов. [Сохранённая трасса](../e4m3-can-9e1c/ordinary-model/round-trip.json)

## Передача интегратору

Остаётся подключить производителей и потребителя к штатному циклу, подтвердить физические независимые цепи, полярности, условия обновления и фактические пределы возраста. Тестовые возраста и нормализованные уровни относятся к модели. Аппаратная приёмка и целевой BIN остаются открытыми. `project_status.py --check` отмечает три изменённых файла кода, их нужно учесть в общем снимке аудита при приёмке порции.
