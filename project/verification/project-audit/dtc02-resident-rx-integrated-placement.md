# DTC-02 — нижний BasicCAN в общей модели компоновки H03

Основа проекта `20bf48d15b27608a39876bc96aacae68c705863a`. Рабочая ветка содержит сданные DTC-02 `ed5fd71`, CAN-02 `b6dccd6`, MODE-03 `64dd049`, CAN-03 `1876a8c` и пересекающийся H03-02 `e27adef3`. Закреплённый H03 имеет SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

Флаг `--with-dtc-rx` в общей адресной модели удерживает обе обёртки IRQ, нативный адаптер и граф кода, достижимый из IRQ. Линкер вычисляет прямую достижимость из того же объекта, который использует общая компоновка. Нижнее окно `0x006000–0x007FFF` зарезервировано для этого графа и его констант. Таблица операций лежит в нижнем окне, её обработчик foreground остаётся выше приложения. Адрес единственного `h03_can_owner` берётся из проверенного инвентаря RAM. Отдельно учитываются четыре байта существующего указателя IRQ.

В известном составе нижний граф занимает 3 224 байта, верхнее приложение и нижний граф вместе занимают 92 078 байт. Владельцу CAN соответствует кандидатный адрес `0x808F3C`. Отчёт рассчитывает переходы по `0x001534` и `0x004738` после сверки исходных слов, вектора CAN0 и границы сектора. При полном линке дополнительно сверяются абсолютные адреса продолжений, адрес владельца и косвенные вызовы из таблиц MMIO и CAN. В текущем составе план ветвей имеет статус `PROVISIONAL_UNLINKED`.

## Проверки

- На закреплённом H03 общий расчёт с `--with-dtc-rx` разместил нижние секции и сохранил обе ветви в отчёте. Полный линк вернул `FAIL_BINDINGS`. ELF с незаполненными символами не публикуется.
- Совместная проверка с типизированными RAM-алиасами и нативной обвязкой CAN из `check_h03_can_monitor_revoke.py` разместила 96 454 байта известных секций. Остались два неопределённых символа, `rbm_h03_application_binding` и `rbm_h03_sensor_config`. Для этого прогона общий адресный расчёт вызывался с `with_dtc_rx=True`.
- Прежний профиль `prefix-candidate --cpu-test` прошёл шесть тестов по адресам размещения. Контроллер и мост пересобраны для big-endian M32R. Стандартная компоновка прошла 11 интеграционных и 18 компонентных проверок.
- Отдельный M32R-прогон нижнего пути сохранил все 18 сравнений со штатным BasicCAN, три обхода и проверки допуска записи и стирания. Запрос `0x732` дошёл до записи `0x722` в CAN13. Это отдельный ELF симулятора.
- Четыре новых проверки проверяют изменения исходных слов и вектора, отказ при выходе ветви из нижнего окна, отделение foreground и распознавание неправильных косвенных адресов.

```powershell
python -B targets/lfj8/check_h03_storage.py --base $h03 --gcc $m32rGcc --out $storageReport
python -B tools/check_h03_image_layout.py --base $h03 --gcc $m32rGcc --controller $controller --bridge $bridge --storage-report $storageReport --profile padding-candidate --with-bindings --with-dtc-rx --out local/dtc02/address-model
python -B targets/lfj8/check_h03_dtc_basiccan.py --base $h03 --gcc $m32rGcc --with-resident-target-rx --out local/dtc02/native-irq.json
```

Остаются рабочие определения `rbm_h03_application_binding` и `rbm_h03_sensor_config`, подтверждённый источник T6, привязка `native_ready` и доказательство раннего владения RAM. Запрет наложения Virtual Flash на нижний сектор и окончательные диапазоны записи относятся к общей компоновке и аппаратной приёмке. Блоки не прошивались.
