# VSS-02 — определение конфигурации датчиков из входных измерений

Проверено на базе `main ae393e8` и штатном
LFJ8-18-9E1C H03 SHA-256
`844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

`targets/lfj8/check_h03_sensor_config.py` сохраняет режим проверки
штатного H03 и парных отсчётов часов. При передаче профиля он сверяет
оба таймера с 1 МГц в указанном допуске, проверяет диапазоны полей C
и сравнивает явно заданные пределы с измеренными максимумами.
`--emit-config` печатает целевое определение
`const Lfj8H03SensorFeedConfig rbm_h03_sensor_config` только после прохода
этих проверок. Пределы переносятся из профиля без пересчёта. В C
сохраняются SHA-256 H03, профиля и файла отсчётов.

## Входы

Файл `--clock-reference` содержит `max_error_ppm` и `intervals`.
В каждом интервале задаются `elapsed_us` независимого эталона и
две пары `tml0` и `tml1` вида `[начало, конец]`. Захваты относятся
к одной внешней шкале времени.

В `--calibration-profile` обязательны `base_sha256` точного H03,
`evidence_id` журнала измерений, объекты `limits` и `observed_maxima`.

| Поле в `limits` | Поля в `observed_maxima` | Единица |
| --- | --- | --- |
| `s51_timeout_ticks` | `s51_period_ticks`, `s51_age_ticks` | такты |
| `s83_timeout_ticks` | `s83_period_ticks`, `s83_age_ticks` | такты |
| `atf_max_age_us` | `atf_age_us` | мкс |
| `max_read_span_ticks` | `read_span_ticks` | такты TML0 |

Для S51 и S83 нужны максимальные периоды отдельных фронтов и
возраст последней метки при опросе в допускаемом рабочем диапазоне.
Возраст ATF считается от захвата AN1. Окно чтения — интервал
между двумя чтениями TML0 вокруг чтения TML1.

```powershell
python -B targets/lfj8/check_h03_sensor_config.py --base $h03 --clock-reference $clockCapture --calibration-profile $profile --out $report --emit-config | Set-Content -Encoding ascii $configSource
if ($LASTEXITCODE -ne 0) { throw "H03 sensor config rejected" }
```

Отчёт `PASS_CONFIG_INPUTS` означает внутреннюю согласованность
переданных чисел. При рассогласовании часов код отсутствует на
stdout. При ошибке структуры или выхода за пределы команда также
завершается с ненулевым кодом.

## Проверки и ограничения

- `tests/test_h03_sensor_config.py` прошёл 5 групп проверок. В том числе
  проверены перенос TML0, остановка каждого таймера, привязка SHA,
  обязательность измерений, границы полей и отсутствие C при отказе.
- Существующие 11 тестов `test_vss_measurements.py` прошли.
  Проверка без профиля на точном H03 дала `PASS_STOCK_ONLY`.
- `check_h03_sensor_native.py` прошёл на исходном и кандидатном
  ELF. Отдельно сгенерированный по синтетическим входам C собран
  M32R GCC. Поля сверены в 16-байтовом объекте big-endian, а
  реальный модуль датчиков разрешил ссылку при компоновке.
- Повтор расширенной компоновки с нативным CAN и типизированными
  адресами RAM удержал 94 786 байт Flash, включая тестовый объект.
  В списке неопределённых символов остался
  `rbm_h03_application_binding`. Статус модели `FAIL_BINDINGS`.

Синтетический профиль и выходной C хранятся только в игнорируемом
`local/` тестовой копии. Для целевого профиля остаются замеры
TML0/TML1, периодов и возраста S51/S83, задержки ATF и окна чтения.
Отдельно нужны подтверждённые масштабы S83 и ходовой части, независимое
подтверждение остановки и проверка скорости на CAN. Стендовая
проверка и выпуск BIN не выполнялись.

`project_status.py --check` отмечает изменённый инструмент и его тест.
Общий снимок готовности обновляет интегратор после объединения.
