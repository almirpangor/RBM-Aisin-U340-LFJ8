# TOY-01. Трёхбайтовые дескрипторы GP

База `e24ae2ca05677df9e3a2326e43b9cbc6c67e23db`. Генератор хранит позицию в GP в 10 битах, смещение в нативном объекте в восьми, маску перестановки байтов элемента в двух, длину участка минус один в четырёх. Четыре исходные строки массивов длиннее 16 байт разбиты по границам элементов. Итоговые 296 дескрипторов описывают прежние 292 поля. При сборке проверяются размер формата, граница GP, размер каждого поля и представимость его нативного смещения. [Генератор](../../controller/hydraulic_port.py).

## Сборка и размер

Оба замера используют GCC M32R 4.8.0, точный H03, один объект переходника LFJ8 и один набор из 116 обязательных корней в расширенной адресной модели. Входные таблицы и исходники Toyota проверены по существующему манифесту.

| Показатель | База | Трёхбайтовый формат |
| --- | ---: | ---: |
| Девять символов `map_Factory*` по `m32r-elf-nm -S` | 1 168 Б | 888 Б |
| Код расширенного ELF | 75 128 Б | 75 188 Б |
| Данные только для чтения расширенного ELF | 6 956 Б | 6 676 Б |
| Основное окно расширенной модели, из 65 536 Б | 64 140 Б | 63 920 Б |
| Второе окно расширенной модели, из 16 100 Б | 17 944 Б | 17 944 Б |

Чистая экономия ELF составила 220 байт. Строгая модель сохранила 3 412 байт в основном окне и 720 во втором. Расширенная модель закономерно отказала из-за превышения второго окна на 1 844 байта. Суммарный дефицит обоих окон уменьшился с 448 до 228 байт. [Замер базы](integration-3/expanded/unbounded-sizing.json).

## Проверки модели

- На ПК прошли 37 шагов и 102 теста Python. После усиления шаблона данных отдельно повторена сборка контроллера с Zig 0.13.0. Проверены все 292 поля и пять донорских снимков. Во временной копии отброшены старшие биты смещения только во время теста переносов. Проверка остановилась на сравнении ожидаемого и полученного значения.
- GCC M32R выполнил тот же усиленный тест переносов и проверки контроллера. Объект `rbm_u340e_m32r_be.o` после усиления тестового шаблона побайтно совпал с объектом, использованным в компоновке и связанных прогонах. SHA-256 `a0bc50d2a460d10fb298489af11ef2fad550a01126a393268a530e7bb5919216`.
- Прошли 18 компонентных прогонов и сквозной сценарий строгой адресной модели, 17 штатных групп M32R и пять дополнительных групп. Замер `lfj8_h03_cycle_tick` снова показал 720 байт максимальной записи в стек на 37 414 вызовах.

```powershell
python -B tools/build_pc_checks.py --cc $zig --out local/toy01-gp/pc
python -B controller/build.py --cc $zig --out local/toy01-gp/host
python -B controller/build_target.py m32r --cc $m32rGcc --out local/toy01-gp/controller
python -B targets/lfj8/check_h03_link.py --base $h03 --gcc $m32rGcc --controller $controller --bridge $bridge --bosch-trace verification/e4m3-can-9e1c/ordinary-model/round-trip.json --out local/toy01-gp/strict.json
python -B tools/check_integrated_h03.py --suite expanded --base $h03 --gcc $m32rGcc --controller $controller --bridge $bridge --bosch-trace verification/e4m3-can-9e1c/ordinary-model/round-trip.json --out local/toy01-gp/expanded
```

Команды `--suite native` и `--suite components` использовали тот же объект контроллера. Для GCC 4.8.0 на Windows штатные прогоны выполнялись из копии проверенных исходников с ASCII-путём. Для полного набора на ПК использован проверенный S03 в `RBM_S03`.

## Остаток

Интегратору предстоит повторить замер после объединения остальных порций и разместить полный состав в доступных окнах. Замер стека относится к симулятору и вызванным сценариям. Компоновка выпуска, полный стек с вложенными IRQ и приёмка на оборудовании остаются открытыми. `project_status.py --check` отмечает `controller/hydraulic_port.py` до обновления общего снимка аудита.
