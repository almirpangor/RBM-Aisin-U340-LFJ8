# MODE-02 — публикация отсчёта селектора из штатной функции H03

Основа проверки — `b2ca79d006426a9839d64e8553cd81bf71953fe9` и H03 `LFJ8-T-D.bin`, 524 288 байт, SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

Штатный вызов `0x00816C → 0x040324` получает ADC0 AN2 и сохраняет 10-битный результат в `0x804BC6`. Кандидат на перехват входит через `BRA` вместо пары инструкций `2024 6103` по `0x040370`. Он выполняет исходный `sth r0,@r4`, передаёт уже сдвинутый отсчёт в `rbm_h03_selector_adc_capture(uint16_t raw)` при сброшенном IE, восстанавливает контекст, повторяет `ldi r1,#3` и продолжает по `0x040374`. Приложение предоставляет функцию публикации по ABI C, её часы и состояние очереди. [Адаптер](../../targets/lfj8/h03_selector_adc_hook.S)

## Целевая сборка и модель

- **Сборка.** GCC M32R 4.8.0 собрал и скомпоновал отдельный тестовый ELF из штатного фрагмента, адаптера, существующих функций публикации и MMIO. Кадр адаптера до входа в C занимает 44 байта по измерению в симуляторе. Общий стек с целевой функцией публикации и вложенными IRQ требует отдельной проверки.
- **Модель M32R.** Четыре пары прогонов штатного и изменённого пути. Исходные инструкции H03 исполняются по штатным адресам, ответы периферии и отдельные соседние подпрограммы подставляет существующий тест foreground. Сравнены R0–R15, CR0, ACC, слова AN2/AN3/AN4 и байт статуса. Функция публикации вызвана один раз после записи AN2 и до обработки AN3. Она использует существующую очередь селектора и MMIO. Метки времени в таблице заданы тестом. [Проверка](../../targets/lfj8/check_h03_selector_adc.py) · [Функция для симулятора](../../targets/lfj8/h03_selector_adc_fixture.c)

| 0 | 1 / 0 | 0 | VALUE |
| 347 | 1 / 1 | 101 | VALUE |

Проверка отвергла подмену канала AN3, пропуск маскирования IRQ и пропуск восстановления младшего слова ACC во временных копиях адаптера. Прогон между запуском штатного пути и завершением адаптера идёт без точек останова GDB, поскольку они меняют PSW в GNU-симуляторе.

- **Регрессия ПК.** Zig 0.13.0, 35 шагов с кодом 0 и 71 тест Python. Для проверки точного донора таблицы DTC задан `RBM_S03` из закреплённого Git blob R1.
- **Регрессия M32R.** Перемещаемые ELF контроллера и моста собраны. `check_h03_link.py` прошёл 17 компонентных прогонов и сквозной прогон с проверками события и давности ADC. `check_h03_foreground.py` прошёл три пары отдельного сравнения штатной функции и существующей обёртки. Прогоны проверяют программные компоненты и модели размещения.

Команды из корня. `$h03`, `$m32rGcc` и `$zig` берутся из локальной конфигурации.

```powershell

python -B tools/build_pc_checks.py --cc $zig --out local/pc-checks
python -B controller/build_target.py m32r --cc $m32rGcc --out local/audit/controller
python -B targets/lfj8/build.py --output local/audit/bridge --m32r-cc $m32rGcc --base-9e1c $h03
python -B targets/lfj8/check_h03_link.py --base $h03 --gcc $m32rGcc --bridge local/audit/bridge/lfj8_9e1c_m32r.o --controller local/audit/controller/rbm_u340e_m32r_be.o --out local/audit/h03-link.json --bosch-trace verification/e4m3-can-9e1c/ordinary-model/round-trip.json
```

## Остаток MODE-02

Для интеграции нужно подключить функцию публикации к инициализированной очереди и общему монотонному счётчику H03, определить размещение адаптера и данных, измерить бюджет IRQ и период опроса, затем передать заявку передачи в полный цикл Toyota. Для стенда остаются шесть напряжений на селекторе, переходы между положениями, уровни и полярности M/`+`/`−`, источник OD, реакция на обрыв и фактические сроки фильтрации. Сборка ограничена тестовыми ELF и объектами. Аппаратная проверка открыта.
