# CAN-01 — метка RPM и ОЖ в штатном Task 2 H03

Основа `f64eff7c24744cef0fe608415039c6d10c677ff1`. Порция использует включённый в main вызов двигателя в startup и OEM foreground.

`lfj8_h03_engine_feed_target_task2` получает общие квалифицированные часы TML0 под тем же исключением, что и приёмник. Для каждого фактически опубликованного значения берётся нижняя граница метки времени приёма. Из раннего отсчёта TML0 вычитается возраст CAN0 в битовых тиках с поправкой на один тик квантования. При неподвижном CAN0 прежний отсчёт остаётся опорой. Период тика является обязательным параметром `bit_time_us`, без значения инициализация источника отклоняется.

При штатном удержании RPM квалификатор пользуется меткой кадра, который обновил обороты. Переинициализация RX, потеря допуска или смена поколения сбрасывают её. Обороты без датированного источника передаются как недоступные. Для температуры по CAN берётся метка температурного кадра. Метку резервного источника и прочих операндов контекста предоставляет вызывающий слой. `prepare_engine` передаёт старейшую из этих меток через `input.command_at` в действующий цикл H03. [Код вызова](../../targets/lfj8/lfj8_h03_application.c) · [Код квалификации](../../targets/lfj8/lfj8_h03_engine_feed.c)

## Проверка и расход памяти

- Штатный маршрут запуска и foreground прошёл 62 сценария M32R. В сценарии `engine` приёмник проходит отзыв и новое поколение. После восстановления контрольная запись декодированного кадра в кэш RX дала ожидаемые RPM и более ранний `command_at` в настоящем Task 2. Само чтение FullCAN отдельно проверено на модели регистров с подтверждением флагов.
- Регрессия на ПК и M32R проверяет переход CAN0 и TML0 через ноль, старейший ECT, удержанный RPM после истечения кадра, сброс при смене поколения, метку резерва и отказ без масштаба CAN0.
- Общий прогон ПК прошёл 41 шаг и 179 тестов Python. Модель размещённого ядра прошла шесть проверок выполнения кода по адресам.
- Пересобраны контроллер и мост. Компоновка и модель M32R прошли 11 интеграционных и 18 компонентных проверок. Для прогона понадобилось локально добавить `rbm_u340e_runtime_prepare_s01_cold` в корни `check_h03_link.py`. В опубликованной main этот корень пропущен в компактном наборе, а компонентный тест уже вызывает его. Файл находится в действующем резерве H03-04.
- Инвентарь RAM M32R вырос с 2728 до 2736 байт, отдельно остаются 4 байта указателя IRQ. `engine_rx` занимает 56 байт. Измерение отдельных объектов GCC 4.8.0 показало рост кода и констант на 344 байта. Собственный кадр стека Task 2 вырос с 56 до 68 байт по инструкциям пролога. Общий стек и время блокировки на устройстве остаются открытыми.
- Проверка совмещённой CAN-обвязки с RAM-алиасами разместила 101 380 байт известного состава. Полный линк в этом режиме ожидаемо возвращает `FAIL_BINDINGS`.

Для `rbm_h03_target_engine` остаются конкретный источник `context_for_task2`, политика FD00.5, проверенный резерв FA7B либо его признак недоступности и измеренные `bit_time_us`, `max_age_ticks`, `max_poll_gap_us`. Временная граница относится ко времени приёма CAN. Задержка между измерением в Bosch и отправкой кадра требует отдельного подтверждения. Оборудование не использовалось, прошиваемый образ не создавался.
