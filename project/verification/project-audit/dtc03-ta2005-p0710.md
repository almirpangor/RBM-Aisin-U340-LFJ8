# DTC-03 — квалификация Chery P0710 по состоянию цепи ATF

База проверки — `e24ae2ca05677df9e3a2326e43b9cbc6c67e23db`. Область изменения — переносимый монитор, проверка и этот отчёт.

## Поведение монитора

`chery_atf_circuit_step` получает одну классификацию за вызов диагностического владельца. Годная проба обнуляет накопление до появления неисправности. На 127-й пробе вне диапазона выставляется current индекса `0x04`, счётчик принимает значение 125. После 125 годных проб счётчик равен нулю, и следующая годная проба снимает current. Проба вне диапазона при уже активном коде восстанавливает счётчик до 125. Пропущенная проба оставляет счётчик, current и историю в прежнем состоянии.

История и слоты проходят через существующий `chery_dtc_raise_c0`. При разрешённой записи первый подъём использует свободный слот. При заполненных слотах сохраняется бит истории. Запрет записи при первом подъёме оставляет только current. Снятие запрета на уже активном коде само по себе историю не добавляет. Для сохранённой записи сервис `17 FF 00` выдаёт `57 01 07 10 74`, после восстановления — `57 01 07 10 54`.

После принятого `14 FF 00` общий диагностический владелец должен вызвать `chery_atf_circuit_reset` при обработке события сброса, до следующей пробы. Тот же вызов инициализирует счётчик при запуске. Проверка очистки использует RAM-режим сервиса.

## Доказательства

- **Модель S03.** Выполнены исходные инструкции C167 с входа `06EE20`, в том числе запись через `05C7F2`. Сравнивались `E061`, все байты current/history и пять видимых слотов. Совпали 2 560 переходов с начальными значениями счётчика 0…255, 4 096 комбинаций 10-битной пробы с опорой на четырёх границах, 8 проверок истории и 256 шагов непрерывной последовательности. Декодер выполняет две дополнительные инструкции ADC3 по образцу R3. S03 SHA-256 `6f0433dc44871ed00e73f2766b0b37dce39b19c600f2b8248fb626554b0cfa79`. Декодер R3 SHA-256 `7de99b47c8c077cc70f38239d4cdd5162b6faee0760f1b6bb93e46c58f7a6ae3`.
- **Сборки.** Один и тот же C-тест прошёл на ПК (Zig) и на GNU M32R в симуляторе. Он проверяет квалификацию, `17 FF 00` до и после восстановления, запрет записи, принятый `14 FF 00` и постановку после повторного сбоя без дублирования слота.
- **Оборудование и BIN.** Проверка на LFJ8, измерения опорного входа и проверка сканером остаются открытыми. Объект монитора собран для отдельной оснастки. В состав H03 модуль ещё не включён.

```powershell
python -B diagnostics/verify_atf_circuit.py --cc $zig --m32r-gcc $m32rGcc --r1 $r1 --ta-repo $taRepo
```

## Регрессия состава H03 из main

- Общая проверка ПК прошла 37 шагов, включая 102 теста Python. SHA-256 отчёта `PC-CHECKS.json` — `856e34491ab3cf819b9a6069f326e076429dd3f6e44bcdd3c3553608609943ed`.
- Сборка объектов контроллера и моста, проверка компоновки H03, 18 групп проверок и повтор CAN-трассы Bosch прошли. SHA-256 отчёта `h03-link.json` — `46d53c2e1bbb10f4a309d87728f90ed72d508c37efa09f7412cd22cad41cb366`.
- Пять сценариев `--suite components` прошли в отдельном временном worktree с ASCII-путём. Там же прошли 17 сценариев `--suite native` с исходным манифестом сборки контроллера. GNU M32R 4.8 не принимал исходный путь с кириллицей.

## Подключение к H03

Числовые пороги S03 для опоры 495…529 и ADC8 10…252 используются только в проверке донора. Для подключения на LFJ8 нужно подтвердить диапазон датчика и признак годности опоры, назначить период вызова и проверить общий сброс мониторов. Отдельный нативный монитор Mazda и соответствия другим DTC остаются частью дальнейшей работы по DTC-03.
