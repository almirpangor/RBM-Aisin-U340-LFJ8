# VSS-02 — допуск парного профиля часов H03

База проверки `f64eff7c24744cef0fe608415039c6d10c677ff1`. Включена предыдущая порция VSS-02 `007f28ea1e3fd2eee46c17e3e22092711e228937`. SHA-256 исходного H03 LFJ8-18-9E1C `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

## Формат ввода для сборки

- Профиль датчиков содержит `base_sha256`, `clock_reference_sha256`, `evidence_id`, `limits` и `observed_maxima`. SHA файла замеров вычисляется по его исходным байтам. В отчёт и сгенерированный C попадают SHA обоих файлов.
- Для каждого интервала в файле замеров нужен `elapsed_us` с независимого эталона и по два отсчёта в `tml0`, `tml1` и `tml0_after`. Элементы с индексами 0 и 1 относятся к началу и концу интервала. На каждом конце регистры читаются в порядке TML0, TML1, TML0. `tml0` содержит первое чтение TML0, `tml0_after` — второе. Формат соответствует последовательности чтения в H03.
- Ширина каждого окна вычисляется по модулю 2³² и должна укладываться в зафиксированный `observed_maxima.read_span_ticks`. Разность приростов TML1 и TML0 должна быть от минус ширины начального окна до ширины конечного окна включительно. Оба таймера используют Clock Bus 1. Проверка каждого таймера против независимого эталона по-прежнему обязательна. Прежний формат без `tml0_after` можно использовать для отдельного аудита частоты.

Штатный компоновщик `check_h03_image_layout.py` вызывает этот допуск до сборки сгенерированного C. При успехе он связывает `rbm_h03_sensor_config` и `rbm_h03_target_clock_ready` с существующей привязкой H03. Callback допуска проверяет регистры в startup. Настройки датчиков используются в нативном foreground. Набор полей и значения C на согласованных входах совпадают с предыдущей порцией.

## Проверено

- 9 тестов генератора и 11 тестов измерений VSS. Покрыты переход TML0 через ноль, оба асимметричных предела, расхождение в пределах отдельных ppm-допусков, превышение заявленного окна, остановка счётчика, подмена файла и отсутствие обязательных отсчётов. Аудит исходного H03 без калибровки вернул `PASS_STOCK_ONLY`.
- На ПК прошёл 41 этап, включая 183 теста Python. Сквозная модель с Bosch завершилась со статусом `PASS_OFFLINE_ONLY`.
- Собраны контроллер и мост M32R. Прошли 22 нативные и 8 компонентных групп. Отдельно в симуляторе прошли штатные и проектные S51/S83, отзыв допуска часов, повторное открытие эпохи, startup и foreground со штатным callback.
- Компоновщик с синтетической парой разрешил оба символа датчиков. Профиль с SHA другого файла и корректно привязанный профиль с расхождением таймеров были отклонены до появления ELF. С предыдущим генератором оба отвергнутых набора давали C. В согласованном наборе разность приростов равна ширине конечного окна и проходит допуск. В модели защищённого размещения `padding-candidate` 101 492 байта Flash и 4 учтённых байта статической RAM, как в предыдущей порции VSS-02. Итог модели `FAIL_BINDINGS`. Не определены `rbm_h03_target_engine`, `rbm_h03_target_initialize`, `rbm_h03_target_ram_owned`, `rbm_h03_target_service_phase`, `rbm_h03_target_startup_gear`, `rbm_h03_target_startup_gp`, `rbm_h03_target_take_toyota` и `rbm_h03_target_takeover_ops`.

Для повтора аудита и генерации через штатный интерфейс:

```powershell
python -B -m unittest discover -s tests -p test_h03_sensor_config.py
python -B targets/lfj8/check_h03_sensor_config.py --base $h03 --clock-reference $clockReference --calibration-profile $sensorProfile --out $sensorReport --emit-config
python -B targets/lfj8/check_h03_application_binding.py --gcc $gcc --controller $controller --out $bindingReport
```

## Остаток

На физическом блоке нужны парные замеры с обоими чтениями TML0, допустимое отклонение частоты и пределы периода и возраста S51/S83, ATF и окна чтения. Для VSS остаются кинематика, независимое подтверждение остановки и сверка скорости по CAN с эталоном. Эта порция проверяет входы генератора. Наблюдение хода TML1 в работающем приложении остаётся отдельным шагом. Аппаратный прогон и выпуск BIN в эту проверку не входили.
