# Сектор Flash `0x020000–0x02FFFF` в H03

Проверен `LFJ8-T-D.bin`, внутренний ID `LFJ8-18-9E1C`, 524 288 байт, SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`. Все 65 536 байт сектора заполнены `FF`. Штатное обновление может стереть сектор отдельно, вместе с предыдущим сектором или вместе с приложением. Сохранность добавленного кода определяется диапазоном конкретного обновления и побайтовой проверкой содержимого после него. [Идентификация H03](lfj8-9e1c-base.md) · [Renesas 32176, § 6.5](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

## Встроенные проверки H03

| Проверка | Участок | Результат |
| --- | --- | --- |
| Переход из загрузчика в приложение | `0x003DC8 → 0x004210 → 0x008084 → 0x008100` | Исходник и пробная замена байта внутри сектора приводят в `0x008100`. Результат порчи любого из маркеров `5AA5` по `0x008000` или `A55A` по `0x07FFFE` — вход по `0x0047D8`. |
| Допустимый диапазон стирания | `0x005200–0x005254` | Допускаются `[0x008000, 0x080000)`, `[0x010000, 0x020000)`, `[0x020000, 0x030000)` и `[0x010000, 0x030000)`. Сдвиг любой границы отдельного сектора на один байт отклоняется. |
| Сверка записанных байтов | `0x004554–0x004588` | В симуляторе совпадение трёх последних байтов сектора даёт `0`. Несовпадение последнего даёт `0xFFFF`. Завершение передачи по `0x0045D8–0x004610` проверяет совпадение принятых и заявленных размеров. |
| Диагностическая сумма | `0x00A0CC`, публикация `0x00A408–0x00A428` | В режиме 4 из нулевого накопителя обрабатываются 512 участков по 1 024 байта. Результат по модулю `2^16` для H03 — `0xC97D`. Изменение байта в симуляторе даёт `0xC8D8`. Сумма публикуется в диагностическую телеметрию. Маркерная проверка загрузчика от неё не зависит. |

Таблица по `0x000958` хранит начало сектора `0x020000` и адрес последнего выровненного полуслова `0x02FFFE`. Штатный парсер приводит конец диапазона к исключительной границе. Драйвер стирания в RAM по `0x8051E8` принимает размер `0x10000` и обращается к последнему полуслову сектора. Путь записи отдельно проверяет границы начиная с `0x008000`, передаёт данные драйверу в RAM `0x805000` через `0x00452C` и сверяет результат с принятым буфером. После запуска приложения `0x040620` проверяет сохранённую RAM. Признаки допустимости внутренней записи и запуска относятся к H03. Приём полного BIN внешним программатором и поведение физического `LFJ8-18-9E1C` требуют отдельной проверки. [Renesas 32176, § 6.5](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

## Ссылки и динамическая карта

Во всём H03 проверены выравненные слова, загрузки `LD24` и шаблоны прямых переходов. Найдены четыре загрузки `LD24` для условий обновления. Среди четырёх выравненных слов внутри диапазона два относятся к геометрии, одно объединяет два 16-битных калибровочных значения по `0x01A194`, одно содержит ключ диагностической записи по `0x0318A0`. В таблице диагностики адрес этой записи указывает на RAM `0x80403C`. Все 27 совпадений с шаблоном прямого перехода со знаковым 16-битным смещением лежат в данных калибровок. Прямых переходов из идентифицированного штатного кода в сектор этот поиск не обнаружил.

Сервисная ветвь `0x002DF8–0x002E00` выбирает страницу по рабочему адресу. `0x003550–0x0035B4` использует полученное значение при записи регистров `FCNT1` и `FESBANK1`. Режим Virtual Flash может отображать 4 КиБ RAM поверх выбранной страницы Flash. В модели регистров исходные команды H03 сформировали `0x8020` и `0x802F`, соответствующие первой и последней 4‑КиБ страницам сектора. Это подтверждает возможность наложения в сервисной ветке. Фактическое использование этих страниц в рабочем цикле и поведение устройства при подмене требуют отдельной проверки. [Renesas 32176, §§ 6.4.5 и 6.6.1](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

## Воспроизведение проверки

Запуски используют штатные инструкции H03 с исходными адресами. Проверка диапазона завершается до вызова драйвера стирания. Изменения пробных байтов и регистров действуют в памяти симулятора. Исходный файл при повторной сверке имел тот же SHA-256. [Верификатор](../targets/lfj8/check_h03_flash_policy.py)

```powershell
python -B targets/lfj8/check_h03_flash_policy.py --base $base --gcc $m32r --out "$out/h03-flash-policy.json"
```

## Проверка адресов приложения

Дополнительный режим принимает итоговый ELF32 M32R с разрешёнными релокациями и проверяет адреса его размещаемых секций. Для каждой из 128 страниц внутренней Flash пробник исполняет селектор `0x003550` напрямую и штатную ветвь его вызова из монитора. Для пересечений он сохраняет диапазоны секций и номера страниц в JSON и завершает команду с кодом 2.

```powershell
python -B targets/lfj8/check_h03_flash_policy.py --base $base --gcc $m32r --placement-elf $appElf --out "$out/h03-placement.json"
```

Пробник входит в ветвь активации `0x003364 → 0x003550` после диспетчеризации, с уже подготовленным состоянием монитора. При штатном адресе назначения для Virtual Flash ветвь включает отображение и передаёт селектору каждый проверенный номер страницы. В двух граничных сценариях с соседними адресами ранее включённое отображение выключается. Сравнение основано на записанных значениях FCNT1/FESBANK1. Допуск внешнего запроса до этой ветви и аппаратное наложение Flash остаются открытыми. Эти результаты применяются к обеим кандидатным областям, включая хвост после `0x07C118`. [Достижимость перехватов выхода](lfj8-slt-calibration.md#достижимость-при-сервисных-операциях)

В пробной компоновке M32R проверка отклонила две секции с кодом H03-05: функцию отзыва в `[0x020000, 0x020028)` и группу перехватов в `[0x07C118, 0x07C1A8)`. Селектор сформировал значения `0x8020` и `0x807C` для этих страниц. Пустой список пересечений означает только отсутствие попадания секций во внутреннюю Flash в рамках этой проверки.
