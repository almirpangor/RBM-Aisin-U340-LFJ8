# Штатные пути ATF в H03

Пробник исполняет функцию H03 `0x03B110` в симуляторе M32R с образа `LFJ8-T-D.bin`. Значения входов подставляются в память симулятора. При AN1 = 315 и сохранённой температуре 20 °C получены следующие результаты.

| Путь | Точки H03 | Значение в `0x805028` |
| --- | --- | --- |
| Прямая запись | `0x03B138 → 0x03B1A4` | Около 60 °C |
| Запись с фильтрацией | `0x03B138 → 0x03B1B0 → 0x03B218` | 25 °C |
| Пропуск записи | `0x03B138 → 0x03B1B0` | Прежние 20 °C |
| Штатный признак отказа | `0x03B138 → 0x03B178` | Резервные −50 °C |
| Напряжение из ROM | `0x03B130 → 0x03B1A4` | 150 °C |
| Подставное напряжение из ROM совпало с AN1 | `0x03B130 → 0x03B1A4` | Те же биты, что у прямой записи |

Выбор напряжения из ROM происходит при значении 400 в `0x0166A4`. Этот режим пропускает чтение AN1. Даже при совпадении напряжения и температуры с реальным измерением у такой записи нет метки преобразования АЦП.

Кандидат обвязки в [h03_atf_hooks.S](../targets/lfj8/h03_atf_hooks.S) повторяет исходные инструкции в семи точках. После записи AN1 в `0x040178` вызывается регистрация отсчёта. При чтении `0x03B138` метка сохраняется в 8-байтовой записи текущего вызова. На входе `0x03B110` запись помечается пустой, а на выходе `0x03B21C` снимается со стека. Записи `0x03B1A4/0x03B218` передаются адаптеру вместе с захваченной меткой либо с `NULL`. Запись `0x03B178` инвалидирует результат, а проход без записи не публикует температуру. Исходные операции чтения и записи и соответствующие вызовы адаптера выполняются при снятом разрешении маскируемых прерываний.

В парных прогонах совпали адреса продолжения, напряжение и температура в RAM, регистры, PSW и наблюдаемое состояние аккумулятора. Изменение SP внутри функции соответствует дополнительным 8 байтам, при возврате SP совпадает. В седьмом прогоне между чтением AN1 и конверсией выполнена вторая запись с тем же кодом и новой меткой. Штатная температура совпала, адаптер отклонил её по устаревшей метке. В обоих сценариях напряжения из ROM перед входом в функцию в стек подложена старая метка, чтобы проверить очистку записи.

```powershell
python -B targets/lfj8/check_h03_atf_native.py --base $h03 --gcc $m32rGcc
```

Перехваты вызывают [целевые функции ATF](../targets/lfj8/lfj8_h03_atf_target.c) с существующим `lfj8_h03_mmio`. Владелец приложения связывает символ `rbm_h03_atf_state` с единственным объектом `atf` в хранилище управления и инициализирует его до включения перехватов. Он также предоставляет пригодные для вызова при маскированных IRQ часы `rbm_h03_atf_now_us`. Для чтения из основного цикла `lfj8_h03_atf_target_snapshot` берёт время и снимок под одной блокировкой. Недоступные часы сбрасывают достоверность и ожидающий отсчёт. Сами метки остаются для отсева повторов. При смене эпохи часов приложение переинициализирует состояние при остановленных перехватах.

## Источник времени TML0

В штатном H03 код `0x009E78–0x009E84` устанавливает `PRS1 = 9`. В `0x009F18–0x009F24` прошивка восстанавливает это значение при расхождении. Код `0x00A86C–0x00A870` выбирает Clock Bus 1 через `TML0CR = 0x01`, а `0x00A92C–0x00A938` восстанавливает эту настройку. Штатное чтение `0x00A82C–0x00A830` забирает всё 32-битное слово `TML0CT` по адресу `0x8003E0`. Пробник сверяет все пять фрагментов с исходным H03.

По документации Renesas Clock Bus 1 питается от PRS1. Частота TML0 при этой настройке составляет `BCLK / (2 × (9 + 1))`, то есть 1 МГц при BCLK 20 МГц. TML0 начинает счёт при выходе из сброса с неопределённым начальным значением. Само значение регистра при первом чтении не доказывает непрерывность прежней эпохи. [Renesas, §§ 10.2.2–10.2.3](https://www.renesas.com/en/document/mah/32176-group-hardware-manual#page=257) · [Renesas, §§ 10.6.4–10.6.5](https://www.renesas.com/en/document/mah/32176-group-hardware-manual#page=361)

[Поставщик TML0](../targets/lfj8/lfj8_h03_atf_tml0.c) использует штатный MMIO. Он отдаёт счётчик в микросекундах при подтверждении от владельца часов, `PRS1 = 9` и выбранной Clock Bus 1. Флаг `rbm_h03_tml0_1mhz_qualified` остаётся нулевым до проверки физической частоты и непрерывности. Перед известным перенастраиванием часов или сбросом счётчика владелец снимает флаг. После смены эпохи нужно переинициализировать общее состояние ATF при вызовах, остановленных на это время.

В симуляторе связаны целевой поставщик TML0, штатный MMIO и обвязка ATF. Проверены отсутствие подтверждения при захвате AN1, изменение PRS1 при публикации, смена источника при чтении снимка и переход `0xFFFFFFFE → 1`. После восстановления настройки старый отсчёт остаётся недоступен. Симулятор подставляет содержимое MMIO и тем самым проверяет программное поведение. Для целевой компоновки остаются размещение, источник флага подтверждения и замер задержек с вложенными IRQ. Физическая частота и тарировка U340E требуют стенда. [Карта входов H03](lfj8-h03-input-paths.md#чтение-atf-для-0x300-и-toyota)

## Передача измерения в Toyota и Chery

Перед подготовкой входов цикла владелец передаёт успешный снимок в [адаптер ATF](../targets/lfj8/lfj8_h03_atf_feed.c). Адаптер повторно проверяет возраст отсчёта на общей шкале микросекунд, записывает исходное значение Q8 в Toyota `GP−7184` и учитывает время отсчёта при выборе самого старого операнда `command_at`. Целые градусы из того же измерения поступают в поля кадра Chery `0x300`.

Если снимок недоступен либо достиг предельного возраста, температура в кадре кодируется как `0xFF`. Адаптер возвращает отказ для цикла Toyota и оставляет его GP и метку без записи. Свежая температура доступна в Chery и при отсутствии остальных квалифицированных входов Toyota.

Компонентный тест `h03_atf_feed` в `check_h03_link.py` проверяет запись Q8, байт температуры в кадре, предельный возраст, метку из будущего и переход счётчика через ноль. Все 18 компонентных тестов и связанный прогон прошли в M32R. В двух окнах проверочной компоновки осталось 1304 и 1388 байт, число релокаций равно нулю. Вызов из штатного цикла и целевое владение окнами остаются частью интеграции H03.

## Глубина записи в стек

Пробник заполняет 1024 байта ниже SP и измеряет глубину изменённой памяти отдельно для записи AN1, расчёта и публикации температуры и чтения снимка из основного цикла. Между стадиями проверяет возврат SP и восстанавливает шаблон. Каждый вариант пройден с двумя взаимно противоположными шаблонами, нижние 16 байт проверяются как защита. Ни один шаблон не изменил результат сценария.

| Стадия | Штатный путь, максимум | С перехватами, максимум |
| --- | ---: | ---: |
| Запись AN1 с возвратом из пробника | 4 байта | 92 байта |
| Функция температуры H03 | 56 байт | 120 байт |
| Чтение снимка в основном цикле | 72 байта | 72 байта |

Пик расчёта с перехватами наблюдался при вставленной второй записи AN1. При пропуске публикации записано 68 байт с перехватом и 16 байт в штатной функции. В сводке для чтения снимка обе колонки исполняют один целевой потребитель и его тестовый вызов. Числа характеризуют наблюдаемые записи, включая кадры пробника и целевого поставщика TML0. Выделенное без записи место на стеке и сосуществование кадров вложенных IRQ сюда не входят.
