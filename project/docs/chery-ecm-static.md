# Штатный приём скорости и температуры в Chery Tiggo T11

Статический разбор S02 `CHERY_REFERENCE_DO_NOT_FLASH.bin` по разделам 3 и 7 ТЗ, 20.11.2026. Размер образа 851 968 байт, повторно вычисленный SHA-256 `99dc271a861ab6d9e6749e8beb4637ab5c6c7e111f3ff0d9df4e147b2a0a6e1c`. Адреса инструкций приведены как смещения в этом образе. Для переменных указаны логические адреса ST10. Индекс байта кадра начинается с нуля. [Бинарный источник S02][s02]

## Поле скорости, используемое в доноре

**Стандартный кадр `0x1AE`, DLC 8, байты 6 и 7 в порядке старший → младший. Шкала поля 0,01 км/ч на единицу в штатном диапазоне. `FFFF` — признак недостоверности.** Обоснование опирается на обработчик приёма, фактическую константу выбора источника в S02 и связь с OBD Mode 01 PID `0D`.

| Участок S02 | Что подтверждено |
| --- | --- |
| `0A2BD8–0A2BF4`, `0A21F4`, `0A22E6–0A22F8` | Опрос индекса 0 с очисткой признака нового кадра. При стандартном `0x1AE` декодер собирает `raw = 256 × RAM[853C] + RAM[853D]` и сохраняет его в `8C5E`. |
| `0A236A–0A238C` | При `raw=FFFF` выставляет `FD10.5` и пишет ноль в `8C60`. В остальных случаях сбрасывает этот бит и пишет `8C60 = ((raw // 25) << 5) & 0xFFFF`, где `//` — деление с усечением. Ветка недоступного кадра или активного `B254.0` через `0A23A2` также пишет резервное значение `8C60=0`. |
| `026530–02655C`, `026650–0266BA` | Команда `C2 FC 43 04` загружает байт калибровки по логическому `0443`. При `DPP0=0x2E` это `0B8443`. Фактический байт образа равен `20`, установлен только бит 5. После переноса этого бита в бит 13 регистра `R12` задача выбирает `896A = 8C60` в `0266B6–0266BA`. |
| `02679C–0267D8` | Селектор ограничивает шаг между новым `896A` и прошлым `8968` калибровкой `2920`, затем сохраняет результат в `8968`. В S02 по `0BA920` записано `0080`. Это до 1 км/ч за один проход действующей ветви. |
| `02FA52–02FA76`, таблицы `0BB66E`, `0BB6AE` | Задача публикует `min(8968 >> 7, 255)` в `81EA` и выставляет `81EB=1`. Слот 4 списка PID содержит `0D` по `0BB6B2`, а его указатель `0BB67E: EA 01 3C 00` адресует физический `0F01EA`, соответствующий логическому `81EA` при `DPP2=0x3C`. Сервис `0317D8–03182A` читает дескриптор `82` по `0BB6F9`, проверяет соседний байт состояния и отдаёт один байт значения. |

В установившемся режиме при `0 ≤ raw ≤ 51199` перед насыщением PID вычисляет `floor(raw / 100)` км/ч. Поэтому, например, `17 70` (6000) даёт 60 км/ч. Внутреннее слово `8C60` использует 128 единиц на км/ч и квантуется с шагом 0,25 км/ч. Начиная с `raw=51200`, сдвиг переполняет 16-разрядное слово. Прямое кодирование по этой шкале применимо в нормальном диапазоне. Для кандидата LFJ8 дополнительно требуются подтверждённая кинематика VSS и правила полной передачи `0x1AE`, включая соседние поля, счётчик и контрольное поле. [Контракт Chery][contract] · [Разбор контроля приёма][supervision]

### Другие источники в коде ECM

- `0x310` принимается через индекс 2 и буфер `854A..8551`. Ветвь `0A2CA4–0A2CBA` вызывает `0A24D6`, где формируются четыре big-endian слова. Два первых слова ведут в `8C68/8C6A`, среднее доступных значений масштабируется на `9/5` с целочисленным усечением и проверкой диапазона. После фильтра `023416` результат попадает в `8C56` через `0A268E`. Селектор копирует его в `896A` при бите 3 калибровки `0443`. В проверенном S02 этот бит сброшен. Физический смысл отдельных пар и масштабы кадров для вариантов с этим источником требуют отдельного подтверждения.
- `0x430[5:6]` ведёт в `8C5C` через проверку ID у `0A2D8E` и декодер у `0A2760`. У селектора это ветвь по биту 0 либо по биту 2 совместно с дополнительным признаком (узлы `026660–026678`). При `0443=0x20` она тоже не выбирается. В коде присутствуют отдельная ветвь по биту 1 и расчётный резерв.

## Что принимает ECM из `0x300`

| Участок S02 | Что подтверждено |
| --- | --- |
| `0A2800–0A2810 → 093B78` | CAN1, программный индекс 1, аппаратный объект 2, стандартный ID `0x300`, RX, начальный DLC 8. IF1 получает арбитражное слово `EF1A=8C00`, управление `EF1C=0088`, команду `EF12=00F0` и номер объекта `EF10=0002`. |
| `0A2C48–0A2C5E → 0205FE` | Переданы индекс 1 и флаг очистки NewDat. Драйвер проверяет `FD00.8`, затем `EF90.1`, переносит объект 2 в IF1 командой `EF12=0077`, сохраняет DLC в `8548` и четыре слова данных в `8540..8547`. Верхним уровнем проверяется возвращённый стандартный ID `0x300`. DLC здесь сохраняется отдельно от payload. |
| `0A2472–0A24B8` | Обработчик читает байт 3 по `8543` и пишет исходный код в `817E`. Для `d[3]=FF` сохраняет местный код ОЖ `8356` в `817D`. Иначе для `0 ≤ d[3] < 144` пишет `floor((4 × d[3] + 32) / 3)`, для `144 ≤ d[3] < 255` пишет 202. Остальные семь байтов и сохранённый DLC этот обработчик не читает. |
| `028376–028386` | `817D` используется как вход таблицы по `0A8151` с узлами `10, 50, 100, 150, 200, 250`. Результат записывается в `8B12`. Для недоступного кадра или активного `B254.0` применена та же подстановка ОЖ. |

У отправителя S03 байт `0x300[3]` связан с `FA7B`, фильтрованным кодом температуры масла TA2005. Пакетер образует `max(FA7B − 10, 0)` при действительном значении и `FF` при признаке недостоверности. Пара `°C+50` для `FA7B` и `°C+40` для передаваемого кода согласуется с преобразованием в ECM и подстановкой по шкале ОЖ. Это программная привязка к донорской температуре масла. Аналоговую тарировку датчика U340E следует определять отдельно. [Роль FA7B в S03][atf] · [Программный контракт объектов CAN][contract]

При включённом профиле ECM проверяет `0x300` по счётчику `8C76` с перезагрузкой 5, то есть на каждом шестом вызове соответствующей задачи. Счётчик пропусков `8C70` обнуляется при успешном приёме. Порог `05AF` читается из `0B85AF=05`, поэтому признак пропуска `FD0E.15` появляется на шестом подряд неуспешном опросе от нуля. `B254.0` может выбрать резерв даже после успешного опроса. Соотношение между вызовами и миллисекундами здесь не измерялось. [Базовый разбор драйвера и BusOff][driver]

## Проверка исполнения на ПК

На неизменённых инструкциях S02 в модели ST10 выполнены три группы сверок.

- `0A2472` — все 256 значений байта `0x300[3]` при пяти значениях местной ОЖ. Все 1 280 случаев совпали с формулой и правилами подстановки.
- `0A236A..0A2390` — все 65 536 значений `8C5E`. Получены ожидаемые 16-разрядные `8C60` и бит недостоверности.
- `02652C..02679C` и `02FA52` — 12 контрольных значений с неизменённой калибровкой `0B8443=20`, конкурирующим значением `8C56` и проверкой итогового байта PID в установившемся состоянии. Все результаты совпали, включая 6000 → 60 км/ч, насыщение PID на 255, переполнение при 51200 и нулевой резерв для `FFFF`. Четыре дополнительные пробы по `02652C..0267DC` подтвердили шаг 128 внутренних единиц в обе стороны и точный выход на цель в пределах шага.

Для проверки использовалась модель `C167` с `DPP=(2E,2F,3C,03)`. Обмен IF1, аппаратный CAN, работа сканера, двигатель и коробка в этом прогоне не моделировались целиком. Для нового блока остаются реализация полного кадра, контроль времени передачи и стендовая проверка с реальными сигналами VSS и приборной панелью. [Код модели инструкций][vm]
