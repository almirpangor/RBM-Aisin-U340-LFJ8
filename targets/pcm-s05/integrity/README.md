# Проверка целостности Mazda PCM S05

Исходный `RB-J-P01.bin` содержит ПО `LFJ8EF030LFXF0A0` для Mazda PCM `LFJ8-18-881F`. Размер образа 1 048 576 байт. SHA-256 `3d55f5be4cfda23a065371d71e84cc233aa111c8b237d063b1e8fc205337850d`.

## Контроль программы в PCM

Адреса приведены как смещения полного BIN. Для диапазонов `[начало, конец)` верхняя граница исключена.

| Участок | Установленное поведение |
| --- | --- |
| `0x004470`, `0x0052F4` | Ветка по `0x004470` вызывает проверку двух 16-битных слов. Функция возвращает `1`, когда `0x008002 = 0x5AA5` и `0x0FFFFE = 0xA55A`. При `0` вызов идёт через `0x005AF8`, при `1` через переходник `0x0FFF20` в `0x0294C2`. |
| `0x029050`, `0x0B2EBC` | Инициализация выставляет указатель программы `0x029000` в RAM `0xFFFF5ECC` и нулевую сумму в `0xFFFF5EC8`. |
| `0x0B2DCC`, `0x0B2FE6` | За один вызов читаются 32 блока по 32 байта. В каждом восемь 32-битных слов big-endian. Сумма накапливается по модулю `2^32`. Указатель увеличивается на `0x400` через функцию беззнакового сложения `0x0FE166`. |
| `0x0B3014–0x0B3040` | При достижении `0x100000` указатель возвращается к `0x029000`, итог записывается в `0xFFFF0380`, накопитель очищается и вызывается сравнение. |
| `0x0B2E0C–0x0B2E1A` | Результат из `0xFFFF0380` сравнивается с константой `0x5AA55AA5` из `0x0B3060`. При несовпадении код обновляет счётчики сбоев. |

При превышении порога из `0x020BA0` монитор выставляет бит 0 в `0xFFFF5EC5`. Код по `0x0A82A4` передаёт этот признак в `0xFFFF6120`. Через общие поля таблиц по `0x023AB0` и `0x027B4C` он связан с DTC `P0601`, ошибкой суммы памяти PCM. [Mazda6 Workshop Manual, DTC P0601](https://mazdamanuals.com/Mazda/md6%200605%201107/D923-1A-22C_Ver25/esicont/srvc/html/id0102a1809100.html).

Пределы контроля программы — `[0x029000, 0x100000)`. Охвачены `0xD7000` байт, 860 итераций по `0x400` байт, включая заполнение `FF`. Слово big-endian по `0x03FFC0` участвует в сумме. Формула для проверки этого слова — `(0x5AA55AA5 − sum32_остальных_слов) mod 2^32`.

| Локальный образ | Начало диапазона | Сумма без слова `0x03FFC0` | Слово `0x03FFC0` | Итог |
| --- | ---: | ---: | ---: | ---: |
| `RB-J-P01.bin`, LFJ8EF030 | `0x029000` | `0x103C2DEE` | `0x4A692CB7` | `0x5AA55AA5` |
| `LFJ8EE020.MPC` | `0x029000` | `0x777CA8BE` | `0xE328B1E7` | `0x5AA55AA5` |
| `LFR5EC000LFX6060-20241104-155822.bin` | `0x031000` | `0xE32192F1` | `0x7783C7B4` | `0x5AA55AA5` |

`LFJ8EE020.MPC` имеет SHA-256 `ab0da2aa145bf54ebe87c064b70ef7601ed77411bcb7efca49cfd9f1b051cadf`, его цикл сложения по `0x0B2DB4` совпадает с циклом S05. У LFR5EC000 SHA-256 `949d2ace2f694d6bd0d383d5e0560f440bcb3183c6bb259f8bbfa36a5316263f`, тот же цикл начинается по `0x0B78B4`, начальный указатель берётся из `0x0B7B88`. Последовательность по `0x03FFC4–0x03FFFF` совпадает у трёх образов. Это подтверждает назначение слова `0x03FFC0` по формату и результату вычисления на разных сборках. В проверяющем коде PCM слово читается внутри общего диапазона. Правила коррекции в конкретном профиле программатора остаются открытыми.

## Диагностический CVN

Код `0x09D6DA–0x09D6FC` задаёт диапазон `[0x00803C, 0x0FFFFC)` для другого вычисления. Цикл `0x093E74` идёт по 16-битным словам big-endian. Для последовательности индексов `i = 1, …, period` при каждом слове увеличиваются два 16-битных накопителя. В первом прибавляется `word // i`, во втором — `word & (i − 1)`. `period` читается по `0x01E9A0`, в S05 равен `0xFF`. После последнего слова пара записывается в RAM `0xFFFF5784` как `(A << 16) | B`. Для исходного файла CVN равен `0xD32EAA32`.

Запись по `0x028368` связывает `PID 0x06`, длину 4 и адрес `0xFFFF5784`. Перед копированием результата код по `0x07C72E–0x07C78A` проверяет готовность по флагу `0xFFFF004D`. Это значение выдаётся по OBD Service 09 PID 06. Подтверждённый потребитель — ответ диагностике. [CARB On-Board Diagnostic Submission Guide](https://ww2.arb.ca.gov/sites/default/files/2020-06/psip_obd_submission_guide.pdf).

В `0x0B2EFC` найден отдельный код, вычитающий из входного параметра значения ряда слов ниже `0x029000`. Его вызывающий путь и ожидаемый результат пока неизвестны. Применимость к приёмке программатором не установлена.

## Воспроизведение

```powershell
python targets/pcm-s05/integrity/verify.py 'C:/путь/RB-J-P01.bin' --expect-original
python targets/pcm-s05/integrity/verify.py 'C:/путь/кандидат.bin'
```

Скрипт читает полный бинарный файл, выводит JSON и возвращает `0` при совпадении размера, идентификатора ПО, участков штатного проверяющего кода, обоих маркеров и суммы программы. С `--expect-original` также требуется SHA-256 исходного файла. Отчёт содержит CVN и текущее и расчётное значения слова `0x03FFC0`. Скрипт работает на стандартной библиотеке Python. Проверка исходника и отрицательные сценарии с повреждённым маркером, суммой, проверяющим кодом и усечённым образом пройдены на локальных данных в памяти.

Функция `compensation_bytes(image)` возвращает четыре расчётных байта поля `0x03FFC0`. Вызов оставляет входной образ и файл без изменений.

Этот результат подтверждает описанные статические проверки. Для аппаратной приёмки отдельно нужны фактический идентификатор PCM, корректный профиль записи, подтверждённый запуск и испытания функций на стенде.
