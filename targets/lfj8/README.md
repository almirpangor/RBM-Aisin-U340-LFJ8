# Переносимый тракт VSS и CAN Chery

В каталоге находятся расчёт скорости, упаковка кадров Chery, логические команды двух реле и проверка для ПК. Общая часть используется транспортом [S05 SuperH](../pcm-s05/native/s05_chery.c). Отдельный модуль M32R воспроизводит наблюдаемые аппаратные точки Mazda LFJ8-18-9E1B. У каждого профиля свой аппаратный слой.

Для согласованной основы `LFJ8-T-D.bin` добавлены точки ADC и VSS версии 9E1C и проверка целостности исходного файла по SHA-256 перед сборкой. [Профиль H03 и команда сборки](../../docs/lfj8-9e1c-base.md)

## Сборка и проверка

Требуются Python 3.10 или новее и компиляторы для выбранных режимов. Параметры компиляторов независимы. Скрипт запускает EXE для ПК, проверяет формат и неопределённые символы каждого объектного файла, записывает размеры, SHA-256 и набор исходников в `build-manifest.json`.

```powershell
python targets/lfj8/build.py --output "$env:TEMP/rbm-lfj8-build" --zig $zig
python targets/lfj8/build.py --output "$env:TEMP/rbm-s05-sh" --sh-cc $sh --sh-cpu m2e
python targets/lfj8/build.py --output "$env:TEMP/rbm-9e1b-m32r" --m32r-cc $m32r
```

Переменные `$zig`, `$sh` и `$m32r` содержат пути к `zig.exe`, `sh-elf-gcc.exe` и `m32r-elf-gcc.exe`. Проверены Zig 0.16.0, GCC 8.4.0 и Binutils 2.34 для SuperH и GCC 4.8.0 и Binutils 2.23.1 для M32R. Все три режима можно указать одним вызовом и получить общий манифест. [Zig](https://ziglang.org/download/), [порт GCC для SuperH, зафиксированный коммит](https://github.com/johannes-fetz/joengine/tree/71f8314e7f22e8920fd30cbb99b7a901e77024b4/Compiler/WINDOWS), [пакет Sysprogs M32R](https://www.gnutoolchains.com/m32r-elf/).

| Уровень | Артефакт | Содержание |
| --- | --- | --- |
| ПК | `lfj8_host_check.exe` | Арифметика VSS, проверка обоих пакеров, реле, расписание, захват через переполнение таймера и сквозная постановка CAN-заявок в имитацию слота |
| S05 | `s05_chery_sh.o` | ELF32 BE REL, EM_SH=42, `e_flags=0xB` в сборке SH2E. Переносимое ядро и транспорт S05 с функцией отправки, которую передаёт интегратор |
| Донор 9E1B | `lfj8_m32r.o` | ELF32 BE REL, EM_M32R=88. Отдельный адаптер VSS и CAN0 для карты M32R, плюс то же ядро расчёта и пакеры |

Объектные файлы имеют точку входа 0 и требуют целевой компоновки. `-m2e -mb` задаёт семейство команд SuperH и big-endian. ABI встраивания, область размещения, профили памяти и контроль целостности образа проверяются отдельно по выбранной ревизии. Стендовый прогон и запись в ЭБУ не проводились. [S05 и штатная периферия Mazda PCM](../../docs/mazda-pcm-s05.md), [GCC SuperH Options](https://gcc.gnu.org/onlinedocs/gcc/SH-Options.html).

## Входы и выходы

- Скорость `lfj8_vss_raw_1ae` вычисляется из отсчётов таймера, числа импульсов в измерительном окне, частоты счётчика, окружности колеса в мкм и отношения оборотов колеса к оборотам дифференциала. Расчёт сотых км/ч использует точный множитель `99/1250000` после включения в единицы отношения `22/100` и коэффициента км/ч. Дробная сотая отбрасывается. Например, период 26 400 тиков на частоте 1 МГц, окружность 2 м и отношение 1:1 дают `6000`, то есть 60 км/ч. При потере датчика, неприемлемых входах или выходе из диапазона ECM выставляется `FFFF`. Подтверждённая остановка используется отдельно от потери импульсов.
- `0x1AE` содержит слово скорости в байтах 6–7 BE, контрольные полубайты и счётчик по донорскому формату. Источники статусных полей и запросов момента должен задавать связанный контроллер по подтверждённой карте. `0x300` несёт ATF в байте 3, где код равен `clamp(T, −40, +104) + 40` либо `FF` при недостоверности. Байты 0–2 задаёт вызывающий код, байты 4–7 нулевые для подтверждённого формата TA2005 C0. [Аудит TA2005](../../docs/chery-ta2005-static.md), [проверка обмена Chery](../../docs/chery-can-dtc.md).
- Периоды CAN задаются явно в мкс. При 32 МГц на доноре TA2005 статические формулы дают 10/30 мс, испытание использует эти числа как сценарий. После задержки накапливается максимум одно актуальное сообщение каждого ID. При двух ожидающих запросах используется чередование, а счётчик `0x1AE` меняется только после принятия заявки. Этот порядок выбран для предсказуемой работы адаптера с одним слотом и требует проверки на целевой сети.
- `lfj8_relay_mask` принимает декодированное положение селектора. В R устанавливаются биты обоих реле, в L — только дополнительного, в остальных оба сбрасываются. Выбор входов P/R/N/D/L, выходов, полярности, допустимого тока и подавления выбросов относится к целевому аппаратному профилю. [Таблица Mazda](../../docs/lfj8-wiring-sources.md).

## Данные двигателя и селектора

`ta2005_chery_inputs.c/.h` перенесены из R3 `7585de6945b4b6b3ef381c6062070a5f417cf588`. В исходном C добавлено явное преобразование при сборке двух байтов в `uint16_t`. Исходные Git blob `c91c12a3f4f961a04bbc45ca16f39e1743119e0c` и `cfbdae9512661ec4261d7e3b5613f6c8e44e4ed3`. Принимаются только выделенные драйвером стандартные кадры с данными, DLC 8. Два канала стареют независимо, код недостоверности снимает действительность, при потере CAN и переинициализации часов сбрасывается весь приёмник. Выходной код оборотов `FAD8 / 8` и температуры `F9E9 − 50` следует донорским формулам. В тесте Bosch передал 1200 об/мин и 87 °C, в приёмнике получены 9600 и 137. Разрешение переключений формируется в контроллере после собственных проверок. [Исходник R3](https://github.com/almirpangor/Chery-TA2005-U340E/blob/7585de6945b4b6b3ef381c6062070a5f417cf588/firmware/src/ta2005_chery_inputs.c) · [Карта Chery](../../docs/chery-can-dtc.md)

`lfj8_selector_adc` передаёт один отсчёт на событие готовности, включая случай, когда несколько последовательных преобразований дают одинаковые числа. Опрос пустого канала сам по себе не создаёт отсчёт. Потеря порядка событий или невалидное значение сбрасывают квалификацию декодера. Контроль пропадания событий со временем относится к планировщику целевого блока. Донорский вход 9E1B привязан к чтению `AD0DT2` после завершения преобразования и публикации по `0x040370 → 0x804BC6`. Эта привязка относится к выбранной версии 9E1C. [Селектор и проверенные окна](../../docs/lfj8-selector.md)

## Аппаратные точки донора M32R

`lfj8_9e1b_raw_vss_edge` использует 32-битную метку на нарастающем фронте TIN23 после штатного захвата `0x00AA04` и записи `0x00AA0C` в `0x8048B8`. Штатный IRQ продолжает работу. Таймер `TML0CT` читается по `0x8003E0` под той же блокировкой, что и приватное состояние. При переполнении вычисляется разность по модулю 2³². Первый фронт запоминается, дубль отбрасывается, протухший интервал снимает допуск. Настраиваемый тайм-аут требует привязки к минимальной измеряемой скорости и частоте счётчика. Опрос и захват выполняются чаще полного оборота счётчика.

Раздельная функция `lfj8_9e1b_capture_snapshot` повторяет штатный способ чтения окна 1/2/4, включая условия допуска. В старом B штатное окно порядка 225 мс и требование набрать шесть новых фронтов ограничивают малую скорость. Для `100/22` и окружности 2 м при 1:1 граница по интервалу 225 мс составляет около 7,04 км/ч. Прототип передатчика использует отдельный трекер сырых фронтов, а штатный снимок оставлен для сравнения.

`lfj8_can0_slot13_submit` проверяет нормальный режим CAN0, 11-битный формат IDE13, допустимый статус и передаёт байты через внедряемый интерфейс регистров. Принятая заявка подтверждается отдельно по CAN. Слот 13 занят штатным отправителем `0x00C424–0x00C4D8`. Использование в интеграции требует одного владельца слота, завершения конкурирующей передачи и отдельной проверки приёма. Кандидат на встраивание вне ISR находится рядом со штатным циклом `0x008164–0x00816C`, где выполняются OEM-обработка, упаковка и чтение CAN. Для выбора точки требуются проверка вызовов, соглашения о регистрах, доступного стека и длительности выполнения.

`lfj8_can0_receive8` опрашивает заранее настроенный принадлежащий вызывающему коду слот 0–13 карты Renesas 32176. Перед чтением снимает TRFIN с сохранением признака ML, после чтения повторно проверяет регистр. Перезаписанный кадр отбрасывается, а новая публикация остаётся доступна следующему опросу. В кадр попадает аппаратная 16-битная метка CAN. Срок годности задаёт вызывающий диспетчер, который расширяет метку и очищает состояние при BusOff и сбросе времени. Модель регистров проверяет кадры `0x0FA` и `0x278`, отказ шины, формат, длину, потерю и гонку приёма. Слоты 14 и 15 заняты штатным BasicCAN для идентификаторов 0x600–0x7FF. В модели опрашивается слот 11. Его назначение в проекте требуется согласовать со штатной инициализацией и восстановлением CAN. Для проверки IDE используется 16-битный CAN0EXTID по 0x801004. [Renesas 32176, §§ 13.2.3, 13.2.5, 13.6.3](https://www.renesas.com/en/document/mah/32176-group-hardware-manual?r=1051766)

Штатный стартовый код M32R устанавливает стек `CR2=0x809EFC` и базу R13 `0x808000`. Указатель стека сохранения CR0 находится по `0x809F9C`. Состояние адаптера передаётся через аргументы. Фиксированные адреса размещения кода и состояния остаются открытыми. [Разбор VSS и CAN 9E1B](../../docs/lfj8-9e1b-vss.md), [Renesas M32R §§ 10.2, 10.6 и 13.2](https://www.renesas.com/en/document/mah/321923219532196-group-hardware-manual?r=1051791).
