# REL-02. Офлайн-проверка записи CAN для стенда

База ветки `b2ca79d006426a9839d64e8553cd81bf71953fe9`. Проверка дополняет [протокол стенда LFJ8](../../docs/lfj8-9e1c-minimum-bench.md). Инструмент читает CANHacker TEXT v3 и выводит JSON в стандартный вывод.

## Воспроизведение

Из корня репозитория, Python 3.12.14. В первой команде `input_trace.trc` — локальная копия исходного журнала. Вторая команда воспроизводит отрицательный тест на историческом архиве. Его числа выбраны для проверки отсутствующих кадров, а стендовые допуски нужно взять из манифеста соответствующего измерения.

```text
python -B -m tools.check_bench_can_trace input_trace.trc --minute-wrap
python -B -m tools.check_bench_can_trace input_trace.trc --minute-wrap --stream 1 --interval 0FA:0:1000000 --interval 278:0:1000000 --interval 1AE:0:1000000 --interval 300:0:1000000
python -B -m unittest discover -s tests -p test_bench_can_trace.py -v
```

- Отчёт содержит SHA-256 входного файла, число записей каждого ID по потокам, пары сырых флагов, число разрывов времени и статистику интервалов `0x0FA`, `0x278`, `0x1AE`, `0x300`. Для расчёта интервалов этих ID используются записи DLC 8 с парой флагов `00000004/00000000`, наблюдаемой в исходном TRC. Иные записи того же ID учитываются отдельно, прерывают сравнение и дают отказ по заданному критерию.
- Без `--interval` результат `OBSERVED_OFFLINE_ONLY` описывает наблюдения. Для проверки задаются номер потока и включительные границы `ID:MIN_US:MAX_US` в микросекундах для каждого нужного ID. `PERIODIC_CHECKS_PASS` относится к перечисленным критериям и требует хотя бы одного интервала по каждому из них. Код выхода `0` соответствует успешному выполнению выбранного режима, `1` — невыполненному критерию, `2` — ошибке ввода или формата.
- При убывании времени внутри потока по умолчанию начинается новый участок сравнения. Наличие такого разрыва даёт отказ при проверке потока по допускам. `--minute-wrap` добавляет 60 секунд при каждом убывании. Этот режим требует внешнего подтверждения минутного счётчика и непрерывности записи.
- Для `0x1AE` используется [разбор модели TA2005](../../model/chery_1ae.py). Отчёт считает ошибки контрольного поля, приращения младших трёх битов счётчика при активном флаге и сброса в ноль при выключенном флаге. После ошибки контрольного поля сравнение счётчика начинается заново. Проверка приращения требует двух соседних пригодных кадров в одном участке записи.

## Доказательства

- **Программная модель.** Шесть целевых тестов прошли. Они покрывают границы интервалов, отсутствие кадров, одинаковые метки, разрывы и переход минуты, разделение потоков, ошибки DLC и флагов, контрольное поле и счётчик `0x1AE`.
- **Регрессия Python.** `python -B -m unittest discover -s tests -v` прошёл 77 тестов из 77, включая целевые. `RBM_S03` указывал на локальный донор `EMS.bin` TA2005.
- **Архивная запись.** Проверен TRC R1 из коммита `8cf4308d` с SHA-256 `7d541499762d5a5aa73e8613722da05eac597773704d6224ef06e45cbb9e4175`. В потоке `1` найдены 25 261 запись и четыре перехода минуты. Счётчики совпали с предыдущим разбором архива (`5E0=10323, 5E1=2256, 5E2=2256, 5E8=104, 5E9=10322`). Для всех четырёх периодических ID получено `no_intervals` при проверке по допускам. Итог `PERIODIC_CHECKS_FAIL`, код `1`. [Исходная запись](https://github.com/almirpangor/CM-AVEO-TCM-AKP-U340/blob/8cf4308d8539253d4ac994dd99c9650f02da6236/firmware/can/rb-bench/input_trace.trc), [разбор архива](../../docs/chery-can-dtc.md).
- **Сборка.** Изменение касается только хостового Python. Образы TCM и ECM для этой работы не собирались.
- **Оборудование.** `hardware_verified=false`. Для приёмки нужны новые журналы именно пары H03/E4M3, подтверждённые роли отправителей, допуски и аппаратные измерения по протоколу стенда. Интервалы относятся к соседним записям внутри захвата. Владение CAN13, состояния TRFIN/RR или BUS-OFF и время появления первого кадра после подачи питания подтверждаются отдельными наблюдениями на стенде.

Общий снимок аудита и реестр оставлены интегратору. `project_status.py --check` указывает на два новых файла Python до их включения в снимок после review.
