# H03-05 · Нативная привязка выходов

База интеграции — `f64eff7c24744cef0fe608415039c6d10c677ff1`. Исходный H03 `LFJ8-T-D.bin` — `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`.

## Подключение

`lfj8_h03_application_binding.c` определяет `rbm_h03_target_takeover_ops` для штатного `rbm_h03_application_binding.takeover_ops`. Компоновщик уже добавляет эту единицу трансляции через `--with-bindings --application-profile`. Старт приложения передаёт таблицу в `lfj8_h03_phase_startup`, а публикация фазы продолжает работать с тем же объектом часов. Новый экземпляр состояния отсутствует.

Для встроенного поставщика профиль задаёт оба параметра.

| Параметр профиля | Основание |
| --- | --- |
| `RBM_H03_PROFILE_OUTPUT_ISOLATION_MASK` | Допуск существующего контура D/E/F и Pressure A после подтверждения силовой карты и реакции на отказ. Все пять битов изоляции обязательны, включая TIO9/P97. |
| `RBM_H03_PROFILE_OUTPUT_PHASE_CLOCK` | Типизированный объект `control/phase_clock` владельца RAM по окончательной карте. Макрос обозначает объект, адрес которого использует таблица операций. |

Один параметр без второго и прежняя маска `0x0F` отклоняются при компиляции. Без обоих параметров действует прежний контракт с внешним поставщиком. Профиль с допуском оборудования не добавлен.

| Операция | Путь |
| --- | --- |
| Допуск | Под существующей блокировкой IRQ проверяет владение RAM и состояние приложения через `lfj8_h03_application_running_locked`, квалификацию 1 МГц и регистры PRS1/TML0/TML1. Сервисные условия, возраст фазы и блокировки выходов проверяет существующий takeover. |
| Арбитраж | `lfj8_h03_takeover_prepare_plan` → почтовый ящик D/E/F, 32-битная запись Pressure A по `0x80508C` → штатная `0x0717B8` → сверка итоговых команд. |
| Выдача | `lfj8_h03_takeover_apply` → штатная `0x046900` → P3 и Pressure A/TIO4. |
| Отзыв | `lfj8_h03_output_inhibit_locked` сбрасывает три бита P3, снимает Pressure A с PWM и очищает оба банка команд. P9/TIO9 сохраняются, поэтому до измеренного допуска этого отдельного канала требование физической изоляции обязательно. |

## Проверка

- Новый `check_h03_target_outputs.py` с `h03_target_outputs_fixture.c` прошёл 11 сценариев в каждой из моделей M32R `small` и `medium`. В ELF исполнялись исходные байты H03. Проверены переход TML0 через переполнение, D и Pressure A, отзыв при несовпадении настроек часов, режиме Flash и остановке приложения, отклонение старой выдачи после восстановленных регистров часов, отсутствие допуска без владельца RAM, сохранение регистров TIO9. Тест также проверил отказ двух неполных профилей и отсутствие встроенного поставщика при обычном профиле.
- Повторно прошли `check_h03_application_binding.py`, `check_h03_slt_fault.py`, `check_h03_slu_output_paths.py`, `check_h03_native_hooks.py` с контроллером, сборка M32R контроллера и H03 bridge. Тест штатных переходов включает 15 сценариев выхода, в том числе MAIN Toyota до оригинального исполнительного вызова в модели.
- Общие проверки прошли 22 группы `native`, 8 групп `components`, 6 групп размещённого кода и 41 этап на ПК. Набор Python проверил 179 тестов, один пропущен из-за отсутствия локального входа `RBM_S03`.
- Общая проверка `padding-candidate` с BasicCAN RX, native binding и отчётом RAM в модели `medium` удержала 96 920 байт против 96 804 при обычном профиле. Дополнение занимает 116 байт Flash. Новая статическая RAM осталась 4 байта для всего проверенного состава. Сборщик снял ровно одну неопределённую ссылку, `rbm_h03_target_takeover_ops`, и вернул `FAIL_BINDINGS` по оставшимся 20 ссылкам, включая 11 типизированных привязок RAM и девять поставщиков. Адрес часов в тестовом профиле получен из модели `control/phase_clock`. Такой профиль не утверждает владение памятью.
- Старый `check_h03_link.py` прерывает линковку `test_runtime.c` на `rbm_u340e_runtime_prepare_s01_cold`. Ошибка воспроизведена в отдельной чистой копии `f64eff7` и в ветке этой порции. Размещённое ядро через `check_h03_image_layout.py --cpu-test` успешно выполнило тот же тест холодного старта.
- Дизассемблирование `small` и `medium` показывает 0 байт собственного стека у записи и по 4 байта у проверки допуска и двух вызовов OEM. Это замер обёрток, без стека вызываемых функций и вложенных IRQ.

## Остаток

В общем исполняемом составе нужны поставщики выше и установка связанных переходов `0x036F30` и `0x07C10C` с согласованными поколениями. Для штатного `lfj8_h03_cycle_prepare_outputs` нужны данные MAIN/FAST, подтверждённая силовая `Lfj8H03OutputBinding`, измеренная таблица `Lfj8H03SltCalibration` и согласованный снимок питания, ATF и OEM-флагов. Проверки переходов с модельными входами подтверждают механику, а окончательный вызов из целевого расписания ждёт этих поставщиков.

На физическом стенде остаются прозвонка D/E/F и Pressure A, проверка отсечки при потере управления, трассы тока и давления SLT по рабочим ATF/питанию и выбор физического SLU. До подключения SLU требуется либо подтверждённая изоляция TIO9/P97, либо отдельный подтверждённый путь SLU с отзывом. Стендовых данных в этой порции нет. Выпуск обоих BIN остаётся открытым.
