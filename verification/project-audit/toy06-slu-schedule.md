# TOY-06. Команда SLU в SECONDARY

База `e24ae2ca05677df9e3a2326e43b9cbc6c67e23db`. Вход `lfj8_h03_cycle_tick_with_slu` запускает `05DC5E → 05DCE8 → 055C5E` после квалификации нагрузки на каждом допущенном SECONDARY, в том числе без MAIN. Операнды, уже доступные в каноническом GP, читаются из текущего состояния цикла. Остальные поступают из `Lfj8H03SluSnapshot` с номером события, отметкой времени и признаком квалификации. В снимке явно передаются смещения `GP−7028/−7030`, override `GP−7082` и 12 байт общего банка обучения `GP−4616…−4605`. Владелец, включивший SLU, ведёт все события этой точкой входа до переинициализации.

`Lfj8H03SluOutput` содержит численную команду в единицах донора, номер события и отметку старейшего входа из снимка цикла, нагрузки и снимка SLU. Результат действителен только для завершившегося SECONDARY. Повтор события не запускает расчёт. Пропуск события, неверный номер снимка, неполная квалификация, пустой, будущий или просроченный снимок не выдают команду. При ошибке допущенного цикла действуют правила повторной инициализации состояния. [Контракт цикла](../../targets/lfj8/lfj8_h03_cycle.h), [предыдущая численная проверка](toy06-slu-pressure.md).

## Владение GP−4735

Байт `GP−4735` имеет индекс 81 в диапазоне `GP−4816…−4620`. По границам банков `32, 82, …` он находится во втором банке FAST. Существующий префикс FAST продвигает его до 255 на чётной фазе `GP+1060`. SECONDARY читает тот же байт и сохраняет только сброс при исходном переходе режима 1→2 с активным `GP−4828.7`. Сохранённое состояние SLU содержит `GP−7026`, `GP−7032` и `GP+1637`. Инициализатор должен дать их и начальный `GP−4735` из квалифицированного состояния донора. [Расписание Toyota](../../docs/toyota-integration.md), [счётчики FAST](../../controller/vendor/toyota/src/factory_inputs.c), [карта GP](../../controller/vendor/toyota/src/hydraulic_mapping.h).

## Воспроизведение

```powershell
python -B tools/build_pc_checks.py --cc $zig --out local/toy06-schedule/pc
python -B targets/lfj8/check_toyota_slu.py --cc $zig --m32r-cc $m32rGcc --r1 $r1 --r3 $r3
python -B tools/check_integrated_h03.py --suite components --base $h03 --gcc $m32rGcc --controller $controller --out local/toy06-schedule/components
python -B tools/check_integrated_h03.py --suite native --base $h03 --gcc $m32rGcc --controller $controller --out local/toy06-schedule/native
python -B targets/lfj8/check_h03_link.py --base $h03 --gcc $m32rGcc --controller $controller --bridge $bridge --bosch-trace verification/e4m3-can-9e1c/ordinary-model/round-trip.json --out local/toy06-schedule/strict-link.json
python -B tools/check_integrated_h03.py --suite expanded --base $h03 --gcc $m32rGcc --controller $controller --bridge $bridge --bosch-trace verification/e4m3-can-9e1c/ordinary-model/round-trip.json --out local/toy06-schedule/expanded
```

ПК использует Zig 0.13.0 и проверенный S03 в `RBM_S03`. Компонентный и штатный прогоны GCC 4.8.0 выполнены на той же версии исходников из пути ASCII, который поддерживает этот компилятор на Windows. Контроллер и адаптер проверены как ELF32 big-endian для точного H03. Использованный CAN-обмен Bosch воспроизведён из ранее проверенной трассы.

## Результаты

- **ПК.** 37 шагов общего набора и 102 теста Python прошли без пропусков, включая проверку цикла c SLU.
- **Модель.** В сценарии цикла пять публикаций на 37 событиях, включая SECONDARY без MAIN, насыщение, сброс и повторное достижение температурной задержки. Проверены выбор самой ранней метки, переход через ноль, повтор события, приоритет override и семь отказов. Сценарий прошёл в стандартной проверке M32R и в отдельной группе `cycle-slu`. Все шесть компонентных групп M32R прошли. Прямое сравнение цепочки SLU с R3 и изолированный тест M32R повторены.
- **Штатные пути H03.** 17 групп M32R прошли, включая фазовый вызов исходных инструкций, сервисные границы и замер стека.
- **Стек в симуляторе.** Существующий замер `lfj8_h03_cycle_tick` дал 736 байт максимальной наблюдаемой записи на 37 414 вызовах, на 16 байт больше опубликованного замера. Он измеряет прежнюю функцию цикла. Новый полный путь с SLU и вложенными IRQ требует отдельного замера.
- **Сборка.** Стандартная строгая адресная модель прошла 18 компонентных прогонов и сквозной сценарий. Запас основного и второго окон составил 3 192 и 572 байта. Расширенная модель с новой точкой входа сохранила 1 396 байт в основном окне и превысила второе на 2 652 байта, на 808 больше опубликованной базы. Линкер правильно отклонил расширенную раскладку. [Размеры исходной расширенной модели](integration-3/expanded/summary.json).
- **Оборудование.** Открыты подключение квалифицированных производителей оставшихся полей под владельцем приложения H03, измерение стека нового полного пути с IRQ, окончательная раскладка Flash, привязка SLU к каналу H03 и стендовые измерения тока, скольжения и снятия блокировки при отказе. Результаты относятся к ПК, симулятору и ELF.

Общий снимок аудита остаётся у интегратора. `project_status.py --check` отмечает изменённые исходники и скрипты до принятия порции.
