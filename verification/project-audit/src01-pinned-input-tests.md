# SRC-01. Офлайн-регрессии проверки происхождения исходников

База — `main` `ae393e852fd8e110892c6725f219f3e43585d33c`. Проверки используют небольшие синтетические файлы и временные локальные Git-репозитории. Проверяемый интерфейс — `tools.verify_sources.verify`.

- Временная ссылка `refs/replace` меняет байты, которые читает обычный вызов `git cat-file`. Проверка происхождения по-прежнему читает исходный закреплённый blob и сверяет его SHA-256. Ссылка остаётся в репозитории после проверки.
- Совпадение размера и SHA-256 исходника при неверном Git blob ID даёт отказ. Совпадение blob ID при неверном SHA-256 файла того же размера также даёт отказ.
- H03 проверяется отдельно от S05 и S06. Архивные образы можно опустить, а при явной передаче каждый проверяется по собственной записи. Ни S05, ни S06 не меняют выбранную роль H03. H02 остаётся вне проверки активного входа.

```powershell
python -B -m unittest discover -s tests -p test_verify_sources.py -v
python -B -m unittest discover -s tests -p test_inspect_lfj8_tcm.py -v
```

Пять тестов проверки источников и два теста определения H03 прошли. Отдельный контроль подтвердил, что тест подмены blob обнаруживает удаление `--no-replace-objects`. Контроль выполнялся с подменой параметров команды только в процессе теста.

Эти результаты относятся к поведению утилиты проверки на ПК. Для этой порции использовались синтетические данные, статус реальных исходных файлов и готовности BIN берётся из отдельных проверок проекта.
