# MODE-02 — общий захват AN2 и P1DATA на H03

База — `ae393e852fd8e110892c6725f219f3e43585d33c`. В начале порции файлы запуска и общего foreground занял TOY-05. Выполнен участок от штатного вызова AN2 до готового снимка для цикла Toyota и логической заявки водителя.

## Подключение

1. Штатная обёртка точки `0x040370` сначала записывает AN2 по `0x804BC6`. Затем её целевой callback `rbm_h03_selector_adc_capture` проверяет часы и вызывает `lfj8_selector_adc_publish_h03`. Под тем же исключением он публикует AN2 и один байт P1DATA из `0x800701` с одной меткой `captured_us`.
2. Потребитель один раз забирает запись через `lfj8_selector_adc_take`. Переполнение, недействительный ADC и потеря часов сбрасывают полезные данные пары. Восстановление часов до чтения ожидающего события не заменяет отметку CLOCK_LOST. Для новой эпохи `initialize` владельца должен сбросить состояние захвата, фильтр селектора и кнопок.
3. При заданном `Lfj8H03InputBinding.p1_button_map` функция `lfj8_h03_input_propose` получает кнопки из захваченного байта по неизменяемой карте P1. Повторное чтение порта на этом шаге отсутствует. Сторонний `sources.buttons` в том же вызове считается неоднозначным вводом и снимает допуск. Карты с назначенным другим банком используют прежний путь явного нормализованного снимка. Пустое назначение OD допустимо, пока его источник открыт. Принятая заявка проходит через существующую проверку поколения и давности независимых признаков `GP−5722/GP−5250.2`.

P1DATA и признак наличия байта заняли два прежних байта выравнивания. Размер почтового ящика и снимка в ABI M32R равен 12 байтам, смещение события — 8. Свежий учёт RAM снова дал 2692 байта для трёх групп, отдельно от указателя IRQ.

## Доказательства

- **Штатные инструкции H03.** Шесть пар исходного и перехваченного вызова M32R совпали по регистрам, PSW, ACC и штатным словам ADC. Проверены байты порта `00/A5/FF`, одна общая метка, переполнение, потеря часов и сохранение отметки потери при повторном вызове. SHA-256 отчёта `an2-p1.json` — `7651d05c95c4fad0d3140d1447570710666095c26ecaa350966b3581f591ca70`.
- **Сборки ПК и M32R.** Проверены защёлкнутый порт после изменения его сырого значения, запрет повторного запроса, переход микросекундного счётчика через ноль, два конкурирующих источника, отсутствие P1DATA и получение годной серии после отказа. Повторены 512 сочетаний нормализатора и 256 значений штатного P1DATA.
- **Совместимость с main.** Прошли все 41 шаг проверки ПК, включая 120 тестов Python и сценарий сохранённого Bosch OFFLINE_ONLY, и 22 группы штатных проверок H03 на M32R.
- **Общая компоновка.** 169 корней, 522 секции и 95 070 байт известного Flash, на 300 байт больше объединённой базы. Временный учёт RAM не вырос. Оба профиля дают `FAIL_BINDINGS` по прежним `rbm_h03_application_binding` и `rbm_h03_sensor_config`. Известные секции укладываются в расширенный адресный кандидат. SHA-256 отчёта `bindings.json` — `c2b42aebf2cb459272412f5965c58f7787549a50aa914359ae9a6f857621348d`.
- **Целевое оборудование.** Карта контактов 2B/2D/2F, уровни, источник OD и фактический период получения/потребления снимка остаются измерениями для LFJ8. Нужны `rbm_h03_application_binding` с одним потребителем на соответствующем ритме и `rbm_h03_sensor_config`. После подключения владелец цикла должен провести принятую логическую заявку через гидравлику и проверить выдачу. В этом прогоне проверены модель CPU и объекты сборки. Стенд и выпуск обоих BIN открыты.

```powershell
python -B targets/lfj8/check_h03_selector_adc.py --base $h03 --gcc $m32rGcc --out local/audit/an2-p1.json
python -B targets/lfj8/check_h03_input_binding.py --zig $zig --controller $pcController --out local/audit/input-binding-pc.json
python -B targets/lfj8/check_h03_input_binding.py --gcc $m32rGcc --controller $m32rController --out local/audit/input-binding-m32r.json
```
