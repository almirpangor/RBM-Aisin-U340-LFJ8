# TOY-05 — проверка хранения адаптаций Toyota

База — `a52ab8ce955959ed109d53e6c554beb68f814c2e`.

Добавлен регрессионный сценарий в `controller/tests/test_controller.c`.
Он выполняет действующие `factory_adaptation_save/load` и восстановление
в каноническом GP через `factory_hydraulics_restore`. Модель реализует
два массива по 96 байт. Каждый вызов записи заполняет выбранный слот
значением `FF` и копирует заданное число байтов по порядку.
Поведение физического стирания страницы остаётся предметом проверки H03.

- При пустых слотах восстановление сообщает об отсутствии записи.
  При первом сохранении выбирается слот 0 и поколение 1. Нулевой
  признак простоя, значения коррекции за проверенными пределами
  `−40…40` и повторное сохранение того же состояния не вызывают запись.
- Проверены 96 прерываний до конца записи, включая частичную запись
  маркера. Ранее подтверждённый слот остаётся целым и выбирается после
  перезапуска. Полная запись с ошибкой контрольного чтения возвращает отказ.
- При переходе поколения `FFFFFFFF → 00000000` выбирается новый слот
  с тестовым снимком сброса. Его восстановление в GP заменяет поля
  обучения, сохраняя другое проверенное поле `GP−7184`.
  Разница поколений ровно в половину диапазона даёт отказ без записи.
- Проверены все 768 одиночных инверсий битов нового слота, включая
  CRC и маркер. В каждом случае алгоритм выбирает предыдущую валидную
  запись. Если последняя запись содержала сброс, то при её последующем
  повреждении это поведение возвращает прежние коррекции. Политика
  долговечного сброса для H03 должна учитывать этот результат.

## Проверки и границы

- ПК, Zig 0.13.0. Прошли 33 из 33 шагов, включая 65 тестов Python.
  Сквозной сценарий завершился с `PASS_OFFLINE_ONLY`.
- M32R GCC 4.8.0. Контроллер и мост собраны в big-endian ELF. Новый
  сценарий прошёл в симуляторе контроллера. `check_h03_link.py` прошёл
  для утверждённого H03, сохранённой трассы Bosch и 17 компонентных
  прогонов.
- `project_status.py --check` на ветке указал новый тест для
  актуализации общего аудита. Изменение реестра передаётся интегратору.

Команды приведены в карте проекта. [PC](../../docs/project-map.md#check-pc) · [M32R](../../docs/project-map.md#check-m32r)

Для целевой интеграции остаются координаты и свойства NVM, пределы
износа, расписание операций в простое, подтверждённое исходное состояние
для сброса и политика восстановления, если запись сброса повреждена.
Нулевой снимок применялся только как тестовое состояние. На оборудовании
проверки не проводились.
