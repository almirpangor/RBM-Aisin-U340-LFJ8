# MODE-01 — перекрытие кнопок Tiptronic

Проверено на базе `a52ab8ce955959ed109d53e6c554beb68f814c2e`. Сценарии используют положение D и подтверждённую вторую передачу, с разрешёнными передачами 1–4.

Прежняя логика определяла конфликт по двум фронтам в одном отсчёте. При удержании первой кнопки новый фронт противоположной считался отдельной командой. Регрессия на исходной библиотеке C остановилась на проверке конфликта. В исходной модели Python проверка провалилась для обеих последовательностей.

Контроллер теперь учитывает одновременное устойчивое состояние `+` и `−` при достоверном снимке кнопок. Ручная заявка отсутствует до конца конфликта. Отпускание одной кнопки убирает признак конфликта без выдачи заявки. Для заявки нужен новый фронт. Python-модель принимает то же решение после подтверждения устойчивых состояний. Ранее проверенные сценарии одиночного нажатия и сочетания со сменой режима прошли повторно.

Тест C для ПК компилируется с обычными заголовками контроллера и библиотекой из `local/pc-checks/controller`. На M32R он линкуется с `rbm_u340e_m32r_be.o` и той же стартовой обвязкой `crt0.o`, `__init` и `__fini`, что применяет `controller/build_target.py`, затем запускается через `m32r-elf-run`. Строка результата в обоих случаях `Tiptronic held shift conflicts and release PASS`. В Python проверка входит в unittest discover под именем `test_opposite_shift_conflicts_while_the_first_button_is_held`.

Активный общий аудит проверен до правки. `project_status.py --check` отмечает четыре изменённых файла кода и тестов, пока интегратор не включит результаты в общий снимок.

Физические входы кнопок и обработка заявки в цикле Toyota остаются задачами интеграции и стенда. Испытаний оборудования и прошивочного BIN в этой порции не было.
