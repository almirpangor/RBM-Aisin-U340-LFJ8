## Что добавлено в нативный путь

После сверки сервисных врезок и защищённых диапазонов `lfj8_h03_ram_owned` читает управляющие байты всех десяти DMA-каналов. Для канала с разрешением или захваченным запросом проверяются штатный режим, стабильность повторных чтений и диапазон оставшейся записи. Размер и направление берутся из проверенного управляющего байта. Адрес назначения читается полусловом, к младшим 16 битам добавляется штатная область `0x800000`. Значение счётчика `N` в обычном режиме соответствует `N+1` передачам. Если разрешение уже снято, а запрос ещё присутствует, учитывается одна возможная передача. Для активного кольцевого и неразобранных режимов допуск закрывается. DMA и его регистры остаются под управлением штатного кода. [Код владельца](../../targets/lfj8/lfj8_h03_ram_owner.c) · [Renesas 32176, §§ 9.2–9.4](https://www.renesas.com/en/document/mah/32176-group-hardware-manual#page=227)

| Канал | Допустимый штатный диапазон записи |
| --- | --- |
| DMA0 | `[0x806ACE, 0x806ADA)`, полусловами |
| DMA1 | `[0x806ADA, 0x806AE6)`, полусловами |
| DMA3 | `0x800113`, фиксированный байт передатчика SIO0 |
| DMA4 | `[0x80683A, 0x80693B)`, байтами, по разобранному штатному каналу 0 |

Любая допустимая запись также проходит действующую политику защиты RAM. Это закрывает ситуацию, когда при новой раскладке один из известных буферов DMA оказался в защищённой области. Внешний поставщик владения всё ещё должен исключать последующее переназначение DMA, другие обходы через SBI и обращение IRQ к состоянию до холодного допуска. Проверка рассматривает живые значения регистров в момент вызова. Полномочия остальных писателей и затраты времени под маской IRQ требуют подтверждения на целевой платформе. [Контракт](../../targets/lfj8/lfj8_h03_ram_owner.h) · [Разбор штатных адресов](../../docs/lfj8-h03-ram-audit.md)

## Проверки

В M32R прошёл штатный холодный вход с живыми указателями стеков и регистровой моделью DMA. Проверены полные и частично исполненные переносы, точные края, превышение на один перенос, неверное выравнивание, кольцевой режим, известное назначение в защищённой области, попытка записи в регистр другого канала, активный и ожидающий запрос каждого из шести неразобранных каналов. В положительном сценарии включены четыре штатных канала. Проверка не меняет конфигурацию DMA и закрывает доступ к удержанным данным при отказе. Повторены SBI, допуск S51/S83/ATF и независимый источник Toyota. [Сценарии](../../targets/lfj8/test_lfj8_h03_ram_owner.c) · [Проверка H03](../../targets/lfj8/check_h03_ram_owner.py)

```powershell
python -B targets/lfj8/check_h03_ram_owner.py --base $h03 --gcc $m32rGcc --controller $controller --bridge $bridge --storage-report $storageReport --out local/dma-admission/native.json
```

## Компоновка и служебные врезки

В расширенной компоновке известный состав занимает 97 142 байт Flash, на 484 байта больше предыдущего прогона. Номинальный остаток расширенной карты составляет 5 214 байт до выравнивания, недостающих объектов и остальных обвязок. Новых объектов постоянной RAM не выделено.

На отдельном адресном ELF H03-04 повторены 27 сценариев писателей, 28 закрытий сеанса и 512 случаев Virtual Flash. SHA-256 ELF `8a39584917b65767cd488674b0e76b5d3ed1f4c1ed5c04ed2b77eaad1b80b642` совпал в обоих отчётах. Штатный отбор адреса по-прежнему отвергает `0x003568` и `0x007FFF`, принимает `0x008000`. Повторено 18 компонентных проверок M32R со сквозной архивной трассой Bosch, 11 тестов размещения и 7 тестов служебных врезок.
