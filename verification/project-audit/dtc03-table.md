# DTC-03 — сверка таблицы Chery

База — `264f2498002dbd7ee0d0ca8723ccbb88632ec11d`.

Добавлены две проверки в стандартный набор unittest. Первая сверяет
инициализатор `dtc_table` в C с CSV по порядку всех 96 внутренних индексов.
Проверяются полные слова сервиса `17`, отдельная маска слова снимка,
файловые смещения и оба представления статуса. Повторяющиеся слова
сохраняются по индексу, поскольку соответствующие шаблоны статуса могут
различаться.

Вторая проверка принимает путь к локальному `EMS.bin` через `RBM_S03`.
После проверки размера и SHA-256 по реестру она читает 96 слов
little-endian с `0xEBE2` и 96 байтов шаблона статуса с `0xECA2`.
Проверка проходила с S03 SHA-256
`6f0433dc44871ed00e73f2766b0b37dce39b19c600f2b8248fb626554b0cfa79`.
Без локального образа unittest пропускает только эту вторую проверку.
Путь и бинарный файл в репозиторий не входят.

```powershell
$env:RBM_S03 = $s03
python -B -m unittest discover -s tests -p test_chery_dtc_table.py -v
python -B tools/build_pc_checks.py --cc $zig --out local/pc-checks
```

Отдельный прогон — обе проверки PASS. Это сверка данных и исходного
инициализатора. Условия регистрации ATF, скоростей, соленоидов, давления,
SLU и ошибок двигателя, их привязка к каналам H03 и проверка сканером
остаются открытыми. C-код и образ прошивки в этой ветке не менялись.
Сборка M32R и стендовые проверки для этого изменения не выполнялись.

Полный прогон ПК на Windows, Zig 0.13.0 — 33 из 33 шагов и 61 тест
Python, включая две новые проверки с доступным S03. Сквозной сценарий
завершился с `PASS_OFFLINE_ONLY`. Проверка `project_status.py --check`
прошла на базе, на рабочей ветке указала новый тест для актуализации
общего снимка интегратором.
