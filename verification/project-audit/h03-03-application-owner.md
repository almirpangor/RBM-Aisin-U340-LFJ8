# H03-03 — владелец приложения и штатные точки входа

Основа H03 LFJ8-18-9E1C, SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`. Порция подготовлена на main `e24ae2ca05677df9e3a2326e43b9cbc6c67e23db`.

## Реализация

| Адрес H03 | Переход |
| --- | --- |
| `0x008100` | Закрывается допуск. Обёртка исполняет перенесённое слово `2E7F4FFC` и возвращается на `0x008104`. |
| `0x00814C` | Исходный учёт времени `0x00A838`, проверка владения RAM и времени, сброс источников, инициализация GP, цикла и двух связанных объектов фаз. |
| `0x040424` | Исходная публикация `0x040468` и отметка TML0CT для готового владельца. |
| `0x008150` | Опрос предельного срока H03 и публикации Toyota даже при нулевом флаге. Штатный сброс флага остаётся в `0x00815C`. |
| `0x00816C` | Исходная обработка входов `0x040324`, затем потребление фазы и одного события независимого источника Toyota. Продолжение H03 по `0x008170`. |

Интегрирующий код связывает `rbm_h03_application_binding` с существующими объектами takeover, phase, runtime, cycle и workspace. Холодный запуск и повторный запуск снимают отложенную команду до инициализации. Пропуск, слияние, обгон потребителя или истечение срока закрывают допуск, очищают результат MAIN и отзывают отложенную команду. Повтор идентификатора с неизменной меткой пропускается без продления срока. Toyota получает собственный порядковый номер и время публикации. Возраст входов для Toyota рассчитывается в микросекундах, предельный срок источника и фазы H03 проверяются в TML0CT.

## Воспроизведение

```powershell
python -B targets/lfj8/check_h03_phase_boot.py --base $h03 --gcc $m32rGcc --out local/h03-application-owner/phase-boot.json
python -B targets/lfj8/check_h03_phase_wait.py --base $h03 --gcc $m32rGcc --out local/h03-application-owner/phase-wait.json
python -B targets/lfj8/check_h03_foreground.py --base $h03 --gcc $m32rGcc --out local/h03-application-owner/foreground.json
```

В положительном тесте штатное обновление записывает ADC2, поставщик публикует одно событие Toyota на две фазы H03. За 73 фазы выполняются три вызова MAIN, включая N→D с проверкой пары S1/S2 и метки самого старого операнда. Счётчики OEM проверены при двух начальных значениях сохранённого максимума и переходе TML0CT через ноль. Приёмка также покрывает оба повреждённых маркера, RAM без разрешения, недостоверный период, незапущенный счётчик, отказ инициализатора, отсутствующий поставщик, остановку H03 или Toyota, повтор и потерю номера Toyota, повторный запуск с устаревшим событием, слияние флагов H03 и публикацию во время работы потребителя.

## Открытые вопросы интеграции

- В симуляторе заменены ранние периферийные процедуры, АЦП, поставщик событий Toyota, допуск RAM и исполнитель запрета. Проверка при повреждённом маркере завершается на входе в восстановление. Промежуточные вызовы между ожиданием и обработкой входов заменены маршрутизацией теста.
- Окончательная компоновка должна привязать boot и foreground к тем же объектам фаз, которые используют привязки CAN, датчиков, диагностики и силовых выходов. Нужны источник событий Toyota, реальные интервалы и общий источник отметок, защищённая RAM до первого проектного IRQ, целевой запрет на холодном старте и на отказе, измерения глубины стека и задержки с вложенными IRQ.
- Обработчик `service_phase` получает результат MAIN только в соответствующем проходе. Публикация команды требует отдельной проверки под блокировкой takeover, подтверждённой актуальности FAST и MAIN и перевода возраста в единицы шкалы takeover.
- Выпуск BIN зависит от защиты Virtual Flash, гарантии записи, окончательной компоновки и проверки силовых выходов. Стенд, запись в блок и PCM Flash в этом прогоне не использовались.
