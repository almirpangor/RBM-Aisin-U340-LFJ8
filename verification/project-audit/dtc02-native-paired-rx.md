# DTC-02 — парный захват и повторные попытки штатного RX

Проверка от 20.11.2026 на базе `main` `b2ca79d006426a9839d64e8553cd81bf71953fe9`. Обёртка вызова `0x004738` получает исходный CAN0SLIST из R0. При обеих заявках она добавляет в очередь согласованные копии в порядке меток CAN. Затем восстанавливает контекст и передаёт управление штатному обработчику `0x0013F0` с исходным адресом возврата `0x00473C`. [Парный порядок](dtc02-basiccan-order.md) · [Обёртки](../../targets/lfj8/h03_dtc_rx_hook.S)

Состояние одного прохода содержит поколение CAN и маску успешно опубликованных слотов. Послотовая точка `0x001534` снимает отметку при первой попытке. Последующий повтор снова проверяет MSC и делает снимок при допустимых флагах. Смена поколения сбрасывает отметки, новый проход начинает с пустой маски. OEM сохраняет очистку TRFIN и принятие решения о повторе. Размер состояния прохода в объекте M32R составляет 8 байт, очередь по-прежнему занимает 172 байта. [Интерфейс](../../targets/lfj8/lfj8_h03_dtc_rx_queue.h)

```powershell
python -B targets/lfj8/check_h03_dtc_basiccan.py --base $h03 --gcc $m32rGcc --with-rx-dispatch --out local/audit/dtc02-native-paired-rx.json
```

## Исполнение в M32R

Прошли 18 сравнений исходного пути с обеими обёртками. Совпали контекст на входе штатного обработчика и после послотовой точки, трасса OEM, возврат и маршруты диагностики. В отдельной пробе сверены обе инструкции восстановления старшего слова аккумулятора и их операнды на том же шаблоне, что в предыдущем отчёте. Два прогона дали одинаковый SHA-256 JSON `88ee0c50a3584b329869e16710151d891ded593e369be0b4a89ae364843a1314`. Предыдущие режимы проверки оригинала и одиночной обёртки воспроизвели свои JSON побайтно. [Предыдущая проверка](dtc02-native-rx-hook.md)

| Сценарий | Наблюдение в очереди |
| --- | --- |
| Два ожидающих слота | Метки `0x1234` и `0x1300` идут по времени приёма. Две послотовые попытки снимают свои отметки, число записей остаётся 2. |
| Новый кадр после очистки TRFIN | При перезаписи RX15 в ходе штатной копии повтор добавляет третью метку `0x1310`. Две первоначальные записи сохраняются. |
| Подмена до первой очистки TRFIN | После парного снимка подставлена замена с ML. Сохраняются только две целые исходные копии, поздний кадр с ML не попадает в очередь. |
| Допустим только один слот | При ML у RX14 парный захват ставит отметку только RX15. Первый вход RX14 проверяется обычным наблюдателем и отклоняется. |

Две контрольные сборки воспроизвели отказ. Игнорирование отметки дублирует пару, а сохранение отметки после первой попытки теряет новый кадр на повторе.

Глубина изменённых слов стека от входа `0x004724` составила 256 байт при парном захвате и 32 байта в тех же исходных сценариях. Замер включает тестовый наблюдатель и собственный обработчик CAN0. Общий пролог EIT и вложенные IRQ остаются вне замера.
