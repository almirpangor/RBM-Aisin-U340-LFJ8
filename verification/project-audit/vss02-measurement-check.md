# VSS-02 — офлайн-проверка измерений скорости H03

База — `952658bff619a36f4921d637a2f0efae621f416d`.

`tools.check_vss_measurements` проверяет записанные интервалы между
соседними фронтами S51, независимую скорость по пройденному расстоянию и
времени и байты наблюдаемого кадра `0x1AE`. Используются точные дроби и
отношение 100/22. Восьмибайтный CAN payload разбирается существующим
модулем Chery, включая проверку контрольного байта и поля скорости.

## Исходные параметры машины

В опубликованной истории GW4G15-CAN-U340e описана цепочка U340E →
дифференциал АКПП → кардан 1:1 → мосты УАЗ `37/8` → колёса.
Там же записан замер окружности качения 353 см на шинах 1200×530 R20
при 0,25 бар от 15.10.2026. Нагрузка при замере не указана.
[Расчёт трансмиссии и замер](https://github.com/almirpangor/GW4G15-CAN-U340e/blob/682eeb801171ac4dadee7933b426aaf6709196d6/docs/transmission/README_RU.md)

В локальной редакции 15 от 28.10.2026 владелец подтвердил установленную
ведущую шестерню Z1=25. Ранее в опубликованном расчёте указана Z1=35.
Z2=22, датчик даёт 4 импульса за оборот. Источник редакции 15 —
`output/z25_20261028/GW4G15_U340_parameters.json`, SHA-256
`6ecc46b25d2153fa94e3d819a984b351cbd5b1447eb1cbfc9ffe9c0b31c85718`.

Для этого механического профиля `wheel_um=3530000`,
`wheel_num=8`, `wheel_den=37`. Коэффициент S51 `100/22` уже содержит
4 импульса и пару привода `25/22`. Мосты применяются после точки
съёма S51. Внутренние ступени АКПП расположены до точки съёма.

- `(100/22) × (37/8) = 925/44` импульса за оборот колеса.
- При 3,53 м получаются `23125000/3883 ≈ 5955,446819` импульса на км.
- `V = (69894/115625) × f ≈ 0,604488649 × f` км/ч, где `f` в Гц.
  Контрольные 60 км/ч соответствуют примерно 99,257 Гц.

Проверка точной дроби и CLI повторена с этим механическим профилем.
При условной частоте S51 100 Гц код составляет 6044 (`0x179C`).
Частота TML0 и длительность эталона в этом прогоне были синтетическими.

## Входные данные

В `profile` передаются измеренные `tick_hz`, `wheel_um` и дробь
`wheel_num/wheel_den` (обороты колеса на оборот корпуса дифференциала).
`vss_timeout_ticks` — настроенный срок в отсчётах TML0, а
`max_error_centi_kmh` — согласованный допуск для результата на шине,
в сотых долях км/ч. Инструмент не подбирает эти значения.

Каждая запись `samples` связывает стандартный кадр `0x1AE` с S51 и
независимым эталоном на том же участке трассы. `interval_ticks` — один
период S51, `age_ticks` — время от последнего фронта до снимка в том же
счётчике. При отсутствии периода записывается `null`. Для имеющегося
периода нужна метка возраста. Подтверждение остановки должно поступать
независимо от наличия импульсов. Длительность и расстояние эталона
указываются в мкс и мкм.

- `moving` требует действительного периода и положительной эталонной
  скорости. Проверяются совпадение CAN с расчётом и допуск относительно
  эталона с учётом квантования CAN.
- `standstill` требует отсутствия действительного периода, нулевого
  эталона и независимого подтверждения остановки. Ожидается `0000`.
- `signal_loss` требует отсутствия действительного периода при
  подтверждённом эталоном движении. Ожидается `FFFF`.

Синтетический пример структуры. Все числа относятся к тесту.

```json
{
  "profile": {
    "tick_hz": 1000000,
    "wheel_um": 2000000,
    "wheel_num": 1,
    "wheel_den": 1,
    "vss_timeout_ticks": 30000,
    "max_error_centi_kmh": 0
  },
  "samples": [
    {
      "case": "moving",
      "interval_ticks": 26400,
      "age_ticks": 30000,
      "stopped_confirmed": false,
      "reference_distance_um": 1000000,
      "reference_duration_us": 60000,
      "payload_1ae": "0832133935001770"
    },
    {
      "case": "standstill",
      "interval_ticks": null,
      "age_ticks": null,
      "stopped_confirmed": true,
      "reference_distance_um": 0,
      "reference_duration_us": 60000,
      "payload_1ae": "0832133935000000"
    },
    {
      "case": "signal_loss",
      "interval_ticks": 26400,
      "age_ticks": 30001,
      "stopped_confirmed": false,
      "reference_distance_um": 1000000,
      "reference_duration_us": 60000,
      "payload_1ae": "083213393500ffff"
    }
  ]
}
```

```powershell
python -B -m tools.check_vss_measurements local/vss-measurements.json
python -B -m unittest discover -s tests -p test_vss_measurements.py -v
```

Команда возвращает 0 при прохождении трёх сценариев, 1 при расхождении
или недостающем сценарии, 2 при неверном вводе. Выходной JSON хранит
наблюдаемое и ожидаемое необработанное поле CAN, скорость эталона,
ошибку и причины расхождения.

## Проверки и открытые данные

Восемь отдельных тестов прошли. Проверены граница возраста, неверный
кадр, ложный ноль при потере импульсов, превышение допуска, значения
вне диапазона и коды завершения CLI.

Для VSS-02 остаются проверка окружности при рабочей нагрузке, замеры
TML0, входа S51 и эталонного движения, источник подтверждения
остановки и согласованный допуск. Офлайн-отчёт характеризует только
переданные записи.

Полный прогон ПК дал 35 успешных шагов. Из 78 тестов Python один
необязательный тест S03 был пропущен при отсутствии `RBM_S03`.
Эта проверка отдельно прошла с подтверждённым донором. Пример из
документа выполнен через CLI и вернул `PASS_OFFLINE_ONLY`.

Контроллер и мост собраны в ELF компилятором M32R GCC 4.8.0.
Адресная модель H03, 17 компонентных прогонов и повтор сохранённой
трассы Bosch прошли. Новый инструмент работает на ПК и использует
модель входных данных. Снимок общего аудита для двух новых файлов
передан на актуализацию интегратору. [PC](../../docs/project-map.md#check-pc) · [M32R](../../docs/project-map.md#check-m32r)
