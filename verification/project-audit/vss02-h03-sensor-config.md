# VSS-02 — параметры захвата S51/S83 и свежести ATF для H03

Проверка выполнена на точном H03 LFJ8-18-9E1C. Проверочное дерево собрано из `main 5e3ac74` с H03-04 и опубликованного результата H03-05 `df04331`, который включает CAN-03 и REL-02. Проверена целостность исходного H03 и десять пакетов его инструкций. [Инструмент сверки](../../targets/lfj8/check_h03_sensor_config.py)

| Источник | Что подтверждает штатная ROM | Что требуется для проекта |
| --- | --- | --- |
| Тактирование | `PRS1=9`, `TML0CR=0x01` и `TML1CR=0x31`. Оба таймера выбрали Clock Bus 1. | Замер непрерывного хода обоих счётчиков относительно одного внешнего эталона. Целевой код требует 1 МГц для каждого и заново открывает эпоху после сброса. |
| S51 | В `0x034A80` значение 225,0 из `0x017194` пополняет счётчик свежести штатной ветви. В `0x03B670` и далее его остаток уменьшается на длительность цикла. | Порог возраста и периода отдельного фронта, проверенный на требуемой малой скорости U340E. Для признака остановки нужен независимый источник. |
| S83 | В `0x034AB8` значение 500,0 из `0x01703C` пополняет свежесть. Проверка учитывает текущее и предыдущее значения. Интервал обновляется через восемь событий, а пополнение свежести выполняется до делителя. | Порог для отдельного фронта и число захваченных фронтов на оборот U340E. |
| ATF | AN1 преобразуется в исходное значение в `0x804BC4`, откуда его читает ветвь расчёта температуры. | Допустимый возраст результата в общей шкале и проверка задержки от захвата AN1 до публикации. |
| Чтение пары | Проект оценивает сдвиг TML1 по чтениям TML0 до и после чтения TML1. | Верхняя ширина этого окна на целевом исполнении с учётом допустимой ошибки выравнивания меток. |

Числа 225 и 500 мс относятся к алгоритмам Mazda. В проекте `s51_timeout_ticks` и `s83_timeout_ticks` ограничивают и возраст, и допустимый период отдельного фронта. В частности, механический профиль 3,53 м, 37/8 и 100/22 дал бы границу S51 около 2,69 км/ч при переносе 225 мс в проект. Это расчёт границы, а применимый нижний диапазон измеряют на U340E. `atf_max_age_us` и `max_read_span_ticks` имеют другие физические смыслы, поэтому их проверяют отдельно. [Условия снимка](../../targets/lfj8/lfj8_h03_sensor_feed.h) · [Проверка S51 и 0x1AE](vss02-measurement-check.md)

## Проверка обеих шкал времени

Для каждого интервала записать начальные и конечные значения TML0 и TML1 на одной шкале независимого эталона. `elapsed_us` — измеренное эталоном время. `max_error_ppm` задаётся по допустимой ошибке таймера с учётом погрешности измерения.

```json
{
  "max_error_ppm": 10,
  "intervals": [
    {"elapsed_us": 100000, "tml0": [4294901760, 34464], "tml1": [430, 100430]}
  ]
}
```

В примере синтетические отсчёты с переносом TML0. Проверены совместный проход, остановка TML1, неверная частота TML1, отсутствие TML1 и неопределённость полного оборота счётчика. Возврат `PASS_RECORDED_CLOCKS` означает совпадение переданных отсчётов с заданным допуском. Для подтверждения непрерывности взять отдельные интервалы после холодного старта и после восстановления. Файл отчёта содержит происхождение штатных констант и результаты для каждого счётчика. Установку `rbm_h03_sensor_config` этот шаг оставляет открытой.

```powershell
python -B targets/lfj8/check_h03_sensor_config.py --base $h03 --out local/sensor-config/stock.json
python -B targets/lfj8/check_h03_sensor_config.py --base $h03 --clock-reference $capture --out local/sensor-config/clocks.json
```

## Владение RAM и повторная компоновка

В холодном входе и обработчиках запуск закрыт до разрешения `ram_owned`. Проверили программные ветви с запретом доступа и недоступными часами. Нативная привязка поставщика `ram_owned` должна оставаться независимой от защищаемой RAM. Отдельно повторены 240 сценариев выбранных сервисных писателей и 20 проверок границ. Окончательная `rbm_h03_service_policy`, резидентность обёрток при Virtual Flash, отмена удержанного копирования и защита от остальных писателей ещё нужны для доказательства владения. Три штатные точки H03-04 лежат ниже `0x008000`. Чтобы заявить верхний диапазон записи PCM Flash достаточным, надо доказать другой способ защиты или подтвердить запись нижней области для выбранного метода. [Интервальная защита RAM](h03-04-service-guard.md)

Известный C-состав с отзывом CAN, его обвязками и C-частью H03-04 занял 93 684 байта Flash, 164 корня и 510 секций. Прежние окна дают дефицит 12 048 байт. Известные секции помещаются в расширенных промежутках с номинальным остатком 8 672 байта до выравнивания и добавления недостающих объектов. Таблица и нативные обёртки H03-04 проверялись отдельно, поэтому этот остаток не характеризует установленную защиту. Итоговый статус `FAIL_BINDINGS`. В выбранном C-составе отсутствуют `rbm_h03_application_binding` и `rbm_h03_sensor_config`. [Снимок испытаний](2026-11-20-h03-sensor-config.json)

Bosch E4M3 по реестру выпуска остаётся `OFFLINE_ONLY`. На оборудовании проверка не проводилась, двух файлов для записи пока нет. CANHacker нужен для подтверждения скорости, признаков потери данных и восстановления обмена. Частоту TML0/TML1, момент захвата AN1 и фактические уровни силовых выходов измеряют отдельно.
