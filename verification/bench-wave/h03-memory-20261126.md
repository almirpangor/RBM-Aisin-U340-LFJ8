## Реализация

Пять memory definitions уже были сделаны в предыдущей порции. Они не заменены
заглушками и не написаны заново. `rbm_h03_boot_writers_owned` остаётся функцией
из `lfj8_h03_bench_memory.c`, проверяющей 20 исходных слов ROM и ранний marker;
четыре границы/резерва сохраняют значения и проверки прежнего H03 profile.

Проблема включения: предыдущий replay вводил ABS bounds и compiler flags через
перехват функций сборки в `verification/bench-wave/chat-6/check-composition.py`.
Генератор теперь даёт обычные файлы, которые общий builder может непосредственно
скомпилировать/подключить, и отдельную проверку реально связанного ELF.

После проверки точного H03 и типизированной RAM команда `prepare(...)` создаёт:

| Поле результата | Файл и назначение |
| --- | --- |
| `header` | `h03_bench_memory_profile.h`: прежние 20 ROM anchors |
| `symbol_source` | `h03_bench_memory_symbols.S`: четыре глобальных ABS `.equ`, без выделения RAM/Flash-переменных |
| `linker_fragment` | `h03_bench_memory_symbols.ld`: альтернативные `ABSOLUTE(...)` определения и ASSERT границ SPI/PSW |
| `native_sources` | Точные три потребителя opt-in: `lfj8_h03_bench_memory.c`, `lfj8_h03_ram_owner.c`, `h03_dma4_guard.S` |

Все три файла ASCII/LF. Нужно использовать **один** из `symbol_source` и
`linker_fragment`: либо скомпилировать `.S` вместе с binding sources, либо
включить `.ld` в общий linker script. Оба содержат одинаковые определения:

| Символ | Значение | Единицы |
| --- | --- | --- |
| `rbm_h03_ram_spi_first` | `0x809700` | адрес байта |
| `rbm_h03_ram_spi_reserve` | `1040` | байт оставшегося места |
| `rbm_h03_ram_psw_first` | `0x809F00` | адрес байта |
| `rbm_h03_ram_psw_reserve` | `64` | байт оставшегося места |

Это прежний профиль, не новая оценка максимальной глубины стека. Происхождение
чисел и незакрытые ограничения сохраняются в `verification/bench-wave/chat-6/memory.md`.

`native_compile_flags(profile, source)` возвращает флаги opt-in и путь generated
header только для трёх перечисленных consumers; прочие исходники не меняются.
Флаги должны применяться и при preprocessing для происхождения, и при сборке.

Пример включения в общий builder:

```python
memory = bench.prepare(stock_h03, typed_storage, actual_irq_pointer, output)
binding_sources += [target / bench.MODULE, memory["symbol_source"]]
# При формировании каждой команды preprocessing/compile:
flags += bench.native_compile_flags(memory, source)
# После окончательного реального линка, с M32R ELF, прочитанным read_elf(..., 2):
memory_evidence = bench.verify_linked_profile(memory, linked_elf)
```

Проверка `verify_linked_profile` требует все четыре исходных квалификационных
символа, сверяет их ABS-секции/значения, сверяет два early aliases с текущей
типизированной RAM, требует executable native boot witness и ранний gate в
нижнем Flash. Marker latch stores должен находиться в той же executable-секции
по адресу gate + `0x0C`. Входные записи с неполным/изменённым профилем отвергаются.
Ни одна фактическая writable allocation ELF не может пересекать
`[0x809700,0x80A000)`.

## Проверки и границы

- `python -B -m unittest discover -s tests -p test_h03_bench_memory_profile.py -v`:
  7 Python-тестов, включая генерацию файлов, ASCII/LF, область compiler flags,
  отказ при неверном исходнике до записи, неверные/выделенные ABS, потерянный
  native provider/ранние stores, неверные early aliases и фактическое перекрытие RAM.
- `python -B -m unittest discover -s tests -p test_h03_ram_placement.py -v`:
  5 смежных проверок RAM placement.
- `git diff --check`: без ошибок.

Тестовые ROM/ELF mappings используются только в unit tests и не включаются
в native inputs. Новые `.S`/`.ld` не запрашивают секций хранения; итоговые
размеры настоящего общего ELF ещё не измерены. Новая native M32R компиляция и
H03 replay этой порцией не подтверждены: восстановление компилятора/точного
H03 ведётся отдельно. Прежний PASS не переносится на новый выпуск.

Генерация символов не закрывает полный связанный стековый граф, все OEM writers,
окончательную компоновку и доставку нижних Flash redirects. Полная квалификация
стека не заменена инженерными reserve. `hardware_verified:false`, BIN не создан.
Общий registry/audit остаётся у интегратора и не переписан ради PASS.
