# Проверка требований к реле, скорости и кнопкам

Модель воспроизводит подтверждённые зависимости разделов 6–8 ТЗ на входных данных сценария. Для запуска в корне репозитория требуется Python 3.10 или новее.

```text
python -B -m unittest discover -s tests -v
```

| Функция ТЗ | Интерфейс модели | Результат |
| --- | --- | --- |
| § 6, два реле | `relay_commands(selector)` принимает декодированное положение, например `R` или `L` | Булевы команды реле заднего хода и дополнительного реле |
| § 7, тракт скорости | `SpeedCalibration(...).estimate(vss_hz)` принимает частоту импульсов VSS в герцах | Расчётная скорость в км/ч и расчётная частота импульсов для панели в герцах |
| § 8, режим и кнопки | `DriverControls(starting_mode=..., debounce_ms=...).sample(now_ms, buttons)` принимает состояния четырёх кнопок и монотонное время опроса | Режим, запрос повышения или понижения передачи, событие кнопки Overdrive и отметка одновременного ввода |

В расчёте скорости используется точное отношение `Fraction(100, 22)`. Для конкретного автомобиля требуется подать измеренные параметры `wheel_rev_per_differential_rev` (число оборотов колеса на оборот корпуса дифференциала), `wheel_circumference_m` (окружность колеса в метрах) и `panel_hz_per_kmh` (герц на км/ч). Значения принимаются целыми или в виде `Fraction`, например `Fraction("2.115")` для десятичного числа. Числа в тестах условные.

Период дребезга и режим при старте задаются для каждого сценария. Первый отсчёт фиксирует исходные состояния кнопок, поэтому удерживаемая на старте кнопка потребует отпускания перед новым нажатием. В тестовой модели одновременное нажатие «+» и «−» или подтверждение запроса «+»/«−» в одном отсчёте со сменой режима отмечается как неоднозначное. Для LFJ8 условия разрешения ручных запросов, поведение кнопок при включении питания, обработка одновременных нажатий и политика Overdrive требуют согласования. Состояния CAN и выводов LFJ8 проверяются отдельными измерениями по плану приёмки.

## Офлайн-разбор кадров Chery

`model.chery_can.decode_chery_frame` принимает запись `CapturedFrame` из установленной донорской связки Chery Tiggo T11 ECM и TA2005. Декодируются классические кадры данных со стандартным 11-битным ID, DLC 8, восемью байтами и указанным в записи направлением, соответствующим донорскому коду. Для направления, которое пока неизвестно, в результате сохраняются исходные байты и статус `DIRECTION_UNKNOWN`. Признак RX/TX регистратора сам по себе не определяет передающий блок.

| ID | Поле в записи | Преобразование | Основание |
| --- | --- | --- | --- |
| `0x0FA` | Байты 0–1, старший первым | `raw / 4` об/мин. `FFFF` даёт `None` при сохранении сырого слова. | Связь слова `F7C4` с ветвью оборотов, шкала программной пробы `0x12C0` на 1200 об/мин и чтение слова в TA2005. [Разбор полей][can-owners], [проба оборотов][can-rpm] |
| `0x278` | Байт 0 | `3 × raw / 4 − 48` °C на шине. `FF` даёт `None` при сохранении сырого байта. | Трассировка температуры и проверка арифметики на донорских срезах. [Отчёт проверки ОЖ][can-coolant] |
| `0x1AE` | Восемь байтов TA2005 → ECM | Сырые поля в `fields_1ae`. Байты 6–7 содержат big-endian слово скорости `raw / 100` км/ч. Для `raw ≥ 51200`, включая `FFFF`, поле скорости пустое при сохранении сырого слова. | Привязка передатчика, цепь слова `FAD2`, разбор и потребитель в ECM. [Аудит TA2005](../docs/chery-ta2005-static.md), [аудит ECM](../docs/chery-ecm-static.md) |
| `0x300` | Байт 3, TA2005 → ECM | Температура ATF `raw − 40` °C с насыщением до +104 °C. Резервный `FF` оставляет температуру ATF пустой при сохранении сырого байта. | Пакер профиля C0 и приём в ECM. При `FF` ECM использует собственную температуру ОЖ как замену. [Аудит TA2005](../docs/chery-ta2005-static.md), [аудит ECM](../docs/chery-ecm-static.md) |

Результат сохраняет исходный кадр, статус и направление с уровнем доказательства. Измерение возвращается как сырой код и точный `Fraction` либо `None` для численной интерпретации недостоверного кода. Формулы проверены программно на донорских материалах. Интервалы, валидность приёмника после его внутренних проверок и применимость к целевой паре LFJ8/Bosch остаются предметом стендовой проверки. [Отчёт по CAN Chery](../docs/chery-can-dtc.md)

### Сырые поля `0x1AE`

`model.chery_1ae.parse_1ae_payload` разбирает восемь байтов известного кадра. Полубайты `byte0[3:0]` и `byte3[3:0]` образуют контрольное поле `~(byte1 + byte4) & 0xFF`. В расчёт входят только байты 1 и 4. Разность трёхбитного счётчика вычисляется `counter_delta(previous_counter)` по модулю 8. При включённой в штатном приёмнике проверке последовательности отдельный критерий проходит при шаге 1 или 2. Совпадение контрольного поля и шаг счётчика описывают эти две проверки. Свежесть кадра и допуск запроса требуют состояния приёмника, истории опросов и проверки транспорта. [Аудит передатчика][can-1ae-tx], [квалификация приёмника][can-1ae-rx]

`model.chery_1ae.pack_1ae_payload(PackerInputs(...))` воспроизводит в памяти один вызов упаковщика `0x057028` из сырых входов. Результат содержит восемь байтов и следующий полный байт счётчика `F8E4`. При установленном `FD18.4` счётчик увеличивается, иначе сбрасывается. Для `byte5` используется `min(2 × FA5F, 254)` или резервный `FF` по `E026.0`. Для `byte1`, `byte4`, `byte5` и big-endian слова `bytes6_7` присутствие резервных кодов возвращается отдельно. Физические единицы байта 5 и условия применения запроса остаются открытыми. [Аудит передатчика][can-1ae-tx]

Показание скорости в модели соответствует сетке входного слова 0,01 км/ч. Если ECM выбирает источник `0x1AE`, он выполняет `8C60 = ((raw // 25) << 5) & 0xFFFF` с квантованием по 0,25 км/ч до обработки ограничения изменения и публикации PID `0x0D`. `FFFF` обрабатывается как резервный код до пересчёта. Для слов от 51200 до 65534 исходная 16-битная арифметика переполняется. В обоих случаях декодер сохраняет `raw` и возвращает `None` вместо численной скорости. [Аудит ECM](../docs/chery-ecm-static.md)

`encode_1ae_vehicle_speed` преобразует расчётную скорость в сырое слово `raw_fad2` для упаковщика. В модели дробная часть сотой км/ч усекается, `None` кодируется как `FFFF`, а превышение проверенного диапазона сообщает об ошибке. Сквозной тест берёт точное отношение VSS `100/22` и условные параметры колеса и проверяет 60 км/ч → `17 70` → 60 км/ч. Остальные сырые поля передаются как явные входы сценария.

## Контроль приёма и сквозная проверка на ПК

`DonorReceiveChannel` воспроизводит программные ветви S02 для `0x1AE` и `0x300`. Опросы идут через 2 и 6 вызовов задачи, признаки пропуска появляются после 16 и 6 неуспешных опросов соответственно. Тест сразу после штатной инициализации `0x1AE` задаёт `initial_skip=1`, как `8C77` в доноре. Принятое новое сообщение сбрасывает признак пропуска. В диагностическом состоянии `B254.0` на том же проходе выбирается резерв. Состояние разрешения обмена и результат аппаратного опроса подаются в модель явно. `Donor1AERequestQualifier` отдельно проверяет контрольное поле, последовательность счётчика, резервные коды и задержки установки и снятия флагов. Этот результат описывает диагностическое состояние операндов. [Расписание и приём ECM](../docs/chery-ecm-schedule.md), [аудит ECM](../docs/chery-ecm-static.md), [квалификация S02][can-1ae-rx]

Для сборки и проверки C-компонентов на ПК из корня репозитория выполните команду ниже. В тесте участвуют контроллер U340E, источники Toyota из манифеста, упаковщик LFJ8 и расчёт периода для панели.

```text
python -B -m model.run_integrated --cc zig
```

После сборки кандидата Bosch можно проверить тот же C-кадр на исполняемых инструкциях ST10 в программной модели регистров.

```text
python -B -m model.run_integrated --cc zig --bosch-engine PATH_TO_PINNED_ENGINE_TOOLS --bosch-s04 PATH_TO_S04 --bosch-image PATH_TO_BOSCH_CANDIDATE
```

Проверка встречного направления принимает `--bosch-tx-image` и `--bosch-tx-report`. Из отчёта `targets/bosch/verify_tx.py` она берёт машинные кадры `0x0FA` и `0x278`, сверяет SHA-256 с BIN и передаёт эти данные в собранный приёмник TCM. Сценарий на 1200 об/мин и 87 °C проверяет независимое декодирование. [Сборка и проверка Bosch](../docs/bosch-integration.md)

Для проверки обоих направлений на одном E4M3 укажите один файл с поддержкой RX/TX в `--bosch-image` и `--bosch-tx-image` и соответствующий отчёт в `--bosch-tx-report`. Поле `same_bosch_image_both_directions` подтверждает равенство SHA-256 обоих проверенных образов.

Сценарий проверяет логику реле в R/L/D, Auto/Tiptronic, запросы `+`/`−` и Overdrive. Для заданных условий захвата VSS C-мост формирует `0x1AE` со скоростью 14,40 км/ч и `0x300` с температурой ATF 84 °C. После штатного квантования модель ECM выдаёт 14,25 км/ч. Тест сверяет это значение с моделью кандидата Bosch, если переданы три пути. Номинал 6000 имп./км даёт 23,75 Гц. Независимый C-модуль рассчитывает период 42 105 тактов для тестового таймера 1 МГц. Работу выходного драйвера и показания физической панели проверяют по плану приёмки. [План испытаний](../docs/verification.md)
