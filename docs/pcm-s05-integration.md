# Интеграция Chery CAN в S05

Историческая проверка на предоставленном `RB-J-P01.bin` (`LFJ8-18-881F`, 1 048 576 байт, SHA‑256 `3d55f5be4cfda23a065371d71e84cc233aa111c8b237d063b1e8fc205337850d`). Карта образа приведена в [разборе S05](mazda-pcm-s05.md). Целевой TCM проекта — [LFJ8-18-9E1D](lfj8-target-identity.md).

## Собранный компонент

`targets/pcm-s05/native/s05_chery.c` готовит стандартные кадры Chery `0x1AE` и `0x300` по общим упаковщикам проекта. Входы — готовые признаки состояния, сырая скорость для `0x1AE`, измеренная температура ATF, признак её доступности и монотонное время в микросекундах. Периоды подачи каждого кадра настраиваются раздельно. При занятой очереди компонент сохраняет один запрос на идентификатор. При одновременной готовности кадров он чередует их, а счётчик `0x1AE` обновляет по подтверждению приёма запроса к отправке. Вызов без функции отправки сбрасывает очередь и счётчик. Данные кадра живут на стеке до возврата из функции отправки, поэтому драйвер копирует их синхронно.

`s05_chery_sh.o` — перемещаемый ELF32 для SH‑2E, big-endian, с общим кодом Chery. Для привязки к плате нужны выделенное состояние `S05CheryTransport`, источник входных данных и функция отправки с подтверждённым владением ящиком. [Исходники компонента](../targets/pcm-s05/native/) · [Разбор кадров TA2005](chery-ta2005-static.md).

`s05-chery-selftest.elf` — отдельный исполняемый тест с памятью и временем, заданными в эмуляторе. Сборка GCC 8.4.0 с `-m2e -mb`, ELF32 big-endian, `EM_SH=42`, `e_flags=0xB`, адрес входа `0x1040`. Проверены полные данные обоих кадров, повтор при занятости, порядок выдачи, счётчик, переход времени через `UINT32_MAX`, недоступные скорость и ATF, отключение отправки. Тест исполнил **2236 инструкций**, завершился с результатом **0**, вернул SP и `R8–R14` в исходное состояние. Глубина стека в этой проверке составила **148 байт**. Тест использует целочисленное подмножество SH‑2 и выделенный диапазон памяти эмулятора. [Исходник теста](../targets/pcm-s05/native/check.c) · [Эмулятор erings SH‑2 v1.2.0](https://github.com/user-none/erings/tree/v1.2.0/core/sh2) · [Руководство Renesas SH‑2E](https://www.renesas.com/en/document/mas/sh-2e-software-manual).

## Штатное место вызова

| Якорь в S05 | Подтверждённое действие |
| --- | --- |
| `0x003726`, `0x004470`, `0x0FFF20`, `0x0294C2` | Путь запуска штатной задачи после прохождения проверки маркеров |
| `0x0295EE–0x029604` | Проверяет и сбрасывает флаг `0xFFFF3026`, вызывает функцию `0x0B2B54` |
| `0x029764` | Адрес литерала указателя `0x0B2B54`. В пределах доступного окна найден один подходящий PC-relative `mov.l` по `0x029600` |
| `0x0B2B54` | Читает 16 младших бит `ATU-II TCNT0` по `0xFFFFF430` и сохраняет их по указателю в `R4` |
| `0x0B1AC4`, `0x029F3C`, `0x02A380` | Путь CMT0 до регулярной установки флага `0xFFFF3026` после 10 событий сравнения |
| `0x0B1CD8`, `0x0AC8BE` | CMT0/1 с делителем 32 и `CMCOR` 249/1249, запуск обоих каналов. В установившемся режиме флаг публикуется через 80 000 тактов периферии, что при 16 МГц даёт 5 мс |
| `0x0B1B94`, `0x0A9778`, `0x0A9948` | Вызовы обслуживания HCAN1 из CMT1 при разрешении штатной логики. Приём применяет маски `0xFFFF75DA/DC` и штатную RX-таблицу `0x025F00` |
| `0x00065C`, `0x000664`, `0x00066C` | Границы стека задачи с входом `0x00371C`, `0xFFFFB130–0xFFFFB92F`. Штатное заполнение `0xAA` и функция оценки глубины находятся по `0x000858` и `0x0008D4` |

Для интеграции подходит исследование обёртки вызова `0x029600` с сохранением штатного чтения таймера, живого `R1` и контекста исходной программы. Флаг цикла может объединять несколько срабатываний, поэтому временные интервалы для транспорта должны приходить от аппаратного счётчика с подтверждёнными единицами. Фактический запас стека с прерываниями, владение областью RAM для нового состояния и бюджет времени требуют проверки на S05. Штатный CMT1 и автомобильный 500 кбит/с проверяются по реальной частоте и наблюдению обмена. [Верификатор исходных байтов S05](../targets/pcm-s05/native/verify_runtime.py) · [Renesas SH7058 Hardware Manual, § 7.2, 11, 14 и 16](https://www.renesas.com/en/document/mah/sh-2e-sh7058-f-ztat-tm-hardware-manual).

## Готовность образа

Штатная сумма S05 покрывает область `0x029000–0x0FFFFF`, включая литерал потенциального вызова и области заполнения `FF` после конца кода. Для интеграции с АКПП остаётся проверить карту и уровни входов платы, силовые каналы, безопасное состояние приводов, использование ящика HCAN1, фактическую частоту периферии и запас стека. Сборка `s05-chery-selftest.elf` предназначена для исполнения в эмуляторе. Полный образ S05 с управлением U340E и проверка на оборудовании остаются открытыми. [Штатная проверка целостности S05](../targets/pcm-s05/integrity/README.md) · [Подключение S05](pcm-s05-wiring.md).

## Повтор проверки

Для локальной сборки использован GCC из закреплённой версии `2026.5` Jo Engine и Go `1.26.0`. Версия эмулятора и контрольные суммы модуля закреплены в `check_sh/go.mod` и `check_sh/go.sum`. Путь к компилятору и Go передаются в скрипт. [Версия Jo Engine 2026.5](https://github.com/johannes-fetz/joengine/tree/v2026.5/Compiler/WINDOWS) · [Архив Go 1.26.0](https://go.dev/dl/#go1.26.0).

```powershell
python targets/pcm-s05/native/verify_runtime.py 'C:/path/to/RB-J-P01.bin'
python targets/lfj8/build.py --output local/pcm-s05/obj --sh-cc 'C:/path/to/sh-elf-gcc.exe' --sh-cpu m2e
python targets/pcm-s05/native/build_check.py --gcc 'C:/path/to/sh-elf-gcc.exe' --go 'C:/path/to/go.exe' --out local/pcm-s05/native
```
