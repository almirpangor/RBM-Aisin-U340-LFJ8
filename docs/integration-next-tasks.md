# Следующая работа после объединения 31 результата

Цель: два BIN для H03 / LFJ8-18-9E1C и Bosch E4M3, U340E. Реле и импульсный выход панели отложены. Срез 20.11.2026 основан на точных результатах из [аудита интеграции](../verification/project-audit/2026-11-20-integration-3.json).

Все восемь чатов завершили предыдущие порции. Это не завершение ТЗ. Никакая из следующих задач не закрывается только добавлением очередной проверки: требуется указанная реализация, её включение в общий путь либо точное доказательство оставшегося внешнего ограничения.

## Как продолжить

Обновить свою отдельную рабочую копию из опубликованной main. Прочитать AGENTS.md, проверить task_coordination.py list. Старый claim_id после complete больше не действует. Занять перечисленный ID и **только свои файлы**; пока прежняя порция в review, не менять её коммит. Общие README, реестр, аудит и финальную компоновку меняет основной чат.

Имена чатов повторяются, поэтому ниже приведены полные ID. Это распределение следующего объёма; фактическое занятие подтверждается только командой claim. Автоматическая рассылка в чаты не выполнялась.

## 1. Запуск и единый рабочий цикл H03

Чат 01a1f99f-5cb5-70e0-afd0-60e6b41a5d51, задача **H03-03**.

- Реализовать владельца состояния приложения и последовательность cold start → часы → инициализация компонентов → допуск обработчиков → foreground. Соединить существующие phase_startup/phase_wait с рабочим циклом, а не оставлять их только в fixture.
- Начать с targets/lfj8/lfj8_h03_phase_startup.*, lfj8_h03_phase_clock.*, h03_phase_startup_hook.S; новую обвязку разместить в lfj8_h03_application.*.
- Вызовы модулей других исполнителей получать через явные интерфейсы. Не присваивать тестовым callback и квалификации аппаратное значение.
- Приёмка: исходный путь сброса H03 достигает нового владельца; один инициализированный объект каждого состояния; потеря/повтор события, неполная инициализация и повторный запуск не допускают старую команду. Прогон на оригинальных инструкциях плюс совместный цикл с точным списком ещё неподключённых входов.

## Основной чат

Основной чат сохраняет **общую компоновку, уменьшение размера, аудит и выпуск**. Дефицит измеряется с удержанием всех заявленных точек входа; удаление корней из проверки не считается оптимизацией. В текущую расширенную модель ещё не входят все нативные ASM-обёртки и финальные платформенные callbacks.

Отдельная работа основного чата — **TOY-02 / CAN-05 / ECU-01**: установить точные источники и шкалы нагрузки Bosch и её передачу в Toyota. Проверка давности восьми донорских слов уже есть; доступные штатные кадры не дают однозначного восстановления этих слов. Нужен прослеживаемый путь от внутренних переменных ECU до квалифицированного GP, затем повтор ST10 ↔ M32R.

После приёма новых порций выполнить общий набор из check_integrated_h03.py, ПК, сквозной Bosch и контроль происхождения. Выпуск REL-01 допускается только после действительной сборки двух целевых образов, проверки стартового пути, целостности и отсутствия тестовых функций. REL-02 хранит отдельную аппаратную приёмку.
