# Разделение рабочего цикла и сервисной записи H03

Проверено для H03 `LFJ8-T-D.bin`, внутренний ID `LFJ8-18-9E1C` и SHA‑256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`. При сохранении WDS для нового приложения нужны две независимые гарантии. Код должен исполняться при стабильной карте Flash. Рабочая RAM должна быть защищена от прямых и отложенных сервисных записей. [Карта Flash](lfj8-h03-retention-audit.md) · [Рабочая RAM](lfj8-h03-ram-audit.md)

| Проверка исходных инструкций | Результат |
| --- | --- |
| Конфигурация монитора `0x000201`, проверка по `0x0034A8` | Исходное `1` пропускает вход в диспетчер `0x002E10`. Подставленный в симуляторе `0` блокирует этот вызов. Значения ранее включённого отображения в `FCNT1` и `FESBANK1` в обоих случаях сохраняются. |
| Граница штатного обновления `0x004F54–0x004F84` | При обоих значениях конфигурации проверки адреса отклоняют `0x000201`, `0x003550` и `0x007FFF`. Начала `0x008000` и `0x020000` проходят проверку диапазона. Список допустимых стираний тоже начинается с `0x008000`. |
| Граница адреса монитора `0x003528` | Проверка разрешает по одному байту на обоих концах `[0x806B40, 0x807000)`, а по `0x808578` и `0x808DB3` запрещает. Драйверы записи в проверке не запускались. |
| Закрытие сеанса `0x002E80` с незавершёнными операциями | После закрытия `0x808580` меняется с `0x20` на `0x10`. Остатки подсчёта по `0x808DA4` и копирования по `0x808DA8` сохраняются. Обе штатные фазы достигают своих вызовов. Программный перезапуск обнуляет оба остатка, сохраняя состояние Virtual Flash в модели регистров. |

Флаг `0x000201`, исполнитель Virtual Flash `0x003550` и проверка адреса `0x003528` лежат ниже `0x008000`. Изменить их через штатный путь обновления приложения H03 нельзя. Флаг контролирует один вход, а уже включённое отображение и начатые операции имеют свой жизненный цикл. [Штатная геометрия и цикл обновления](lfj8-h03-flash.md)

Обработчик ADC0 `0x003608 → 0x0035F4 → 0x002D1C` может продолжать сервисное копирование после того, как пакет принят. `0x002D90` проверяет остаток передачи, а `0x002DE0` записывает очередной байт по рассчитанному адресу. Штатное закрытие сеанса не отменяет этот остаток. Поэтому временная маска CAN0 и CAN1 защищала бы только от нового входа через эти прерывания. Маска `IMASK`, исключающая CAN0 с приоритетом 1, исключит и TOP10 с таким же приоритетом. Для режима с временным разделением перед выдачей владения приложению одновременно проверяются завершение сервисных записей и отсутствие возможности начать новые. [Renesas 32176, §§ 5.2.2 и 5.2.4](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

## Граница аппаратной реализации

Обе фазы адаптера теперь допускают команду только при штатном режиме чтения `FCNT1 = 0`, без активного сеанса и при нулевых остатках обеих сервисных операций. Проверки выполняются под той же блокировкой прерываний, что подготовка и выдача. В трёх сквозных прогонах на инструкциях H03 включение сеанса, оставшееся копирование и включение Virtual Flash после подготовки отдельно остановили выдачу. Проектный код отдаёт запрос на проверенную реакцию отключения, которую предоставляет владелец исполнительного каскада. Предварительное владение кодом и RAM требуется уже при входе в адаптер. [Прогоны фаз](../verification/e4m3-can-9e1c/h03-native-phases.json) · [Отчёт по закрытию сеанса](../verification/e4m3-can-9e1c/h03-monitor-residency.json) · [Renesas 32176, § 6.4.3](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

Точные места для будущего контроля — выбор банка `0x003550` и обе ветви доступа к RAM, прямая и отложенная. Контроль банка должен исключать пересечение с кодом, его константами и путём возврата. Контроль RAM должен учитывать полный диапазон записи, включая уже запущенный перенос. Приёмка такой защиты включает чтение PID и DTC и штатное обновление приложения. Для установки проверки в подтверждённых точках нижнего ROM потребуется отдельно подтверждённый способ обновления этого участка. Штатная процедура Mazda использует WDS для чтения PID в движении, поэтому блокировка всего диагностического приёма на время работы АКПП несовместима с этой процедурой. [Mazda FS5A‑EL, проверка P0720](https://mazdamanuals.com/Mazda/md6%200605%201107/D923-1A-22C_Ver25/esicont/srvc/html/id050221809800.html)

Вариант с проверкой перед переходом из приложения возможен, если одновременно установлены режим чтения Flash, устойчивое отображение, исключение новых сервисных записей и завершение начатых. Точки `0x036F30` и `0x07C10C` подходят для проверки состояния до вызова. Найденные 16 100 байт `FF` по `[0x07C118, 0x07FFFC)` можно проверять как площадку для короткой обёртки, при подтверждённой доступности страницы `0x07C000`. Для постоянного рабочего состояния такой вариант дополнительно требует гарантии владения RAM между вызовами или определённого выхода в сервис с блокировкой выходов и повторной инициализацией. Характер работы WDS и длительность прерываний на физическом 9E1C пока не измерены.

Новый верификатор выполнил 16 сценариев на исходных инструкциях H03. Он проверяет условия допуска и завершает прогон перед диспетчером или драйвером записи. Подставленная конфигурация и модель регистров живут только в памяти симулятора. [Верификатор](../targets/lfj8/check_h03_service_isolation.py)

## Вариант отключения Virtual Flash для стенда

В модели изменение одного слова по `0x003568` направляет исполнение в штатную ветвь выключения `0x003594`. Дополнительные код и RAM для этого шага не нужны. Повторены 128 страниц обоими путями, через селектор и из сервисной ветви, при включённом и выключенном отображении. В 512 проверках сняты биты включения в FCNT1 и FESBANK1 с сохранением остальных битов. С неизменёнными маркерами путь сброса доходит до приложения. При порче любого маркера он доходит до входа в восстановление. [Верификатор](../targets/lfj8/check_h03_vflash_lockout.py) · [Отчёт M32R](../verification/e4m3-can-9e1c/h03-vflash-lockout.json)

Штатный обновитель H03 отклоняет начало записи `0x003568` и `0x007FFF`, а `0x008000` допускает. Руководство PCM Flash перечисляет чтение, запись и контрольную сумму для профиля Melco КПП Mazda5/6 512 КБ в модуле 08. Диапазон записи ниже `0x008000` для LFJ8-18-9E1C в этом описании не указан. Физическая запись, восстановление и прямые или отложенные записи монитора в RAM в этом прогоне не выполнялись. [Руководство PCM Flash](https://eu.pcmflash.ru/legal/manual.pdf)
