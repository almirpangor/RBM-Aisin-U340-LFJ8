# Анализ предоставленного образа Mazda PCM LFJ8-18-881F

Статический анализ предоставленного файла S05. Пользователь связал чтение с блоком LFJ8-18-9E1D и программой PCM. Содержимое файла идентифицирует программу моторного PCM `LFJ8-18-881F`. Зафиксированные ниже адреса и таблицы относятся к этому образу. Происхождение отдельного донора TCM описано в [сверке PCMflash и локальных образов](pcmflash-evidence.md).

## Идентификация образа

| Поле | Значение | Основание |
| --- | --- | --- |
| Файл S05 | `RB-J-P01.bin` | Приложение пользователя |
| Заявленный при передаче блок | `LFJ8 18 9E1D` | Сообщение пользователя. Внутренний идентификатор S05 отличается |
| Размер | 1 048 576 байт (`0x100000`) | Локальное измерение файла |
| SHA-256 | `3d55f5be4cfda23a065371d71e84cc233aa111c8b237d063b1e8fc205337850d` | `Get-FileHash` и независимый расчёт `hashlib.sha256` |
| Средство чтения | PCM по сообщению пользователя. Установлен PCMflash 1.2.1 | Локальный журнал не содержит успешного чтения S05 |
| Программная идентичность | Моторный PCM `LFJ8-18-881F` | Раздельные поля `LFJ8`, `18`, `881`, `F` с `0x01EBEE` и согласованные строки ПО |
| Архитектура для анализа | SuperH с FPU, big-endian. Рабочий профиль SH-2E | Таблица векторов, когерентные команды и ссылки, команды FPU |
| Профиль регистров | Совместим с картой Renesas SH7058/SH7058S | Образ 1 МиБ, адрес стека и обращения к памяти. Для точных идентификаторов ПО найдено вторичное указание Mitsubishi MH8405F. Маркировка кристалла требует независимого подтверждения |

## Карта образа

Пределы включительные, приведены как смещения файла. Первая гипотеза загрузки в дизассемблере — база `0x00000000`. Её подтверждают работающие ссылки на код, константы и векторы. Границы ниже получены из состава файла, опорных инструкций и длинных диапазонов заполнения.

| Диапазон | Установлено по образу |
| --- | --- |
| `0x000000–0x003FFF` | Таблица векторов в начале и ранний код. При сбросе `PC=0x00004430`, `SP=0xFFFF8C00`. Есть код по `0x003C1C` и ссылка на него из точки входа |
| `0x004000–0x006877` | Код старта и обработки исключений, данные и литералы. Переход из вектора `0x00001C` ведёт к `0x004C1C`, где выполняется `rte` |
| `0x006878–0x006FFE` | Непрерывное заполнение `FF` |
| `0x006FFF–0x007FFF` | Редкие служебные данные, включая идентификатор по `0x007080`. `0x007100–0x007FFF` заполнен `FF` |
| `0x008000–0x028A91` | Маркер в начале, строки, числовые таблицы и другие данные. Из кода по `0x040020` читается байт по `0x00A07C`. Назначение таблиц требует анализа ссылок |
| `0x028A92–0x028FFF` | Непрерывное заполнение `FF` |
| `0x029000–0x02A48F` | Код и данные. Из переходника `0x0FFF20` имеется переход к `0x0294C2` |
| `0x02A490–0x03FFBF` | Непрерывное заполнение `FF` |
| `0x03FFC0–0x03FFFF` | Короткое окончание блока с ненулевыми полями. Назначение требует анализа ссылок |
| `0x040000–0x0CA083` | Программный код, литералы и данные. По `0x040000` начинается функция с `sts.l pr,@-r15` и `fmov fr8,@(r0,r15)` |
| `0x0CA084–0x0FE12F` | Непрерывное заполнение `FF` |
| `0x0FE130–0x0FFFFF` | Код, промежуточные переходники, таблицы адресов и конечный маркер. Некоторые векторы из начала образа направлены в этот диапазон |

Границы пользовательской области Flash `0x00000000–0x000FFFFF` и RAM `0xFFFF0000–0xFFFFBFFF` совпадают с рабочей гипотезой SH7058/SH7058S. Стек `0xFFFF8C00` и переменная `0xFFFF2D0A`, к которой код обращается по `0x04000C–0x040010`, лежат внутри этой RAM. У SH7059 пользовательская Flash составляет 1,5 МиБ. Определить вариант по одному объёму файла можно только после подтверждения диапазона чтения. [Руководство Renesas SH7058, § 9.3](https://www.renesas.com/en/document/mah/sh-2e-sh7058-f-ztat-tm-hardware-manual), [руководство Renesas SH7058S/SH7059, отдельные карты § 9.3 и § 9.4](https://www.renesas.com/ja/document/mah/sh-2e-sh7059-f-ztattm-sh7058s-f-ztattm-hardware-manual?r=1054751), [спецификация Renesas SH7058S, 1024 КБ Flash и 48 КБ RAM](https://www.renesas.com/en/products/sh7058s/part-details/df7058scbpakv).

## Старт, целостность и доступные средства

- `0x004430` загружает `r15=0xFFFF8C00`, обнуляет `VBR` и `GBR` и вызывает код по `0x003C1C`. Это опорный путь для восстановления инициализации периферии. `0x0FFB40` и соседние входы передают управление адресам из таблицы в конце образа.
- Функция по `0x0052F4` сравнивает два 16-битных значения в образе с константами. По `0x008002` лежит `0x5AA5`, по `0x0FFFFE` — `0xA55A`. Ветвь по `0x004470` использует её результат для выбора пути. Это подтверждённая проверка маркеров. Алгоритм штатной контрольной суммы, её охват и контроль со стороны программатора пока открыты.
- На компьютере установлен Renesas FDT 4.09.02. Профиль `kernels/ProtC/7058/Renesas/1_0_00/7058.fcf` указывает `HD64F7058`, 1 048 576 байт Flash, 49 152 байта RAM и `BOOT Mode Auto Erase = True`. Профиль доступен как справочная конфигурация инструмента. Для считывания исходных данных требуется подтверждённый режим без стирания. На этом этапе проверено наличие программы и профиля. Связь с блоком не устанавливалась.

Разбор проведён в Capstone 5.0.7 с режимами `CS_ARCH_SH`, `CS_MODE_SH2`, `CS_MODE_SHFPU` и `CS_MODE_BIG_ENDIAN`. Порядок байтов и ссылки сверены с исходными байтами. Код прошивки использован как данные для дизассемблирования.

## CAN в образе S05

Функция по `0x0A9180` настраивает **HCAN-II, канал 1**. По `0x0A918E–0x0A91AE` читает `GSR` по `0xFFFFD802` и пишет `MCR`, `IRR`, `BCR1` и `BCR0` по `0xFFFFD800`, `0xFFFFD808`, `0xFFFFD804` и `0xFFFFD806`. Цикл `0x0A91B0–0x0A91DE` проходит 32 почтовых ящика от `0xFFFFD900` с шагом `0x20` байт. Адреса, размеры операций и шаг совпадают с картой HCAN-II. [Renesas SH7058 Hardware Manual, § 16.2.4, рис. 16.2(2), § 16.4, табл. 16.4](https://www.renesas.com/en/document/mah/sh-2e-sh7058-f-ztat-tm-hardware-manual).

По `0x0A91A4–0x0A91AE` загружаются `BCR1=0xB220` и `BCR0=0x0001`. Получаются 12 квантов в TSEG1, 3 в TSEG2, 1 квант синхронизации и делитель тактовой частоты 2. Скорость на этом пути равна `f_Pφ / 32`. Она составит 500 кбит/с при частоте периферии 16 МГц. Частоту блока и фактическую скорость шины ещё предстоит измерить. [Renesas SH7058 Hardware Manual, § 16.4.4](https://www.renesas.com/en/document/mah/sh-2e-sh7058-f-ztat-tm-hardware-manual).

Функция по `0x0A93CC` считывает 16-битные идентификаторы из двух таблиц, ставит стандартный ID в поле управления со сдвигом влево на четыре бита и записывает DLC отдельно. Адреса регистров управления ящиками берутся из таблицы указателей `0x026598`. Для RX используются MBC 2 и 4, для TX — MBC 0. DLC читается из байта 2 записи RX и байта 3 записи TX. Перечисленные записи действуют для статического анализа образа S05 и служат исходными данными для проверки на штатном блоке. [Renesas SH7058 Hardware Manual, § 16.3, табл. 16.3](https://www.renesas.com/en/document/mah/sh-2e-sh7058-f-ztat-tm-hardware-manual).

| Направление в PCM | Начало и шаг записи | Номера ящиков в порядке записей | CAN ID / DLC |
| --- | --- | --- | --- |
| RX | `0x025F00`, 8 байт | 0–10 | `4B0/8`, `4C0/1`, `4C1/1`, `211/8`, `430/8`, `216/8`, `231/8`, `218/8`, `217/2`, `081/4`, `21A/8` |
| TX | `0x025BA0`, 72 байта | 31–21 | `200/8`, `201/8`, `215/8`, `240/8`, `420/8`, `620/7`, `630/8`, `4F0/8`, `4F1/8`, `650/1`, `4EC/8` |

Отдельный код по `0x005B50–0x005B62` читает 16-битное поле RAM `0xFFFFA8DC` и сравнивает его с `0x07DF`. Роль поля, диагностический транспорт, тайм-ауты, значения и шкалы сигналов требуют разбора вызывающих функций и записи обмена. Совместимость с картой Chery определяется по её независимо подтверждённым требованиям.

Машиночитаемая таблица находится в [`data/mazda-pcm-can.json`](../data/mazda-pcm-can.json). Скрипт сверяет размер, SHA-256, записи обеих таблиц и 32 указателя ящиков с исходным файлом. Скрипту достаточно Python 3.

```powershell
python .\tools\verify_mazda_pcm_can.py 'C:/path/to/RB-J-P01.bin'
```

## Связь с целевым блоком

Для целевого TCM используйте [схему и таблицу контактов FS5A-EL](lfj8-wiring-sources.md) с указанным уровнем применимости. Дамп PCM пригоден для воспроизведения расследования о происхождении S05. Перенос адресов, драйверов и таблицы CAN из этого образа на TCM не обоснован.
