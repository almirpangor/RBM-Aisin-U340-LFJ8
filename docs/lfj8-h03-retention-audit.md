# Условия размещения нового кода в H03

Эта проверка относится к исходному `LFJ8-T-D.bin` с ID `LFJ8-18-9E1C` и SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`. Рассмотрены две области для компоновки, пустой сектор `[0x020000, 0x030000)` и штатный расчёт `[0x06FED4, 0x0717B8)`. [Первичная карта Flash](lfj8-h03-flash.md) · [Разделение фаз расчёта](lfj8-h03-strategy.md)

## Virtual Flash и обычный цикл

При аппаратном сбросе контроллер очищает `FCNT1` и `FESBANK1`. В H03 ROM `0x000201` содержит `1` и разрешает соответствующий сервисный диспетчер по `0x0034A8`. Его путь проверяет бит активного сеанса `0x20` в `0x808580`. Вызов `0x003550` меняет отображение при временно запрещённых прерываниях. Таблица по `0x003D5C` указывает на `0x003898`, который ведёт к этому диспетчеру. Путь к записи отображения достижим из диагностических обработчиков CAN IRQ. [Renesas 32176, §§ 6.4.3, 6.4.5 и 6.6](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

В двенадцати запусках с виртуальными регистрами проверены штатные ветви фаз 3 и 2 при активном, закрытом и отсутствующем сеансе. В обычном режиме `0x804887 = 0` обе фазы доходят до вызовов по `0x0081E0` и `0x0081F4`, даже если `FEMMOD` включён и `FESBANK1 = 0x8020` соответствует первой 4‑КиБ странице сектора. Режим `0x804887 = 4` пропускает обе фазы по обычной штатной проверке. Ветка закрытия `0x002E80` меняет `0x808580` с `0x20` на `0x10` и сохраняет оба регистра отображения. Отдельный прогон через программный перезапуск `0x003E40` дошёл до `0x000AE0` с очищенным флагом сеанса и исходными регистрами отображения. Аппаратное перенаправление Flash в симуляторе не моделировалось.

По отдельному штатному флагу программирования `0x80801C` прерывание TOP10 по `0x004714–0x00471C` пропускает вызов приложения. Сервисная смена отображения этот флаг не выставляет. Для компоновки условие входа должно охватывать весь путь, включая обёртку, код, константы, возврат и прерывания. Консервативный вариант допускает выполнение при выключенных `FEMMOD` и `FENTRY`, нормальном чтении массива и подтверждённом исключении сервисного изменения отображения на время выполнения. Снимок регистров перед отдельным переходом сам по себе этого исключения не даёт. При `FENTRY=1` проверка, расположенная во Flash, также зависит от того, что штатный диспетчер исключил её вызов. Аппаратные границы задержки прерываний и режимы 9E1D остаются открытыми. [Renesas 32176, §§ 6.4 и 6.5.2](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

## Штатный гистерезис при удалении расчёта Mazda

По всему H03 найден один внешний прямой переход в `[0x06FED4, 0x0717B8)`, `0x036F30 → 0x06FED4`. Три выровненных слова со значениями внутри диапазона оказались таблицей геометрии `0x00097C/0x000980` и двумя калибровочными полусловами по `0x010150`. Шесть чтений `0x010150` используют первое полуслово как знаковый порог `7` для сравнения с `0x806290`. Вычисляемый доступ через сервисные ветви остаётся отдельным условием. Участок пересекает границу двух секторов стирания `0x070000`.

В обычном профиле H03 функция `0x071124` вызывается через `0x070138`, когда `0x804FBC` содержит binary32 не ниже `300.0`, `0x806379 = 0` и полуслово `0x806234 = 0`. В четырёх запусках штатный расчёт подтвердил порог `299/300`, обход при `0x806379 = 1` и переход на `0x070E00` при `0x806234 = 1`. Источник `0x8050A0` подготавливает штатная оценка скорости, один из путей записывает её по `0x03B5DC`. Функция `0x03C778` подготавливает `0x80502C` из `0x805030` с ограничением или подстановкой по состоянию. Эти данные поступают из предшествующей фазы. Инициализация `0x0404C4 → 0x009184` обнуляет оба флага до проверки тёплого старта.

| Участок H03 | Что сохранять при замене |
| --- | --- |
| `0x071124–0x071203` | Обновляет `0x80658A` при верхнем пороге `5` и нижней границе `3`, а `0x8065F9` по девятиточечной таблице от `0x80502C` с нижней границей на `2` меньше. Сохраняет старое значение внутри гистерезиса. `0x8065F9` нужен функциям по `0x0732F8`, `0x073398`, `0x0771EC`. |
| `0x071204–0x0714CF`, `0x070E00–0x071123` | Ветви расчёта команд D/E и PWM A/B/C. Полный вызов `0x071124` может перезаписать эти предложения. |
| `0x0714D0–0x071713` | Готовит таймеры `0x805E74/78/7C` и флаги `0x80658B/C/D` для соседнего расчёта. В `0x071714–0x0717B7` и `0x070D98–0x070DFF` меняются предложения F и PWM Pressure B. |
| `0x070260–0x070D97` | Альтернативный профиль значения `2` по `0x01716C`. Среди других эффектов формирует `0x804F18`, которое читает штатная телеметрия. В исходном H03 байт профиля равен `0`. Возможность динамического наложения относится и к странице с этой калибровкой. |

В восьми сценариях на каждую из двух сборок симулятора выполнены исходная функция и её начальная часть до `0x071204`, завершённая штатным эпилогом из `0x0714C8`. Сверены все 24 576 байт RAM и сохранённые регистры. У сохранённой части менялись только два флага. Полный вариант в тех же сценариях менял предложения. Сохранение начальной части по её исходному адресу с тем же условием вызова даёт проверяемый способ оставить гистерезис перед выдачей команд Toyota. Оно резервирует 232 байта, если оставить инструкции на месте и перенести эпилог. Проверка полного набора косвенных эффектов, предел стека под нагрузкой и разрешение физического размещения выходят за рамки этих сценариев.
