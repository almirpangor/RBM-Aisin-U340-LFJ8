# Программная основа LFJ8-T-D.bin

Владелец выбрал этот файл для разработки. H03 содержит программу `LFJ8TC000LFXA0A0` с внутренним номером `LFJ8-18-9E1C`. Размер 524 288 байт. SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`. Целевой физический TCM ранее заявлен как `LFJ8-18-9E1D`. [История выбора](decisions.md) · [Сверка образов](lfj8-target-identity.md)

## Проверенные точки в H03

| Функция | Адреса и основание |
| --- | --- |
| Запуск M32R | Вектор `0x000000` переходит на `0x003D94`. Штатная инициализация задаёт SPI `0x809EFC`, FP `0x808000`. Функция `0x004210` проверяет слова `5AA5` по `0x008000` и `A55A` по `0x07FFFE`. H03 проходит обе проверки маркеров. При успехе загрузчик передаёт управление через `0x008084` на `0x008100`. |
| Селектор `2H` | `0x040324` вызывает штатный производитель `0x040354`. ADC0 AN2 преобразуется в `0x009FF4`. После сдвига на 6 `0x040370` публикует 10-битный результат в `0x804BC6`. По `0x034D54` он читается для расчёта напряжения. |
| Захват VSS S51 | Обработчик `0x00A9EC` читает `TML0MR0 0x8003FC` по `0x00AA04`, сохраняет метку `0x8048B8` по `0x00AA0C`. Штатная обработка `0x034858` публикует интервал `0x80616C`, счётчик фронтов `0x8061CC`, окно `0x8061D4`. |
| Захват NT S83 | Обработчик `0x00AA50` читает `TML1MR3 0x800FF0` по `0x00AA68` и публикует метку `0x8048BC` по `0x00AA70`. Таймер канала `TML1CT 0x800FE0`. Связь со входом S83 подтверждена штатной диагностикой P0715. |
| CAN0 TX | Штатная программа `0x00C424–0x00C4D8` обращается к ящику 13 и его данным по `0x80105D` и `0x8011D0–0x8011DD`. Из буфера `0x806309` берётся байт 0 штатного `0x231`, который формируется в `0x03DA60–0x03DA74`. |

Вариант H02 `9E1B` использует другие адреса интервала VSS и буфера `0x231`. Привязка выше проверена по H03. Тесты охватывают четыре независимых отсчёта селектора, повторное чтение, потерю очереди и пропадание VSS. Расчётный интервал штатного опроса ADC равен 5 мс при BCLK 40 МГц, штатном делителе и без пропуска событий. Точка `0x00816C` вызывает полный штатный производитель ADC и подходит для исследования обёртки после его возврата. Она требует проверки регистров, памяти и времени после компоновки. [Карта разъёмов TCM](lfj8-wiring-sources.md) · [Renesas, главы 10–11](https://www.renesas.com/en/document/mah/321923219532196-group-hardware-manual?r=1051791)

В исходном CAN0 включён BasicCAN. Тест с меткой S51 через границу таймера передал `0x1AE` со скоростью 5,28 км/ч в программную модель ящика 13. Входные параметры колеса и таймера заданы в тесте. Для физической интеграции нужны назначение владельца ящика, проверка трансивера и маршрута на разъём. [Код адаптеров](../targets/lfj8/) · [Renesas, §§13.2.2–13.2.3](https://www.renesas.com/en/document/mah/321923219532196-group-hardware-manual?r=1051791)

## Диагностическая сумма и проверка записи

- Подпрограмма `0x00A0CC` в тестовом режиме суммирует беззнаковые байты всего образа `[0x000000, 0x080000)` блоками по `0x400` байт. Итог по модулю `2^16` для H03 равен `0xC97D`, для архивного образа с тем же ПО — `0xC8E4`. Проверка на ПК воспроизводится выражением `sum(Path(имя_файла).read_bytes()) & 0xFFFF`. Код `0x00A408–0x00A428` передаёт два байта в тестовую телеметрию. Критерий допуска файла по профилю PCMflash остаётся неподтверждённым.
- Первые 13 пар в таблице по `0x000920` совпадают с геометрией Flash M32176F4, включая границы `0x004000`, `0x006000`, `0x008000` и последнюю пару `0x070000–0x07FFFE`. Проверка в штатной процедуре стирания по `0x00054A–0x00055E` ограничивает адреса пределом `0x07FFFF`. [Руководство Renesas 32176, § 6.3 и табл. 6.5.3](https://www.renesas.com/en/document/mah/32176-group-hardware-manual?r=1051766).
- После записи подпрограмма `0x004554–0x004586` побайтно сравнивает Flash с принятым буфером. Сектор `[0x020000, 0x030000)` заполнен `FF` в H03 и входит в допустимые диапазоны стирания по `0x005228–0x005254`. Размещение кода в этом секторе зависит от сценария штатного обновления, который может стереть его отдельно.

## Сборка M32R с проверкой выбранного файла

```powershell
python -B targets/lfj8/build.py --base-9e1c 'D:/Новая папка (2)/Общая папка/TCM/LFJ8-T-D.bin' --m32r-cc $m32r --zig $zig --output "$env:TEMP/rbm-lfj8-9e1c"
```

Параметр проверяет размер, внутренний номер и SHA-256 H03, затем записывает их в манифест вместе с `lfj8_9e1c_m32r.o`. Другой файл с тем же внутренним номером отклоняется. Исходный BIN используется для проверки и остаётся в архиве. Результат сборки — перемещаемый объект M32R, для которого ещё нужны целевая компоновка, подключение штатных событий и драйверов.

## Проверка компоновки и исполнения

Следующие команды используют объект адаптера из предыдущей сборки и собирают ядро U340E под M32R. Для проверки компоновки нужен GCC M32R с GNU-симулятором `m32r-elf-run` в том же каталоге.

```powershell
$base = 'D:/Новая папка (2)/Общая папка/TCM/LFJ8-T-D.bin'
$bridge = "$env:TEMP/rbm-lfj8-9e1c/lfj8_9e1c_m32r.o"
$out = "$env:TEMP/rbm-h03-link-review"
python -B controller/build_target.py m32r --cc $m32r --out "$out/controller"
python -B targets/lfj8/check_h03_link.py --base $base --bridge $bridge --controller "$out/controller/rbm_u340e_m32r_be.o" --gcc $m32r --out "$out/h03-link-review.json" --sim-out "$out/h03-m32r-sim.elf"
```

В модели размещения линковщик разрешил 1283 релокации. Статического записываемого состояния нет. Код и константы заняли 59 204 байт в диапазоне `[0x020000, 0x030000)`. ELF симулятора прошёл обработку селектора и истечение срока отсчёта, упаковку скорости и ATF, приём RPM и ECT. Для запуска на TCM остаются открыты размещение рабочего состояния, глубина стека с прерываниями, владельцы ресурсов и совместимость H03 с 9E1D.
