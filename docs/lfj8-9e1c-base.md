# Программная основа LFJ8-T-D.bin

Владелец выбрал этот файл для разработки. H03 содержит программу `LFJ8TC000LFXA0A0` с внутренним номером `LFJ8-18-9E1C`. Размер 524 288 байт. SHA-256 `844a11b809cda1f2ccaf90cb6a75666009487ccedd2e8190b7eb46137b855544`. Владелец подтвердил блок под `LFJ8-18-9E1C` для записи. [История выбора](decisions.md) · [Сверка образов](lfj8-target-identity.md)

## Проверенные точки в H03

| Функция | Адреса и основание |
| --- | --- |
| Запуск M32R | Вектор `0x000000` переходит на `0x003D94`. Штатная инициализация задаёт SPI `0x809EFC`, FP `0x808000`. Функция `0x004210` проверяет слова `5AA5` по `0x008000` и `A55A` по `0x07FFFE`. H03 проходит обе проверки маркеров. При успехе загрузчик передаёт управление через `0x008084` на `0x008100`. |
| Селектор `2H` | `0x040324` вызывает штатный производитель `0x040354`. ADC0 AN2 преобразуется в `0x009FF4`. После сдвига на 6 `0x040370` публикует 10-битный результат в `0x804BC6`. По `0x034D54` он читается для расчёта напряжения. |
| Захват VSS S51 | Обработчик `0x00A9EC` читает `TML0MR0 0x8003FC` по `0x00AA04`, сохраняет метку `0x8048B8` по `0x00AA0C`. Штатная обработка `0x034858` публикует интервал `0x80616C`, счётчик фронтов `0x8061CC`, окно `0x8061D4`. |
| Захват NT S83 | Обработчик `0x00AA50` читает `TML1MR3 0x800FF0` по `0x00AA68` и публикует метку `0x8048BC` по `0x00AA70`. Таймер канала `TML1CT 0x800FE0`. Связь со входом S83 подтверждена штатной диагностикой P0715. |
| CAN0 TX | Штатная программа `0x00C424–0x00C4D8` обращается к ящику 13 и его данным по `0x80105D` и `0x8011D0–0x8011DD`. Из буфера `0x806309` берётся байт 0 штатного `0x231`, который формируется в `0x03DA60–0x03DA74`. |

Вариант H02 `9E1B` использует другие адреса интервала VSS и буфера `0x231`. Привязка выше проверена по H03. При CPUCLK 40 МГц и BCLK 20 МГц таймер TOP10 выдаёт событие каждые 0,5 мс. Счётчик `0x804862` выставляет `0x804ADE` после десяти событий. Цикл `0x008150–0x00816C` читает и сбрасывает этот бит, затем обрабатывает штатные входы. Номинальный период цикла составляет 5 мс. Если цикл отстал, несколько событий могут слиться в одно. [Карта разъёмов TCM](lfj8-wiring-sources.md) · [Renesas 32176, главы 10–11](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

В H03 карта CAN соответствует 16 ящикам Renesas 32176. BasicCAN использует ящики 14 и 15, штатная локальная маска принимает диапазон `0x600–0x7FF`. Формат FullCAN читается из 16-битного `CAN0EXTID` по `0x801004`. Статические настройки `CONF=0x95A0`, `BRP=0x04` дают расчётные 500 кбит/с при CPUCLK 40 МГц. [Renesas 32176, глава 13](https://www.renesas.com/en/document/mah/32176-group-hardware-manual)

Штатная ветвь H03 `0x00BAF4` устанавливает приём в ящиках 1–10 и оставляет 11 и 12 отключёнными. Маска прерываний `CAN0SLIMK=0x8007` отключает IRQ этих ящиков, глобальная маска сравнивает все 11 бит. Адаптер проверяет эти условия и назначает ящик 11 для `0x0FA`, ящик 12 для `0x278`. После штатной переинициализации адаптер обнаруживает сброс обоих ящиков и заново назначает их в рабочем состоянии OEM 6 или 7 при снятых CRS и BOS. Периодический опрос использует 16-битный `CAN0TSTMP` и независимый `TML0CT`. При нарушении непрерывности опроса отложенные кадры отбрасываются, перед приёмом новых кадров счётчик должен возобновить ход. [Код адаптеров](../targets/lfj8/)

Тест с меткой S51 через границу таймера передал `0x1AE` со скоростью 5,28 км/ч в модель ящика 13. Входные параметры колеса и таймера заданы в тесте. Для физической интеграции нужны назначение владельца TX13, проверка восстановления RX11/12 и трансивера.

## Диагностическая сумма и проверка записи

- Подпрограмма `0x00A0CC` в тестовом режиме суммирует беззнаковые байты всего образа `[0x000000, 0x080000)` блоками по `0x400` байт. Итог по модулю `2^16` для H03 равен `0xC97D`, для архивного образа с тем же ПО — `0xC8E4`. Проверка на ПК воспроизводится выражением `sum(Path(имя_файла).read_bytes()) & 0xFFFF`. Код `0x00A408–0x00A428` передаёт два байта в тестовую телеметрию. Критерий допуска файла по профилю PCMflash остаётся неподтверждённым.
- Первые 13 пар в таблице по `0x000920` совпадают с геометрией Flash M32176F4, включая границы `0x004000`, `0x006000`, `0x008000` и последнюю пару `0x070000–0x07FFFE`. Проверка в штатной процедуре стирания по `0x00054A–0x00055E` ограничивает адреса пределом `0x07FFFF`. [Руководство Renesas 32176, § 6.3 и табл. 6.5.3](https://www.renesas.com/en/document/mah/32176-group-hardware-manual?r=1051766).
- После записи подпрограмма `0x004554–0x004586` побайтно сравнивает Flash с принятым буфером. Сектор `[0x020000, 0x030000)` заполнен `FF` в H03 и входит в допустимые диапазоны стирания по `0x005228–0x005254`. Размещение кода в этом секторе зависит от сценария штатного обновления, который может стереть его отдельно.

## Сборка M32R с проверкой выбранного файла

```powershell
python -B targets/lfj8/build.py --base-9e1c 'D:/Новая папка (2)/Общая папка/TCM/LFJ8-T-D.bin' --m32r-cc $m32r --zig $zig --output "$env:TEMP/rbm-lfj8-9e1c"
```

Параметр проверяет размер, внутренний номер и SHA-256 H03, затем записывает их в манифест вместе с `lfj8_9e1c_m32r.o`. Другой файл с тем же внутренним номером отклоняется. Исходный BIN используется для проверки и остаётся в архиве. Результат сборки — перемещаемый объект M32R, для которого ещё нужны целевая компоновка, подключение штатных событий и драйверов.

Общий выигрыш с учётом машинного кода и выравнивания составил 776 байт. В расчёте обучения смещение в таблице теперь вычисляется до сложения с указателем. Линковщик сохраняет точки входа адаптеров H03, численные стадии выбора передач, гидравлики и момента Toyota, передачу команд между фазами и интерфейсы адаптаций. Код, константы и занятые адреса подсчитаны для модели. Рабочее состояние размещает вызывающий код. Разрешение на использование сектора, запас стека с IRQ и целевые вызовы остаются открытыми. ## Проверка возврата из обёртки штатного вызова

В эмуляторе M32R исполнены неизменённые команды H03 по `0x040324–0x04039B` с исходным адресом размещения. В двух вариантах один и тот же вызов по `0x00816C` ведёт напрямую в штатную функцию или через тестовую обёртку. Преобразователь АЦП и пять вспомогательных подпрограмм заменены заглушками. Штатные команды запрашивают каналы 2, 3, 4 в этом порядке и сами записывают полученные значения в RAM.

В шести запусках проверены отсчёты AN2 0, 347 и 1023. Обёртка один раз считывает `0x804BC6` после штатного вызова. По адресу продолжения `0x008170` оба варианта дали одинаковые R0–R15, CR0, младшее слово ACC и записанные значения АЦП. Собственный кадр обёртки в проверке занял 72 байта. При пробе с ненулевым старшим словом ACC установленный эмулятор вернул 0 через MVFACHI, хотя трасса показала запись ненулевого значения. Проверка сохранения старшего слова ACC, запас стека при вложенных IRQ, АЦП реального TCM и выделение RAM остаются отдельными этапами. ## Проверка возврата после настройки CAN0

В симуляторе исполнена штатная настройка CAN0 `0x00BAF4–0x00BD5B` вместе с выбором RX-таблицы, сохранением и восстановлением PSW и продолжениями обоих вызывающих участков. При старте точка вызова `0x00B7D0` возвращает управление на `0x00B7D4`. При восстановлении `0x00B878` возвращает на `0x00B87C`. В 16 запусках прямой вызов и вызов через наблюдатель дали одинаковые R0–R15, CR0, указатель сохранения PSW и значения контролируемых ящиков. Собственный кадр наблюдателя занял 12 байт. Вместо периферии CAN0 использованы ячейки RAM по тем же адресам. Внешние действия вне выбранных ROM-фрагментов заменены заглушками.

Сразу после `0x00BAF4` в обеих ветвях ящики 11 и 12 выключены. Запись `CAN0CNT=8` выполняется дальше в штатном продолжении. В таблице показан результат при подставленных состояниях регистра STAT.

| Ветка | STAT в симуляторе | Состояние OEM после продолжения |
| --- | --- | --- |
| Начальная настройка | 0 | 6 |
| Восстановление, CRS установлен | `0x0100` | 4 |
| Восстановление, CRS снят | 0 | 7 |
| Восстановление, CRS снят и BOS установлен | `0x4000` | 7 |

После штатного вызова можно фиксировать потерю настройки и свежести данных. Для повторного назначения ящиков нужен отдельный вызов при подтверждённых состоянии контроллера, CRS, BOS и масках. Ветка восстановления достижима из обработчика TIO8 через `0x00C0E0` и вызовы `0x00C1F8/0x00C240`. Штатный приём в профиле H03 с RX-таблицей `0x032EC4` заканчивает обход на записи `FFFF` слота 11. Конкуренцию после назначения дополнительных ящиков проверяют на плате. ## RAM и запас стека

Карта Flash H03 согласуется с M32176F4, у которого рабочая RAM занимает 24 КиБ `0x804000–0x809FFF`. Место выше `0x809FFF` нельзя назначать приложению по этой карте. Инициализация H03 записывает `0xFF` в `0x808100` и очищает полуинтервал `[0x808104, 0x808E06)`. Части диагностического тракта работают с адресами до `0x8096FF`, а служебный монитор читает до `0x809FFF`. Штатный начальный SPI равен `0x809EFC`. Пролог IRQ `0x003DE0–0x003E00` сохраняет 48 байт на общем SPI и далее открывает прерывания в `0x003E0C`. Компоновка `.data/.bss=0` требует, чтобы владелец целевого приложения выделил состояние и подтвердил нижнюю границу стека вместе с вложенными IRQ. Незаписанные при запуске адреса сами по себе не подтверждают свободное место. [Renesas 32176, § 3.4](https://www.renesas.com/en/document/mah/32176-group-hardware-manual?r=1051766)

Проверка `check_h03_ram_init.py` сравнивает все 24 576 байт RAM после исполнения исходных команд H03 от `0x0009E0` или `0x003D94` до `0x000AE0`, где начинается первый вызов из блока инициализации. В обоих случаях подтверждены запись `0xFF` и очистка 3 330 байт. При входе через `0x003D94` дополнительно записывается указатель `0x809F9C` по адресу `0x809F9C`. Более поздний код загружает в `[0x805000, 0x8056B0)` две служебные подпрограммы. Адрес `0x8051E8` вызывается из `0x004374`. [Верификатор](../targets/lfj8/check_h03_ram_init.py)

```powershell
python -B targets/lfj8/check_h03_ram_init.py --base $base --gcc $m32r
```
